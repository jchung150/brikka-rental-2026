## 0.3 표기 규칙

| 표기 | 의미 |
|---|---|
| `PRO-1` | 화면 ID. 전체 목록은 부록 화면일람표 참조 |
| `[2차]` | 2차 개발 범위. 1차 미구현. 항목 자리만 확보한 경우 포함 |
| `→ 3.2` | 절 참조 |
| `→ CTR-3` | 화면 참조 |
| 【입출력 항목】 | 화면이 수신·표시하는 데이터 |
| 【동작 규칙】 | 구현 대상 판단·제약·연동 |
| 【설계 의도】 | 오구현 소지가 있는 항목의 배경. 1~2행 |

용어는 3.1절에 정의된 것만 사용한다. 동일 대상을 다른 명칭으로 표기하지 않는다.
(예: `입주자`·`임차사` → **`임차인`**)

### 명칭

| 명칭 | 대상 |
|---|---|
| **브리카** (BRIKKA) | 본 시스템의 서비스 브랜드 |
| **테온하우스** | 본 시스템을 개발·운영하는 회사. 시스템 운영자이자 첫 번째 운영사 |
| **운영사** | 본 시스템으로 건물을 관리하는 사업 주체. 위탁운영사 또는 건축주 |

시스템을 가리킬 때만 `브리카`를 사용한다. 회사를 가리킬 때는 `테온하우스`를 사용한다.

## 0.4 본 문서가 정의하지 않는 범위

| 범위 밖 | 담당 단계 |
|---|---|
| 데이터베이스 컬럼 타입, 인덱스, 제약조건 | 스키마 설계 |
| API 규격, 엔드포인트 | 개발 설계 |
| 화면 디자인, 색상, 컴포넌트 라이브러리 | UI 설계 |
| 배포 절차, 모니터링 구성 | 개발 설계 (인프라 선정은 7.11에서 확정) |
| 브랜드 소개 사이트, 임차인·임대인 포털 | 1차 범위 밖 → 1.5 |

6부는 저장 대상까지만 정의한다. 저장 방식은 스키마 설계에서 결정한다.
