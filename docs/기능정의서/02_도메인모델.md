# 2. 도메인 모델

본 장은 시스템이 다루는 개념과 그 관계를 정의한다.
화면 명세(5부)와 데이터 요구사항(6부)은 여기서 정의한 개념을 사용한다.

---

## 2.1 전체 관계도

```
  임대인 ──┬── 위임계약 ──┐
  (개인·법인)│            │
           └────지분─────┤
                         ▼
                       건물 ──── 청구항목 설정 (건물별 사용 여부·산정 방식)
                         │
                         ├── 주차면
                         ├── 공용시설
                         │
                         ├── 유닛 ──── 검침 설정 (항목별 계량기 유무·배수)
                         │     │
                         │     └── 계약 ──┬── 담당자 (N명)
                         │                ├── 청구 스케줄 (N건)
                         │                ├── 임대조건 조정 일정 (N건)
                         │                ├── 배정 주차면 (N면)
                         │                └── 원장 거래 (N건)
                         │
                         └── 정산 회차 (월 단위)
                               ├── 고지서 (항목별)
                               ├── 검침 기록 (유닛×항목, 원본)
                               └── 조정 기록 (유닛×항목, 사유 포함)

  임차인(사업자) ──── 계약 (N건. 여러 유닛·여러 건물 가능)

  청구 스케줄 ──── 청구 (회차별) ──── 수납 배분 ──── 입금
                      │                                │
                      └──────── 원장 거래 ─────────────┘
```

## 2.2 자산 계층

### 건물

임대 운영의 최상위 단위다. 건물마다 임대인·운영계좌·청구 규칙이 다르다.

| 속성 | 설명 |
|---|---|
| 건물고유이름 | 관리자가 부여하는 식별용 명칭 (예: 역삼 브리카타워) |
| 건물구분 | 오피스빌딩 / 근린생활시설(상가) / 지식산업센터 / 복합상가 / 물류창고 / 기타 |
| 임대가능면적 | 등록 시 직접 입력. 유닛 면적 합계와 자동 일치시키지 않음 |
| 운영계좌 | 임차인 입금 계좌. **건물마다 상이하며 통상 임대인 계좌** |
| 청구 주기 기본값 | 청구일·납부마감일. 계약이 상속받음 |
| 청구 항목 설정 | 항목별 사용 여부·검침분 청구 여부·잔여분 배분 기준 |

### 유닛

임대 단위 공간이다. 계약은 유닛 단위로 체결한다.

| 속성 | 설명 |
|---|---|
| 유닛고유번호 | 관리자가 부여하는 명칭 (예: 8층 전체, 302호) |
| 유닛용도 | 사무실 / 근린생활 / 창고 / 기타 |
| 임대면적·전용면적 | 제곱미터. 전용률은 전용면적 ÷ 임대면적으로 자동 산출 |
| 유닛상태 | 공실 / 사용중 / 비운영중 → 3.2 |
| 검침 설정 | 청구항목별 계량기 유무(기본: 있음), 기본 조정 배수(기본: 1.0) |

유닛에는 주소를 별도로 두지 않는다. 건물주소와 유닛고유번호를 조합해 표시한다.

### 주차면

건물에 속하며 **계약 단위로 배정**한다. 차량번호는 관리하지 않는다.

| 속성 | 설명 |
|---|---|
| 주차장유형 | 일반 / 소형 / 장애인 |
| 배정 계약 | 배정된 계약. 계약 만료 시 해제. 재계약 시 신규 계약으로 이전 |

## 2.3 거래 상대

### 임대인

건물의 소유자다. 개인·법인·개인사업자로 구분한다.

| 속성 | 설명 |
|---|---|
| 임대인구분 | 개인 / 법인 / 개인사업자 |
| 사업자등록번호 | **임대료 세금계산서의 발행 명의.** 유일값 |
| 보유지분 | 건물별 지분(%). 공동소유 가능 |
| 관리위임계약 | 시작일·종료일·수수료. 만료 시 해당 건물의 관리 권한 소멸 |

한 임대인이 여러 건물을 보유하는 경우가 많다. 임대인 보고서(REP-1)는 임대인 단위로 산출한다.

### 임차인

**법인 또는 개인사업자다.** 개인이 아니다.

| 속성 | 설명 |
|---|---|
| 사업자구분 | 법인 / 개인사업자 |
| 사업자등록번호 | **임차인 식별자. 유일값.** 수정 불가 |
| 상호·대표자명·사업장주소·업태종목 | 사업자 정보. 모든 계약에 공통 |
| 입금자명 별칭 | 은행 거래내역 자동 매칭용. 현재 **계약에 등록**한다(CTR-2). 등록 단위는 검토 중 → 6.12 |

주민등록번호는 수집하지 않는다. 개인사업자도 사업자등록번호로 식별한다.

한 사업자가 **여러 유닛·여러 건물**을 임차할 수 있다.
따라서 미납액·거래 요약은 사업자 단위로 합산한다.

### 담당자

임차인의 실무 담당자다. **계약 단위로 관리**한다.

| 속성 | 설명 |
|---|---|
| 담당자명·직위·연락처·이메일 | 청구서 수신 및 요청 응대 창구 |

계약 대표자와 담당자는 별개다.
같은 사업자라도 건물·유닛에 따라 담당자가 다를 수 있으므로 계약에 귀속시킨다.

| 정보 | 수정 위치 | 적용 범위 |
|---|---|---|
| 사업자 정보 | USER-7 | 해당 사업자의 모든 계약 |
| 담당자 정보 | CTR-3 | 해당 계약만 |

## 2.4 계약

유닛과 임차인을 연결하며, 청구의 발생 근거다.

| 속성 | 설명 |
|---|---|
| 계약고유이름 | `건물고유이름 \| 유닛고유번호 \| 대표임차인명` 자동 조합 |
| 계약상태 | 준비중 / 진행중 / 종료됨 / 파기됨 → 3.2 |
| 계약유형 | 확정기간계약 / 확정기간후자동갱신 |
| 계약시작일·종료일 | 계약 기간. 유닛상태·공실률·만료 잔여일의 기준 |
| 보증금 | 약정액·납부마감일·반환예정일 |
| 청구일·납부마감일 | 건물 기본값을 상속. 계약 단위로 1쌍 |
| 연체이자율 | 연 %. 기본값 8% |
| 무상 주차 대수·초과 단가 | 주차요금 산정 기준 |

### 계약 개시 기준

**보증금 전액 입금이 계약 개시 기준이다.** 계약서 날인이나 계약시작일 도래가 아니다.

| 상태 | 의미 |
|---|---|
| 준비중 | 계약금만 입금. 임차인이 공간을 사용하지 않으며 임대료 미발생 |
| 진행중 | 보증금 전액 입금 완료. 임차인의 인테리어 공사 기간도 포함 |

계약금은 보증금의 선입금분으로 보며 별도 항목으로 관리하지 않는다.

### 임대조건 조정 일정

상업용 장기 계약은 계약서에 인상 일정을 사전 명시하는 경우가 많다.
계약 등록 시 해당 일정을 전부 등록한다.

| 속성 | 설명 |
|---|---|
| 적용일 | 조정이 적용되는 날짜 |
| 대상 | 임대료 / 고정관리비 / 둘 다 |
| 조정 후 금액 | 적용일 이후 약정액 |
| 적용상태 | 예정 / 적용완료 / 유예 |

적용일 30일 전과 당일에 알림을 보내며, 관리자가 적용을 실행한다. 자동 갱신하지 않는다.

## 2.5 청구

청구는 **세 단계**로 나뉜다. 각 단계의 대상이 다르므로 혼동하지 않는다.

| 단계 | 개념 | 화면 | 설명 |
|---|---|---|---|
| ① 마스터 | **청구 항목** | PAY-4 | 시스템 전체 공통 목록. "전기요금이라는 항목이 존재한다" |
| ② 약정 | **청구 스케줄** | PAY-1, PAY-3 | 계약별 설정. "이 계약은 매월 임대료 700만원을 청구한다" |
| ③ 발행 | **청구 건** | PAY-2, PAY-5 | 회차별 항목 단위. "2026년 9월분 임대료 700만원" |
| ③ 발행 | **청구서** | PAY-3, PAY-5 | 계약 × 청구년월 단위. 청구 건을 묶어 1장으로 발행 |

### 청구서와 청구 건

임차인이 수령하는 것은 **청구서 1장**이고, 원장에 기록되는 것은 **청구 건 N개**다.

```
청구서  역삼 브리카타워 | 8층 전체 | (주)한빛   2026년 9월분
   ├─ 청구 건  임대료       7,000,000 + 부가세 700,000        → 원장 거래 1건
   ├─ 청구 건  고정관리비   1,800,000 + 부가세 180,000        → 원장 거래 1건
   ├─ 청구 건  전기요금       620,000 + 부가세  62,000        → 원장 거래 1건
   └─ 청구 건  수도요금        85,000 + 부가세       0        → 원장 거래 1건
   합계  10,447,000원
```

**청구서는 독립된 개체다.** 발행일·납부마감일·합계·발송 상태를 보유한다.

| 행위 | 단위 |
|---|---|
| 발행 · 발송 · 재발송 | **청구서** |
| 무효 처리 · 재발행 | **청구서** |
| 원장 기록 | 청구 건 |
| 수납 배분 | 청구 건 |

무효 처리와 재발행을 청구서 단위로 수행하는 이유는, 항목 1건만 취소하면
임차인이 수령한 청구서와 시스템 기록이 불일치하기 때문이다. 세금계산서 실무의
수정세금계산서와 동일한 방식이다.

### 청구 항목 (마스터)

시스템 전체 공통으로 관리한다. 건물별로 분리하지 않는다.
건물마다 항목을 따로 만들면 건물 간 집계와 비교가 불가능해지기 때문이다.

3단 구조는 다음과 같다.

```
PAY-4   "전기요금이라는 항목이 존재한다"              — 시스템 전체
PRO-3   "이 건물은 전기요금을 쓰고 공용부만 배분한다"   — 건물별
CTR-2   "이 계약에 전기요금을 적용한다"                — 계약별
```

기본 제공 19종의 목록과 기본값 → 3.3

### 산정 방식

| 방식 | 금액 결정 시점 | 예 |
|---|---|---|
| **고정액** | 계약 등록 시 약정액 확정 | 임대료, 고정관리비 |
| **정산** | 매 회차 PAY-10에서 산출 | 전기요금, 수도요금, 주차요금 |

고정액 항목은 스케줄러가 회차를 생성하고, 정산 항목은 정산 확정 시 생성한다.
두 항목은 같은 청구년월로 묶여 **계약당 청구서 1장**이 된다.

## 2.6 수납

### 입금과 배분

**입금 1건과 수납 배분 N건의 2단 구조다.**

임차인은 청구서 합계를 한 번에 입금하거나 임대료와 관리비를 나누어 입금한다.
청구는 항목별로 여러 건이므로, 입금을 청구에 직접 붙이면 실제 입금 시점과 금액이 소실된다.

```
[입금 기록] 1건    입금일 · 입금액 · 결제수단 · 입금자명 · 거래번호 · 등록방식
     │
     └─ [수납 배분] N건    청구 건별 배분액
          임대료      7,700,000
          고정관리비  1,980,000
          전기요금      682,000
```

배분 순서 → 4.3

### 미배분 잔액

입금액이 청구액을 초과하면 잔액을 **미배분 상태로 입금 기록에 보관**한다.
별도 계정으로 예치하지 않는다.

관리자가 다음 중 하나를 선택해 처리한다.

| 처리 | 내용 |
|---|---|
| 환불 | 원장에 `환불` 거래로 기록하고 반환 |
| 다음 회차 배분 | 다음 회차 청구 발행 후 수동으로 배분 |

선납은 정책적으로 받지 않는다. 전월에 미리 받는 임대료는 해당 월의 임대료이며 별도 개념이 아니다.

## 2.7 원장

계약 단위의 장부다. **수익계정과 부채계정을 하나의 원장에서 관리**하되 합산하지 않는다.

| 계정 | 포함 항목 | 의미 |
|---|---|---|
| **수익계정** | 청구 항목 전체 | 임차인이 납부해야 할 금액 (미수금) |
| **부채계정** | 보증금 | 임대인이 반환해야 할 금액 |

### 거래유형 8종

| 거래유형 | 계정 | 잔액 | 설명 |
|---|---|---|---|
| 청구 | 수익 | 증가 | 임차인에게 요금 청구 |
| 청구 취소 | 수익 | 감소 | 잘못 발행한 청구를 무효 처리 |
| 수납 | 수익 | 감소 | 임차인이 실제 납부 |
| 수납 취소 | 수익 | 증가 | 잘못 등록한 수납을 무효 처리 또는 배분 재조정 |
| 환불 | 수익 | 증가 | 초과 납부분 반환 |
| 보증금 예치 | 부채 | 증가 | 보증금 수령 |
| 보증금 차감 | 부채 | 감소 | 미납금·위약금·원상복구비 등으로 사용 |
| 보증금 환급 | 부채 | 감소 | 보증금 반환 |

### 원장 운용 원칙

- 모든 거래를 시간순으로 한 줄씩 기록한다. 각 거래는 수익계정 또는 부채계정 중 하나에만 속한다
- **기록을 수정하거나 삭제하지 않는다.** 오류는 취소 거래로 상쇄하고 다시 기록한다
- 각 거래는 공급가액·부가세·합계를 한 줄에 기록한다. 세금계산서 1건이 원장 1행에 대응한다
- 퇴거 정산은 별도 화면 없이 보증금 차감·환급 거래로 처리한다

## 2.8 정산

**건물 단위 월 정산**이다. 공과금 고지서를 유닛에 배분해 정산 항목의 청구 금액을 산출한다.

| 개념 | 설명 |
|---|---|
| 정산 회차 | 건물 × 년월. 확정 전까지 재계산 가능 |
| 고지서 | 항목별 총사용량·총금액. 전기는 공급가액·부가세·전력기금·TV수신료 추가 |
| 검침 기록 | 유닛×항목별 검침값. **원본이며 수정하지 않는다** |
| 조정 기록 | 유닛×항목별 조정 배수·사유·작성자. 검침 원본 위에 별도 레이어로 기록 |

산정 절차와 계산식 → 4.1

### 공실 처리

공실 유닛도 공용분 안분 대상에 포함하되 청구서를 생성하지 않는다.
해당 금액은 건축주가 부담하며 임차인에게 전가하지 않는다.

공실을 안분에서 제외하면 공실이 늘수록 남은 임차인의 관리비가 상승해 분쟁 소지가 된다.

## 2.9 문서

건물·유닛·계약·임차인·임대인 중 하나에 **귀속되어** 저장한다.
귀속 대상이 없는 문서는 생성할 수 없다.

업로드는 각 화면의 자료보관탭에서 수행하고, DOC 계열은 이를 가로질러 검색한다.

## 2.10 이력

**누가·언제·무엇을·왜 했는지**를 기록한다. 금액의 흐름은 원장이 담당한다.

| 기록 | 답하는 질문 | 위치 |
|---|---|---|
| 원장 | 미수금이 얼마 증감했는가 | CTR-3 원장정보탭 |
| 이력 | 누가 언제 왜 처리했는가 | REC-1, REC-2 |

두 기록은 상호 연결한다. 이력에서 관련 원장 거래로, 원장에서 해당 행위의 이력으로 이동한다.
