# 2. 도메인 모델

본 장은 시스템이 다루는 개념과 그 관계를 정의한다.
화면 명세(5부)와 데이터 요구사항(6부)은 여기서 정의한 개념을 사용한다.

---

## 2.1 전체 관계도

```
  임대인 ──┬── 위임계약 ──┐
  (개인·법인)│            │
           └────지분─────┤
                         ▼
                       건물 ──── 청구항목 설정 (건물별 사용 여부·산정 방식)
                         │
                         ├── 주차면
                         ├── 공용시설
                         │
                         ├── 유닛 ──── 검침 설정 (항목별 계량기 유무)
                         │     │
                         │     └── 계약 ──┬── 담당자 (N명)
                         │                ├── 청구 약정 (N건)
                         │                ├── 임대조건 조정 일정 (N건)
                         │                ├── 배정 주차면 (N면)
                         │                └── 원장 거래 (N건)
                         │
                         └── 정산 회차 (월 단위)
                               ├── 고지서 (항목별)
                               ├── 검침 기록 (유닛×항목, 원본)
                               └── 조정 기록 (유닛×항목, 사유 포함)

  임차인(사업자) ──── 계약 (N건. 여러 유닛·여러 건물 가능)

  청구 약정 ──── 청구 (회차별) ──── 수납 배분 ──── 입금
                      │                                │
                      └──────── 원장 거래 ─────────────┘
```

## 2.2 자산 계층

### 건물

임대 운영의 최상위 단위다. 건물마다 임대인·운영계좌·청구 규칙이 다르다.

| 속성 | 설명 |
|---|---|
| 건물고유이름 | 관리자가 부여하는 식별용 명칭 (예: 카리나빌딩) |
| 건물구분 | 오피스빌딩 / 근린생활시설(상가) / 지식산업센터 / 복합상가 / 물류창고 / 기타 |
| 임대가능면적 | 등록 시 직접 입력. 유닛 면적 합계와 자동 일치시키지 않음 |
| 운영계좌 | 임차인 입금 계좌. **건물마다 상이하며 통상 임대인 계좌** |
| 청구 주기 기본값 | 청구일·납부마감일. 계약이 상속받음 |
| 관리위임계약 | **건물 단위로 체결한다.** 시작일·종료일·수수료·운영방식. 만료 시 해당 건물의 관리 권한 소멸 |
| 청구 항목 설정 | 항목별 사용 여부·발행 문서·배분 기준·계량기 보유 유닛·근거 문서 |

### 유닛

임대 단위 공간이다. **계약은 유닛 하나마다 따로 둔다.** 한 회사가 여러 유닛을 써도 유닛마다 계약이 있다.
계약서가 한 장이어도 나눈다. 한 층만 해지하거나 나중에 한 층을 추가로 빌리는 일이 있기 때문이다.

| 속성 | 설명 |
|---|---|
| 유닛고유번호 | 관리자가 부여하는 명칭 (예: 8층 전체, 302호) |
| 유닛용도 | 사무실 / 근린생활 / 창고 / 기타 |
| 임대면적·전용면적 | 제곱미터. 전용률은 전용면적 ÷ 임대면적으로 자동 산출 |
| 유닛상태 | 공실 / 사용중 / 비운영중 → 3.2 |
| 검침 설정 | 청구항목별 계량기 보유 여부, 계기배율(기본 1), 계량기 공유 대상 → 4.1.3-3 |

유닛에는 주소를 별도로 두지 않는다. 건물주소와 유닛고유번호를 조합해 표시한다.

### 주차면

건물에 속하며 **계약 단위로 배정**한다. 차량번호는 관리하지 않는다.

| 속성 | 설명 |
|---|---|
| 주차장유형 | 일반 / 소형 / 장애인 |
| 배정 계약 | 배정된 계약. 계약 만료 시 해제. 재계약 시 신규 계약으로 이전 |

## 2.3 거래 상대

### 임대인

건물의 소유자다. 개인·법인·개인사업자로 구분한다.

| 속성 | 설명 |
|---|---|
| 임대인구분 | 개인 / 법인 / 개인사업자 |
| 사업자등록번호 | **임대료 세금계산서의 발행 명의.** 유일값 |
| 보유지분 | 건물별 지분(%). 공동소유 가능 |

한 임대인이 여러 건물을 보유하는 경우가 많다. 임대인 보고서(REP-1)는 임대인 단위로 산출한다.

### 임차인

**법인 또는 개인사업자다.** 개인이 아니다.

| 속성 | 설명 |
|---|---|
| 사업자구분 | 법인 / 개인사업자 |
| 사업자등록번호 | **임차인 식별자. 유일값.** 수정 불가 |
| 상호·대표자명·사업장주소·업태종목 | 사업자 정보. 모든 계약에 공통 |
| 입금자명 별칭 | 은행 거래내역 자동 매칭용. **사업자 단위로 등록**하며 복수 등록 가능. 재계약·추가 계약 시에도 유지 → 4.6 |

주민등록번호는 수집하지 않는다. 개인사업자도 사업자등록번호로 식별한다.

한 사업자가 **여러 유닛·여러 건물**을 임차할 수 있다.
따라서 미납액·거래 요약은 사업자 단위로 합산한다.

### 담당자

임차인의 실무 담당자다. **계약 단위로 관리**한다.

| 속성 | 설명 |
|---|---|
| 담당자명·직위·연락처·이메일 | 청구서 수신 및 요청 응대 창구 |

계약 대표자와 담당자는 별개다.
같은 사업자라도 건물·유닛에 따라 담당자가 다를 수 있으므로 계약에 귀속시킨다.

| 정보 | 수정 위치 | 적용 범위 |
|---|---|---|
| 사업자 정보 | USER-7 | 해당 사업자의 모든 계약 |
| 담당자 정보 | CTR-3 | 해당 계약만 |

## 2.4 계약

유닛과 임차인을 연결하며, 청구의 발생 근거다.

| 속성 | 설명 |
|---|---|
| 계약고유이름 | `건물고유이름 \| 유닛고유번호 \| 대표임차인명` 자동 조합 |
| 계약상태 | 준비중 / 진행중 / 종료됨 / 파기됨 → 3.2 |
| 계약유형 | 확정기간계약 / 확정기간후자동갱신 |
| 계약시작일·종료일 | 계약 기간. 유닛상태·공실률·만료 잔여일의 기준 |
| 보증금 | 약정액·납부마감일·반환예정일 |
| 청구일·납부마감일 | 건물 기본값을 상속. 계약 단위로 1쌍 |
| 연체이자율 | 연 %. 기본값 8% |
| 무상 주차 대수·초과 단가 | 주차비 산정 기준 |

### 계약 개시 기준

**보증금 전액 입금이 계약 개시 기준이다.** 계약서 날인이나 계약시작일 도래가 아니다.

| 상태 | 의미 |
|---|---|
| 준비중 | 계약금만 입금. 임차인이 공간을 사용하지 않으며 임대료 미발생 |
| 진행중 | 보증금 전액 입금 완료. 임차인의 인테리어 공사 기간도 포함 |

계약금은 보증금의 선입금분으로 보며 별도 항목으로 관리하지 않는다.

### 임대조건 조정 일정

상업용 장기 계약은 계약서에 인상 일정을 사전 명시하는 경우가 많다.
계약 등록 시 해당 일정을 전부 등록한다.

| 속성 | 설명 |
|---|---|
| 적용일 | 새 금액이 시작되는 날짜 |
| 임대료 · 고정관리비 | 적용일부터의 약정액(부가세 포함). 비워 두면 그 항목은 그대로 |
| 적용상태 | 예정 / 적용완료 — 적용일이 지나면 자동으로 적용완료 |

적용일부터 **새 금액으로 자동 청구한다.** 관리자가 잊어도 계약서대로 청구되게 하기 위해서다.
적용일 30일 전에 관리자에게 알린다(확인용). 임차인과 협의해 바뀌면 적용일 전에 일정을 고친다.

## 2.5 청구

청구는 **세 단계**로 나뉜다. 각 단계의 대상이 다르므로 혼동하지 않는다.

| 단계 | 개념 | 화면 | 설명 |
|---|---|---|---|
| ① 항목 | **청구 항목** | PRO-3 | 건물별 목록. "이 건물은 전기요금을 청구하고 우선순위는 4다" |
| ② 약정 | **청구 약정** | PAY-3, CTR-3 | 계약별 설정. "이 계약은 매월 임대료 700만원을 청구한다" |
| ③ 발행 | **청구 건** | PAY-1, PAY-5 | 회차별 항목 단위. "2026년 9월분 임대료 700만원" |
| ③ 발행 | **청구서** | PAY-1, PAY-5 | 계약 × 청구년월 단위. 청구 건을 묶어 1장으로 발행 |

### 청구서와 청구 건

임차인이 수령하는 것은 **청구서 1장**이고, 원장에 기록되는 것은 **청구 건 N개**다.

```
청구서  카리나|801호|(주)한빛   2026년 9월분
   ├─ 청구 건  임대료       7,000,000 + 부가세 700,000        → 원장 거래 1건
   ├─ 청구 건  고정관리비   1,800,000 + 부가세 180,000        → 원장 거래 1건
   ├─ 청구 건  전기요금       620,000 + 부가세  62,000        → 원장 거래 1건
   └─ 청구 건  수도요금        85,000 + 부가세       0        → 원장 거래 1건
   합계  10,447,000원
```

**청구서는 독립된 개체다.** 발행일·납부마감일·합계·발송 상태를 보유한다.

| 행위 | 단위 |
|---|---|
| 발행 · 발송 · 재발송 | **청구서** |
| 무효 처리 · 재발행 | **청구서** |
| 원장 기록 | 청구 건 |
| 수납 배분 | 청구 건 |

무효 처리와 재발행을 청구서 단위로 수행하는 이유는, 항목 1건만 취소하면
임차인이 수령한 청구서와 시스템 기록이 불일치하기 때문이다. 세금계산서 실무의
수정세금계산서와 동일한 방식이다.

### 청구 항목 (건물별)

**청구 항목은 건물마다 따로 관리한다.** 운영사 전체에 공통 목록을 두지 않는다.
건물마다 청구하는 항목이 다르고(전기·수도를 청구하지 않는 건물도 있다) 우선순위도 다르기 때문이다.

```
PRO-3   "이 건물은 전기요금을 청구하고 공용부를 사용량으로 배분한다"   — 건물별
CTR-2   "이 계약에 전기요금을 적용한다"                              — 계약별
```

- 항목을 추가할 때 **기준표 19종**(→ 3.3)에서 고르면 기본값이 채워진다. 기준표에 없으면 새로 만든다
- **건물당 최대 99개.** 배분 우선순위 1~99와 한 칸씩 짝을 이룬다
- 기준표 항목은 건물이 달라도 같은 항목으로 인식한다. 건물 간 집계는 기준표 항목끼리만 한다

### 산정 방식

| 방식 | 금액 결정 시점 | 예 |
|---|---|---|
| **고정액** | 계약 등록 시 약정액 확정 | 임대료, 고정관리비 |
| **정산** | 매 회차 PAY-10에서 산출 | 전기요금, 수도요금, 주차비 |

두 항목은 같은 청구년월로 묶여 **계약당 청구서 1장**이 된다. 청구 건은 청구서를
발행할 때(PAY-1) 생성되며 그때 원장에 기록된다. 고정액은 약정에서, 정산액은 정산 확정 결과에서 가져온다.

## 2.6 수납

### 입금과 배분

**입금 1건과 수납 배분 N건의 2단 구조다.**

임차인은 청구서 합계를 한 번에 입금하거나 임대료와 관리비를 나누어 입금한다.
청구는 항목별로 여러 건이므로, 입금을 청구에 직접 붙이면 실제 입금 시점과 금액이 소실된다.

**입금은 계약이 아니라 임차인(사업자)에 속한다.** 한 사업자가 여러 계약을 가지면
합쳐서 입금하는 것이 실제 관행이다(예: 본관8층·7층 두 계약을 입금 1건으로 납부).
어느 계약의 청구인지는 배분된 청구 건이 가진다.

```
[입금 기록] 1건    임차인 · 건물 · 입금일 · 입금액 · 결제수단 · 입금자명 · 거래번호 · 등록방식
     │
     └─ [수납 배분] N건    청구 건별 배분액
          임대료      7,700,000
          고정관리비  1,980,000
          전기요금      682,000
```

배분 순서 → 4.3

### 미배분 잔액

입금액이 청구액을 초과하면 잔액을 **미배분 상태로 입금 기록에 보관**한다.
별도 계정으로 예치하지 않는다.

관리자가 다음 중 하나를 선택해 처리한다.

| 처리 | 내용 |
|---|---|
| 환불 | 원장에 `환불` 거래로 기록하고 반환 |
| 다음 회차 배분 | 다음 회차 청구 발행 후 수동으로 배분 |

선납은 정책적으로 받지 않는다. 전월에 미리 받는 임대료는 해당 월의 임대료이며 별도 개념이 아니다.

## 2.7 원장

계약 단위의 장부다. 회계의 **거래처별 보조원장**에 해당한다.
**매출채권과 임대보증금 두 계정을 하나의 원장에서 관리**하되 합산하지 않는다.
금액은 차변·대변으로 적는다. 회계 담당자가 그대로 읽을 수 있어야 한다.

| 계정 | 성격 | 포함 항목 | 잔액의 의미 | 늘 때 | 줄 때 |
|---|---|---|---|---|---|
| **매출채권** | 자산 | 청구 항목 전체 | 임차인에게 받을 돈 (= 미납액) | 차변 | 대변 |
| **임대보증금** | 부채 | 보증금 | 임차인에게 돌려줄 돈 | 대변 | 차변 |

> 청구서를 발행하면 **받을 돈(매출채권)이 늘어난다.** 들어온 돈이 아니다. 입금되면 매출채권이 줄어든다.

### 거래유형 8종

| 거래유형 | 계정 | 기입 | 설명 |
|---|---|---|---|
| 청구 | 매출채권 | 차변 | 임차인에게 요금 청구 |
| 청구 취소 | 매출채권 | 대변 | 잘못 발행한 청구를 무효 처리 |
| 수납 | 매출채권 | 대변 | 임차인이 실제 납부 |
| 수납 취소 | 매출채권 | 차변 | 잘못 등록한 수납을 무효 처리 또는 배분 재조정 |
| 환불 | 매출채권 | 차변 | 초과 납부분 반환 |
| 보증금 예치 | 임대보증금 | 대변 | 보증금 수령 |
| 보증금 차감 | 임대보증금 | 차변 | 미납금·위약금·원상복구비 등으로 사용 |
| 보증금 환급 | 임대보증금 | 차변 | 보증금 반환 |

### 원장 운용 원칙

- 모든 거래를 시간순으로 한 줄씩 기록한다. 각 거래는 매출채권 또는 임대보증금 중 하나에만 속한다
- 잔액은 계정마다 따로 센다. 매출채권 잔액 = 차변 합 − 대변 합, 임대보증금 잔액 = 대변 합 − 차변 합
- 수익(임대료 수익)·부가세예수금·현금 계정은 이 원장에 두지 않는다. 회사 전체 회계장부의 몫이다
- **기록을 수정하거나 삭제하지 않는다.** 오류는 취소 거래로 상쇄하고 다시 기록한다
- 각 거래는 공급가액·부가세·합계를 한 줄에 기록한다. 세금계산서 1건이 원장 1행에 대응한다
- 퇴거 정산은 별도 화면 없이 보증금 차감·환급 거래로 처리한다

## 2.8 정산

**건물 단위 월 정산**이다. 공과금 고지서를 유닛에 배분해 정산 항목의 청구 금액을 산출한다.

| 개념 | 설명 |
|---|---|
| 정산 회차 | 건물 × 년월. 확정 전까지 재계산 가능 |
| 고지서 | 항목별 수령일·총사용량·공급가액·부가세. 총금액은 합계. 전력기금·TV수신료는 독립 항목 |
| 검침 기록 | 유닛×항목별 검침값. **원본이며 수정하지 않는다** |
| 조정 기록 | 유닛×항목별 배율·작성자. 검침 원본 위에 별도 레이어로 기록 |

산정 절차와 계산식 → 4.1

### 공실 처리

공실 유닛도 다른 유닛과 동일하게 배율대로 안분에 참여한다.
공실 유닛에 산출된 금액은 청구서를 생성하지 않으며 건축주가 부담한다.

배분 기준이 사용량이면 공실 몫은 0에 가깝고, 면적이면 공실 면적만큼 발생한다.
배분 기준은 건물·항목별로 설정한다. → 4.1.7

## 2.10 이력

**누가·언제·무엇을·왜 했는지**를 기록한다. 금액의 흐름은 원장이 담당한다.

| 기록 | 답하는 질문 | 위치 |
|---|---|---|
| 원장 | 미수금이 얼마 증감했는가 | CTR-3 원장 탭 |
| 이력 | 누가 언제 왜 처리했는가 | REC-1, REC-2 |

두 기록은 상호 연결한다. 이력에서 관련 원장 거래로, 원장에서 해당 행위의 이력으로 이동한다.
