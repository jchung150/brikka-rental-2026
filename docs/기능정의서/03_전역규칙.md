# 3. 전역 규칙

전 화면에 공통 적용하는 규칙이다. 화면 명세(5부)는 본 장을 참조한다.
동일 규칙이 화면마다 다르게 구현되지 않도록 여기서만 정의한다.

---

## 3.1 용어

### 필수 용어

| 사용 | 사용 금지 | 비고 |
|---|---|---|
| **임차인** | 입주자, 임차사, 세입자 | 법인·개인사업자를 포괄 |
| **임대인** | 건물주, 집주인 | 화면 표시는 문맥에 따라 `건물주` 허용 |
| **담당자** | 연락처, 실무자 | 임차인의 실무 담당자 |
| **건물고유이름** | 건물명, 빌딩명 | 관리자가 부여하는 식별용 명칭 |
| **유닛고유번호** | 호수, 유닛명 | 관리자가 부여하는 명칭 |
| **계약고유이름** | 계약명 | 자동 조합 |
| **청구항목** | 청구 타입, 과금 항목 | 건물별 목록 |
| **청구** | 청구 내역, 청구서 | 발행된 회차 건 |
| **입금** | 수납금, 납부금 | 실제로 들어온 돈 1건 |
| **수납 배분** | 충당, 할당 | 입금을 청구에 나눈 내역 |
| **전월 미납액 · 전월 과납액** | 이월액, 이월 미납액 | 마감 때 계약에 남은 잔액을 한 줄로 다음 달에 넘긴 것. 받을 돈이면 전월 미납액, 돌려줄 돈이면 전월 과납액. 청구가 아니다. 그냥 `미납액`은 금액을 가리키는 일반 용어다 → 4.3.6 |
| **과납** | 초과납부, 미배분 잔액, 선수금 | 임차인에게 돌려줄 돈. 매출채권 잔액이 0보다 작은 상태 → 4.3.4 |
| **오납** | 오입금 | 낼 의무가 없는 돈이 잘못 들어온 입금. 계약에 속하지 않는다 → 4.3.5 |
| **감액** | 차감, 청구 조정 | 발행한 청구를 줄이는 원장 거래. 관리비 정산의 `조정`(배율)과 다르다 → CTR-3 |
| **추가 청구** | 일회성 청구 | 한 번만 받는 돈. 계약 상세에서 넣고 다음 청구서에 실린다 → CTR-3 |

### 조합 규칙

| 항목 | 조합식 | 예 |
|---|---|---|
| 건물별칭 | 건물 등록 시 입력. 건물고유이름의 축약형 | 카리나 |
| 계약고유이름 | `건물별칭\|유닛고유번호\|대표임차인명` | 카리나\|101호\|커피로스터리담 |
| 유닛주소 | `건물주소 + 유닛고유번호` | 읽기 전용. 유닛별로 입력받지 않음 |

**계약고유이름 조합 규칙**
- 구분자는 `|` 이며 **좌우에 공백을 두지 않는다**
- 각 요소의 **내부 공백을 제거한다** (`커피 로스터리 담` → `커피로스터리담`)
- 계약·유닛·임차인을 함께 표시해야 하는 모든 목록에서 **단일 열로 사용한다**

**계약이 없는 유닛**
- 계약고유이름은 계약의 명칭이므로 계약이 없으면 성립하지 않는다.
  공실·비운영중 유닛은 `건물별칭|유닛고유번호` **두 요소로 표기한다** (예: `카리나|401호`)
- 임차인 자리에 `공실` 등을 채우지 않는다. 유닛상태는 별도 열에서 확인한다
- **유닛고유번호 열을 따로 두지 않는다.** 열을 나누면 단일 열로 쓰는 취지가 사라진다

## 3.2 상태값

### 계약상태 — 4종

| 상태 | 정의 |
|---|---|
| 준비중 | 계약금만 입금되어 유닛을 선점한 상태. 임차인 미사용, 임대료 미발생 |
| 진행중 | **보증금 전액 입금 완료.** 임차인 사용 가능. 인테리어 공사 기간 포함 |
| 종료됨 | 만기 종료 또는 합의에 의한 중도 해지 |
| 파기됨 | 분쟁·위반에 의한 강제 종료 또는 무효 처리 |

### 유닛상태 — 3종

| 상태 | 정의 |
|---|---|
| 공실 | 임대 가능 상태 |
| 사용중 | 진행중 계약이 존재 |
| 비운영중 | 임대하지 않는 유닛. **건물주 직접 사용** 또는 **공사 중** 두 경우뿐이다 |

### 계약상태 → 유닛상태 연동

```
진행중                        → 사용중
계약없음 · 준비중 · 종료됨 · 파기됨 → 공실
비운영중                      → 수동 지정. 계약 상태 연동보다 우선
```

비운영중인 유닛은 계약이 생성되어도 자동 전환되지 않는다.
슈퍼관리자가 비운영중을 먼저 해제해야 한다.

### 계약상태 전이 규칙

| 전이 | 허용 | 확인 메시지 |
|---|---|---|
| 준비중 → 진행중 | 수동 | "보증금 전액 입금이 완료되었습니까? 진행중으로 변경하면 청구 약정에 따라 청구가 시작됩니다. 청구서 발송은 별도로 진행됩니다." |
| 준비중 → 파기됨 | 수동 | "아직 진행되지 않은 계약을 파기 처리하려 합니다. 이 작업은 되돌릴 수 없습니다." |
| 진행중 → 준비중 | 수동 | "청구 약정에 따른 청구가 중단되며, 다음 청구일에 청구서를 발행하지 않습니다." |
| 진행중 → 종료됨 | 해지 처리 | "해지일 이후의 청구가 중단되며, 보증금 정산은 원장에서 처리합니다." |
| 진행중 → 파기됨 | 해지 처리 | "해지일 이후의 청구가 중단되며, 계약은 무효로 처리됩니다. 되돌릴 수 없습니다." |
| 종료됨 → 기타 | **불허** | "종료된 계약은 상태 변경이 불가능합니다. 새로운 계약을 생성하세요." |
| 파기됨 → 기타 | **불허** | "파기된 계약은 상태 변경이 불가능합니다. 새로운 계약을 생성하세요." |
| 만료일 도달 → 종료됨 | **자동** | — |

재계약의 경우 새 계약 시작일에 자동 전환한다.
기존 계약은 종료됨, 연장 계약은 진행중이 되며 보증금 입금 여부를 따지지 않는다.
동일 임차인이 연속 사용하므로 유닛상태는 사용중을 유지한다.

### 납부상태 — 6종

금액으로 정하되, **한 푼도 받지 못한 청구만 납부마감일로 나눈다.** 시스템이 날짜에 따라 자동으로 바꾼다.

| 상태 | 정의 |
|---|---|
| 완납 | 미납액 0 |
| 부분납 | 수납액이 있으나 미납액 잔존. 납부마감일이 지나도 월 마감 전까지는 부분납이다 |
| 납부전 | 수납액 0, **납부마감일 전** |
| 미납 | 수납액 0, **납부마감일 경과** |
| 과납 | 그 달 청구를 다 받고 돈이 남았다(과납액). **청구 건이 아니라 계약 × 청구년월의 상태다.** 남은 돈은 전월 과납액으로 다음 달에 넘어간다 → 4.3.4 |
| 취소 | 청구서를 취소했다 → PAY-1 |

```
미납액        = 청구액 − 감액 − 수납액
과납액        = 청구 건에 배분되지 않고 남은 수납 (어느 청구항목의 돈도 아니다)
미납 청구     = 미납액이 남은 청구 (부분납 · 납부전 · 미납)
연체          = 미납 청구 중 연체일수 1일 이상
연체일수      = 오늘 − 납부마감일 (마감 전이면 "-")
```

**월 마감한 달은 다 받지 못했으면 `미납`이다.** 부분납이었어도 마찬가지다. 남은 돈은 전월 미납액으로 다음 달에 넘어가고(→ 4.3.6),
마감한 달의 청구와 납부상태는 그 뒤로 바뀌지 않는다.

> **`미납`은 상태 이름이다.** 부분납·납부전·미납을 합쳐 부를 때는 `미납액` 또는 `미납 청구`라고 한다.
> 월 마감이 아니라 납부마감일을 기준으로 삼는다. 마감은 관리자가 누르는 시점이라 날짜가 일정하지 않고,
> 연체료도 납부마감일 기준이기 때문이다 → 4.4

납부상태는 직접 수정할 수 없다. 수납 거래를 기록하면 상태가 따라온다.

### 정산상태 — 2종

| 상태 | 정의 |
|---|---|
| 작성중 | 고지서·검침 입력 가능. 재계산 반영 |
| 확정 | 산출 결과를 스냅샷으로 고정. 수정 불가. **그 회차 청구서를 한 장도 발행하지 않았을 때만 해제할 수 있다.** 발행한 회차는 다시 열지 않는다 → PAY-10 |

PAY-12는 여기에 표시용 상태 둘을 더한다. `미착수`(입력이 하나도 없음),
`해당 없음`(이번 회차에 정산할 항목이 없음). 저장하는 상태가 아니다.

### 마감상태 — 2종

건물 × 월 단위로 관리한다.

| 상태 | 정의 |
|---|---|
| 열림 | 해당 월의 청구·수납·취소 거래 등록 가능 |
| **마감** | 해당 월의 원장 거래를 추가·취소할 수 없음 |

마감 후 정정이 필요하면 **이번 달 거래로** 처리한다. 더 받을 돈은 추가 청구, 덜 받을 돈은 감액이다 → CTR-3
마감 취소는 슈퍼관리자만 수행하며 사유 입력이 필수다. → PAY-11

### 계정상태 — 2종

| 상태 | 정의 |
|---|---|
| 정상 | 로그인 가능 |
| 차단됨 | 로그인 불가. 이력·원장의 처리자 기록은 유지 |

계정은 삭제하지 않는다. 접근 차단만 지원한다.

## 3.2-2 청구항목의 분류

| 용어 | 정의 |
|---|---|
| **청구항목** | 청구서에 오르는 항목. **건물마다 따로 둔다.** 기준표 19종에서 고르거나 새로 만든다 → 3.3 |
| 고정액 항목 | 산정방식이 `고정액`인 청구항목. 계약 약정액이 그대로 청구된다. **임대료·고정관리비뿐이다** |
| **정산 항목** | 산정방식이 `정산`인 청구항목. 고지서·사용량에 따라 회차마다 금액이 달라진다 |

정산 항목은 청구항목의 부분집합이며 별개 엔터티가 아니다.

**화면에는 `청구항목` 하나만 노출한다.** `정산 항목`은 본 문서의 분류 용어로만 사용한다.

| 산정방식 | 금액 확정 시점 | 청구 경로 |
|---|---|---|
| 고정액 | 계약 등록 시 (청구 약정) | 반복주기·기산일로 이번 회차 대상을 판정해 청구서 발행 시 생성 → PAY-1 |
| 정산 | 회차마다 (PAY-10) | 정산 확정 결과를 청구서 발행 시 생성 → PAY-1 |

**산정방식은 이 둘뿐이다.** 다음 둘은 청구항목의 산정방식이 아니라 따로 생기는 청구다.

| 청구 | 금액 확정 시점 | 청구 경로 |
|---|---|---|
| 추가 청구 | 계약 상세(CTR-3)에서 넣을 때 | 다음 청구서 발행 시 함께 실린다 → PAY-1 |
| 연체료 | 수납 처리(PAY-2)에서 받기로 할 때 | 받은 날 청구 1건으로 생성한다 → 4.4.3 |

### 3.2-3 유닛상태 화면 표기

유닛상태는 금액과 청구 대상을 가르는 정보이므로 어느 화면에서나 확인 가능해야 한다.
다만 **표기 방식은 화면의 성격에 따라 둘로 나눈다.**

| 화면 성격 | 표기 | 예 |
|---|---|---|
| 목록·관리 — 상태로 정렬·필터하는 화면 | **독립 칼럼 또는 카드의 상태 배지** | PRO-3 유닛 카드, CTR-1 계약 목록 |
| 계산·작업 — 행 단위로 값을 입력·확인하는 화면 | **계약고유이름 뒤 칩** | PAY-10 전 단계 |

**칩은 예외 상태에만 붙인다.** 기본값 `사용중`은 표시하지 않는다.
칩이 없으면 사용중, 있으면 예외다. 전 행에 칩을 붙이면 예외가 묻힌다.

**설계 의도**
계산 화면에서 상태를 독립 칼럼으로 두면 "정렬·필터할 수 있는 별개 데이터"로 읽히는데,
그 화면에서 상태는 계약고유이름이라는 신원에 딸린 속성이다. 계약이 없는 유닛은
계약고유이름이 이미 두 요소(`건물별칭|유닛고유번호`)로 표기되어 공실임을 드러내므로,
칩은 그것을 말로 확인해 주고 `비운영중`처럼 계약이 있으면서 청구가 다른 경우를 구분한다.

### 발행 문서 — 3종

**과세 구분은 발행 문서에 포함된다.** 별도 설정으로 두지 않는다.

| 발행 문서 | 과세 구분 | 부가세 | 예 |
|---|---|---|---|
| **세금계산서** | 과세 | 공급가액의 10% | 임대료 · 고정관리비 · 전기요금 · 주차비 |
| **계산서** | 면세 | 없음 | 수도요금 · 정화조청소비 · 교통유발부담금 |
| **일반내역서** | 비과세 | 없음 | 전력기금 · TV수신료 |

- **같은 발행 문서끼리 묶여 계약당 1장으로 발행된다.** 한 계약에 세금계산서 1장,
  계산서 1장이 나갈 수 있다
- `일반내역서`는 세금계산서·계산서 대상이 아닌 항목이다. 내역서로만 전달한다
- **`묶음`이라는 용어를 쓰지 않는다.** 실제로 정하는 것은 발행 문서이며,
  묶음은 그 결과로 생긴다. 두 개념을 따로 두면 어긋난 조합이 생긴다

### 반복주기 — 5종

`매월` / `격월` / `분기` / `반기` / `연1회`

정산 항목의 주기는 항목마다 다르다.
예: 전기요금 매월 / 수도요금 격월 / 교통유발부담금 연1회 / 정화조청소비 반기

`이번만`은 두지 않는다. 한 번만 받는 돈은 계약 상세의 추가 청구로 넣는다 → CTR-3

### 항목 관리 원칙

- **기준표 19종은 시스템이 미리 알 수 있는 항목의 목록일 뿐이며 전부가 아니다.**
  공용 회의실 사용료처럼 건물 운영 중에 새로 생기는 항목은 관리자가 추가한다
- **항목은 건물 관리비 탭(PRO-3)에서만 추가·수정한다.** 별도의 청구항목 관리 화면을 두지 않는다
- 기준표 항목을 고르면 기본값이 채워진다. 기준표에 없는 항목은 이름을 입력해 새로 만든다. **그 건물에만 생긴다**
- **건물당 최대 99개.** 배분 우선순위 1~99를 **건물 안에서 겹치지 않게** 하나씩 쓴다. 연체료는 99로 고정한다
- 기준표 항목은 **이름 수정 불가.** 새로 만든 항목은 한 번도 청구하지 않았을 때만 이름을 고칠 수 있다
- 발행 문서·반복주기·우선순위·배분 설정은 수정 가능
- **산정방식은 고칠 수 없다.** 계약에 약정하는 고정액 항목은 **임대료·고정관리비뿐이다.**
  나머지 기준표 항목과 새로 만든 항목은 모두 `정산`이며, 관리비 정산에서 임대면적 비율이나 직접 입력으로 청구한다 → PAY-10
- 한 번도 청구하지 않은 항목은 삭제할 수 있다. 청구한 적이 있으면 삭제 대신 **미사용**으로 전환한다.
  기존 계약과 과거 원장 기록은 유지

## 3.4 금액·부가세 표기

### 화면 성격에 따라 기준이 다르다

| 화면 성격 | 해당 화면 | 표기 기준 |
|---|---|---|
| 약정 | CTR-1, CTR-2, CTR-3, CTR-4, PAY-3, PRO-4 계약정보 | **부가세 포함으로 입력·표시.** "(부가세 포함)" 병기. 공급가액·부가세는 청구서에서 나눠 보인다 |
| 청구·수납·미납 | PAY-1, PAY-2, PAY-6 | **부가세 포함 합계.** 공급가액·부가세 함께 표시 |
| 원장 | CTR-3 | **합계(부가세 포함)만 표시한다.** 공급가액·부가세는 저장하되 보이지 않는다 |

**약정액(임대료·고정관리비)은 부가세 포함 금액으로 입력하고 저장한다.** 입력 화면에는 공급가액·부가세를 보이지 않는다. 실무에서 계약서와 대화가 모두 부가세 포함 금액으로 오가기 때문이다.
공급가액과 부가세는 역산한다: 공급가액 = 약정액 ÷ 1.1 (원 미만 절사), 부가세 = 약정액 − 공급가액 → 4.2.6.
청구·수납도 실제로 주고받는 금액이므로 부가세 포함으로 표기한다. 화면 전체가 부가세 포함 기준이다.

### 부가세 원칙

- 과세 여부는 항목의 **발행 문서**가 결정한다 → 3.3. 별도의 부가세대상여부 설정을 두지 않는다
- 면세·비과세 항목은 부가세를 0으로 기록한다
- **보증금은 부가세 대상이 아니다**
- 연체료는 과세 항목이다. 산출액은 부가세 포함 금액이다 → 4.4
- **청구서 합계는 100원 미만을 자동 절사한다.** 항목별 금액은 원 미만 절사 → 4.2.6

## 3.5 날짜 규칙

### 오늘 날짜 표시

**모든 화면 오른쪽 위에 오늘 날짜를 표시한다.** 형식은 `2026년 8월 10일(월)`이다. 눈에 띄지 않게 흐린 글씨로 둔다.
납부상태(납부전/미납), 연체일수, 연체료, 마감 가능 여부가 모두 오늘을 기준으로 정해지기 때문이다.

### 계약시작일과 기산일의 분리

| 날짜 | 기준이 되는 것 |
|---|---|
| **계약시작일** | 계약 기간, 유닛상태, 공실률, 만료 잔여일 |
| **청구 기산일** | 임대료·관리비의 청구 시작일. 청구항목마다 별도 |

기산일은 계약시작일보다 앞설 수도(소급) 뒤설 수도(렌트프리) 있다.
기본값은 계약시작일이며, 등록 화면에서 체크박스로 열어 입력한다.

```
기산일 < 계약시작일   소급     (예: 8/13 계약, 8/1부터 임대료 산정)
기산일 = 계약시작일   일반
기산일 > 계약시작일   렌트프리
```

**렌트프리는 계약 등록 때 항상 묻는다(있음 / 없음, 필수).** 실무에서 거의 매번 나오고, 계약시작일과 기산일이 다른 대부분의 이유가 렌트프리다.
있음이면 기간과 대상 항목을 입력받고, **기산일은 렌트프리가 끝난 다음 날로 자동 계산한다.**
기간은 개월(1.5개월처럼 소수 가능)로 넣거나 **끝나는 날을 직접** 넣는다. 35일처럼 개월로 떨어지지 않는 경우가 있기 때문이다.
없음이면 기산일은 계약시작일이다. 소급처럼 기산일이 다른 경우만 `기산일을 따로 정하기`로 직접 입력한다.

| 항목 | 내용 |
|---|---|
| 렌트프리 기간 | 계약시작일 ~ 끝나는 날. 개월로 넣으면 끝나는 날을 계산한다(소수는 30일 기준: 1.5개월 = 1개월 + 15일) |
| 대상 항목 | 임대료 · 고정관리비 · 정산 항목(전기·수도 등) 중 선택. 기본은 임대료만 |
| 대상 항목의 청구 | 기간 동안 청구하지 않는다. 기산일부터 청구한다 |
| 대상이 아닌 항목 | 계약시작일부터 청구한다 |

정산 항목이 렌트프리 대상이면 그 기간 산출분은 청구하지 않고 건축주가 부담한다(공실·미청구분과 같다) → 4.1.7.
`렌트프리 중` 판정은 `렌트프리 적용 · 계약시작일 ≤ 오늘 < 기산일`이다.

### 청구일과 납부마감일

| 항목 | 설정 위치 | 설명 |
|---|---|---|
| 청구일 | 건물 기본값. 계약에서 덮어쓸지는 미확정 → 4.7 | 청구서 발행일 (예: 매월 19일) |
| 납부마감일 | **건물 설정. 계약·청구서마다 바꾸지 않는다** | 납부 기한 (예: 매월 말일) |

청구항목별로 두지 않는다. 청구서가 계약당 1장으로 발행되기 때문이다.
납부마감일은 건물마다 정한 규칙이다. 연체료와 미납 판단이 모두 이 날을 기준으로 하므로 청구서마다 다르게 두지 않는다.
청구일 기본값 변경은 이후 등록되는 계약에만 적용한다. 기존 계약은 유지한다.

### 일할 계산

해당 기간의 **실일수**를 기준으로 한다. **시작일과 퇴거일을 모두 포함**한다.

```
청구액 = 월 약정액 × 청구 대상 일수 ÷ 해당 기간 총일수
```

상세 및 예시 → 4.2

### 계약 기간 기본값

| 화면 | 기본값 |
|---|---|
| CTR-2 신규 계약 | 계약시작일로부터 2년 후의 전날 |
| CTR-4 재계약 | 계약시작일로부터 2년 후의 전날. 시작일은 기존 종료일 다음날 |

|---|---|
| 건물 등록·삭제, 계약 삭제 | 유닛·계약 등록·수정·해지 |
| **월 마감 취소** | 월 마감 |
| — | 건물별 청구 주기 기본값 |
| **계약의 임대료·고정관리비 수정 · 인상 예약** | 정산액 대납 계약 지정 |
| **건물별 관리비 설정** | — |
| 사용자 등록·권한 변경·차단 | 청구서 발행·취소, 청구 정정(감액·추가 청구) |
| **관리자별 담당 건물 배정** | 수납 등록·배분·입금 무효, 환불, 오납 표시·환불 기록 |
| 유닛 `비운영중` 지정·해제 | 검침·정산, 문서 관리, 엑셀 내보내기 |

### 담당 건물 배정

슈퍼관리자가 USER-3에서 관리자별로 담당 건물을 복수 지정한다.
건물·유닛·계약·청구·수납·정산·문서의 **모든 조회와 수정**에 적용한다.
미배정 관리자는 조회 가능한 건물이 없다. 슈퍼관리자는 배정과 무관하게 전체를 조회한다.

[2차] 역할 정의와 기능별 권한 부여는 권한 관리(USER-4·5)와 함께 구현한다.

### 계정 생성 경로

계정이 생성되는 경로를 하나로 제한한다. 중복 계정 발생을 방지하기 위한 규칙이다.

| 역할 | 생성 화면 |
|---|---|
| 슈퍼관리자 | SYS-2 운영사 등록 (시스템 운영자가 발급) |
| 관리자 | USER-3 사용자 등록 |
| 임대인 | PRO-2 건물 등록 |
| 임차인 담당자 | CTR-2 계약 등록 |

USER-2 사용자 조회에서는 네 역할 모두 조회 가능하나, 임대인·임차인은 신규 생성하지 않는다.

### 비밀번호 처리

- 시스템이 임시 비밀번호를 생성해 메일로 발송하지 않는다
- 계정 생성 시 **로그인 링크가 담긴 초대 메일**을 발송하고, 본인이 직접 설정한다
- 관리자가 타인의 비밀번호를 지정할 수 없다. 재설정 메일 발송만 지원한다

## 3.8 공통 UI 규칙

### 메뉴

- 사이드바는 도메인별 그룹과 하위 화면으로 구성한다
- **청구·수납 그룹을 클릭하면 PAY-12 청구·수납 현황을 연다.** PAY-12는 하위 메뉴에 따로 두지 않는다
- **그 외 그룹은 클릭하면 첫 하위 화면으로 이동한다.** 그룹 자체의 빈 화면을 두지 않는다

### 목록 화면

| 요소 | 규칙 |
|---|---|
| 필터 | 건물고유이름은 드롭다운. 상태값은 체크박스 |
| 정렬 | 목록별로 기본 정렬 기준을 명시. 남은 일수·금액은 오름/내림차순 지원 |
| 더보기 | 표 맨 오른쪽 칸, 머리글은 `더보기`. **버튼이 아니라 링크다.** 할 일이 하나면 그 이름을 링크로, 둘 이상이면 ⋮(케밥)을 눌러 드롭다운으로 연다. 할 수 없는 일은 흐린 글씨로 두고 이유는 마우스를 올리면 보인다. 행 클릭 시 상세로 이동 |
| 페이징 | 서버 페이징. 기본 25건 |
| 빈 목록 | 조건에 맞는 데이터가 없음을 안내. 빈 표를 그대로 노출하지 않음 |
| 행 높이 | **행의 값은 한 줄이다.** 보조 정보(별칭·지번·연락처·참조 항목 등)는 값 아래에 옅은 글씨 한 줄까지 둘 수 있다. 그보다 많은 정보는 열을 만들거나 펼침 안에 둔다 |

### 상세 화면

| 요소 | 규칙 |

| 탭 구성 | 좌측부터 요약 → 세부 정보 → 부속 정보 순 |
