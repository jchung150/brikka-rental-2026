# 5-2. 화면 명세 — 계약 관리 (CTR)

| 화면 | 명칭 | 주요 액션 |
|---|---|---|
| CTR-1 | 계약 정보 조회 | 조회 |
| CTR-2 | 계약 정보 등록 | 생성 |
| CTR-3 | 계약 정보 조회(상세) 및 수정 | 조회, 수정, 해지, 삭제 |
| CTR-4 | 계약 연장(재계약) | 생성 |

## CTR-1 · 계약 정보 조회

**목적** 전체 계약을 목록으로 조회한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 계약 관리 / DASH-1 만료 임박 카드

### 【입출력 항목】

```
필터: 건물고유이름,
      계약상태(디폴트: 진행중 / 준비중·진행중·종료됨·파기됨),
      계약만료남은일수(만료됨 / 30일이하 / 90일이하 / 180일이하)

[목록]
계약만료남은일수
계약고유이름(건물별칭|유닛고유번호|대표임차인명)
계약상태
현재계약조건(계약시작일, 계약종료일, 보증금, 임대료, 관리비)
계약유형(확정기간계약 / 확정기간후자동갱신)
더보기(계약상세보기, 재계약하기, 계약상태변경, 계약해지, 계약삭제)
```

### 【동작 규칙】

- 상단에 `새로운 계약 등록` 버튼을 배치한다 → CTR-2
- 행 클릭 시 계약 상세로 이동한다 → CTR-3
- 계약고유이름은 자동 조합한다 → 3.1
  예: `카리나|801호|(주)한빛`
- 계약조건은 조합해 표시한다
  예: `2025.08.13 - 2026.08.12 | 보증금 1억 | 임대료 770만원 | 관리비 198만원`
- **임대료·관리비는 부가세 포함 월 금액으로 표시하고, 열 제목에 `(부가세 포함)`을 병기한다.**
  임차인이 매달 실제로 내는 돈으로 보기 위해서다. 보증금은 부가세 대상이 아니다 → 3.4
- 기산일이 계약시작일과 다른 경우에만 금액 옆에 기산일을 병기한다
  예: `임대료 700만원 (2025.08.01부터)`
- **렌트프리 중인 계약은 `렌트프리 중` 배지를 표시한다.** 판정식은 `렌트프리 있음 · 계약시작일 ≤ 오늘 < 기산일` → 3.5
- 계약만료남은일수는 **계약종료일 기준**으로 계산한다. 갱신 통지 마감일을 별도로 두지 않는다
- 남은 일수는 진행중 계약에만 표시하고 나머지는 `—`로 둔다. 30일 이하이면 강조 색상으로 표시한다
- 기본 정렬은 남은 일수 오름차순이다. 오름·내림차순 정렬을 지원한다
- 고정관리비가 0원인 계약은 관리비 자리에 `관리비 없음`으로 표시한다
- `재계약하기`는 진행중 상태에서만 활성화한다
- 계약상태 변경 시 해당 유닛의 유닛상태가 자동 연동된다 → 3.2

### 【설계 의도】

- 갱신 통지 마감일을 별도로 두지 않는다. 종료일과 두 날짜를 동시에 관리하면 혼동이 발생하므로 계약종료일 하나를 기준으로 삼는다

### 【연관 화면】 CTR-2, CTR-3, CTR-4, DASH-1
### 【알림】 없음

### 【동작 규칙】

**건물**
- 비운영중인 건물은 고를 수 없다(목록에 `(비운영중)`으로 흐리게) → 3.2 건물 운영상태

**계약상태**
- 기본값은 준비중이며 진행중으로 변경할 수 있다
- **준비중 → 진행중 전환은 수동으로만 수행한다.** 계약시작일 도래는 전환 사유가 아니다 → 3.2
- 계약 만료일 도달 시 종료됨으로 자동 전환한다

**임차인·담당자**
- 임차인은 법인 또는 개인사업자이며 사업자등록번호로 식별한다. **주민등록번호는 수집하지 않는다**
- **사업자등록번호는 유일값이다.** 입력 시 이 시스템에 이미 있는 임차인인지 확인해, 있으면 그 임차인에 계약을 붙이고 없을 때만 신규 등록한다 → USER-6.
  같은 임차인이 계약을 여러 건 갖기 때문이다((주)아이씨비 본관701호·본관801호). 두 번 만들면 입금 매칭·미납이 임차인별로 모이지 않는다
- 사업자 정보는 USER-7에서 수정하며 해당 사업자의 모든 계약에 공통 반영된다. 담당자 정보는 본 계약에만 적용된다
- **임차인 담당자 계정은 이 화면에서만 생성한다** → 3.7

**날짜**
- 계약시작일 입력 시 계약종료일은 **2년 후의 전날**로 자동 설정한다. 수정 가능하다
- 청구일과 납부마감일은 건물 설정을 그대로 따른다. 계약마다 다르게 두지 않는다 → 3.5
- 청구 기산일은 계약시작일과 별개다. 소급·렌트프리 모두 이 항목으로 표현한다 → 3.5
- 렌트프리가 있으면 **체크한 항목만** 기산일부터 청구하고, 체크하지 않은 항목은 계약시작일부터 청구한다 → 3.5

**청구**
- **임대료와 고정관리비는 필수다.** 빈칸이면 저장할 수 없다. 고정관리비는 **0을 넣을 수 있고**, 0이면 청구하지 않는다.
  예: 본관301호(고우컴퍼니)는 임대료만 내고 나머지는 모회사 계약(302호)이 낸다
- 등록 뒤의 조정은 계약 상세 요약 탭(임대정보 · 임대료 인상 예약)에서 한다. 나중에 고정관리비를 받게 되면 `수정`에서 금액을 넣는다
- 임대료·고정관리비가 모두 없는 계약(모회사가 전부 내는 동거 계약 등)은 이 시스템에서 다루지 않는다
- **정산 항목은 계약에 저장하지 않는다.** 모든 계약은 건물 관리비 탭에서 `사용` 중인 정산 항목을 그대로 받는다. 금액은 매 회차 PAY-10에서 산출한다.
  임차인이 전용부를 공급자에게 직접 내는 항목은 그 유닛에 계량기를 두지 않는다. 공용분만 청구된다 → 4.1.7-2
- 과세 여부는 청구항목의 발행 문서가 결정한다. 계약에서 따로 정하지 않는다 → 3.3
- **정산액 대납 계약**은 계약 상세 요약 탭 임대정보의 `수정` 패널에서 지정한다. 지정하면 이 계약의 정산 항목은 지정된 계약의 청구서에 `대납`으로 실린다.
  고정액 항목은 옮기지 않는다. 같은 건물의 진행중·준비중 계약만 선택할 수 있다 → 4.1.7-3
- 정산 항목은 금액이 0원일 수 있다 (예: 무상 주차 3대 중 2대 사용). 0원 항목은 청구서에서 생략한다
- 무상 주차 대수·초과 단가는 주차비 금액을 계산하는 근거다. 1차는 관리비 정산(PAY-10)에서 주차비를 계약별로 직접 입력한다 → 4.1.3-2

**임대료 인상 예약**
- 계약서에 `0000년 00월 00일부터 임대료·관리비 얼마` 형태로 명시된 경우 입력한다. 5년 이상 장기 계약에 흔하다
- 대부분 임대료와 고정관리비가 함께 바뀌므로 **한 일정에 두 금액을 같이 입력한다**
- 적용일부터 **새 금액으로 자동 청구한다.** 관리자가 잊어도 계약서대로 청구되게 하기 위해서다 → 4.2.7
- 적용일 30일 전에 관리자에게 알린다(확인용). 알림을 놓쳐도 청구는 바르게 된다

**검증**
- **같은 유닛의 진행중 계약과 기간이 겹치면 등록을 차단한다.** 진행중 계약이 끝나는 다음 날부터 시작하는 계약은 미리 등록할 수 있다
  (다음 임차인과 먼저 계약하는 실무). 유닛을 고르면 화면 안에 겹치는 계약과 가능한 시작일을 안내한다
- 준비중 계약과 기간이 겹치면 안내만 하고 저장은 허용한다
- 렌트프리 `있음`이면 기간(끝나는 날)도 필수다. 끝나는 날을 직접 고르면 개월 칸을 비운다.
  계약시작일이 없으면 `계약시작일을 먼저 넣으세요`, 끝나는 날이 계약시작일보다 앞이면 `끝나는 날이 계약시작일보다 앞입니다`를 표시한다
- 보증금 반환예정일은 계약종료일을 기본값으로 따라간다. 직접 고치면 그 값을 유지한다
- 필수 항목이 빠졌거나 기간이 겹치면 저장 버튼 위에 `저장할 수 없습니다`와 빠진 항목을 표시한다

**저장**
- 맨 아래에 `취소` · `저장 (웰컴 메일 안 보냄)` · `저장 및 웰컴 메일 보내기`를 둔다. 취소는 저장 왼쪽이다(건물 등록과 같다)
- 저장하면 계약 상세(CTR-3)로 이동한다. 보증금은 아직 받지 않은 상태이므로 원장에 `보증금 예치`가 없다. 받으면 기록한다
- **웰컴 메시지 전송 여부와 무관하게 임차인 계정의 비밀번호를 변경하지 않는다.** 기존 임차인의 추가 계약 시 계정이 잠기지 않아야 한다
- 웰컴 메시지에 임시 비밀번호를 담지 않는다. 계정 신규 생성 시 로그인 링크가 담긴 초대 메일을 발송한다 → 3.7

**제외 항목**
- 반려동물, 외국인 정보는 사용하지 않는다. 차량은 등록 차량으로 따로 관리한다 → PRO-3 주차 탭
- [2차] 가상계좌 발급 → PAY-7
- [2차] 알림 선호 채널 설정 → NTF 계열

### 【설계 의도】

- 보증금 전액 입금을 확인한 뒤 담당자가 진행중으로 바꾼다(자동 전환하지 않는다 → 3.2). 계약금만 입금된 상태에서는 임차인이 공간을 사용하지 않으므로 임대료가 발생하지 않는다
- 계약 대표자와 실무 담당자를 분리한다. 같은 사업자라도 건물·유닛에 따라 담당자가 다르다
- 렌트프리는 등록 때 항상 묻는다. 실무에서 계약시작일과 기산일이 다른 이유 대부분이 렌트프리다. 기간은 개월 또는 끝나는 날로 받고 기산일은 계산한다 → 3.5
- 메일 본문에 비밀번호를 평문으로 담지 않는다. 임차인 계정은 계약·청구 정보에 접근한다

### 【동작 규칙】

**수정 범위**
- 수정 불가 항목은 잠금 아이콘 + 회색 비활성화로 표시한다
- **유닛고유번호는 수정할 수 없다**
- 계약시작일은 수정 가능하나 `계약 기간, 유닛상태, 공실률 집계에 영향을 줍니다` 경고를 표시한다
  청구 시작일은 기산일로 별도 관리하므로 청구 약정은 영향받지 않는다 → 3.5

**청구 정정 — 덜 받기(감액) · 더 받기(추가 청구)**
- 버튼은 하나이고 패널 안에서 방향을 고른다. **기록 방식은 방향마다 다르다** — 덜 받기는 원래 청구 항목을 오늘 날짜로 줄이고,
  더 받기는 다음 청구서에 새 항목으로 싣는다. 세금계산서가 원래 청구에 붙어 있어 덜 받을 돈을 다음 달 청구에서 빼지 않는다
- **감액** — 발행한 청구 건의 금액을 줄인다. 원장에 `감액`(매출채권 대변)을 **오늘 날짜로** 기록하고 원 청구는 그대로 둔다
  - 마감한 달의 청구도 감액할 수 있다. 거래일이 오늘이라 잠긴 달을 건드리지 않는다. 그 달은 바뀌지 않고 다음 달로 넘어가는 잔액이 준다 → 4.3.6
  - 이미 낸 금액보다 작아지면 그 차이가 과납이 된다 → 4.3.4
  - 감액 합계는 원 청구액을 넘을 수 없다. 늘리는 감액은 없다. 세금계산서 항목의 수정세금계산서는 미확정 → 4.7
- **추가 청구** — 한 번만 받는 돈(엘리베이터 사용료, 파손 수리비, 지난달 정산에서 더 받을 차액)을 넣는다
  - **다음 청구서에 함께 실린다**(PAY-1). 원장에는 그때 `청구`로 기록되며, 실리기 전에는 지울 수 있다
  - 지난 청구 항목을 고르면 이름은 `26.07월분 전기요금 정정`, 발행 문서는 그 항목의 것을 따른다. 사유는 필수다
  - 원장에 바로 청구를 넣지 않는다. 청구서·세금계산서·납부마감일 없이 받을 돈만 생기기 때문이다
  - 안분하지 않는다. 우선순위는 99다(연체료와 같음) → 4.3.1
- 원장 표 안에는 버튼을 두지 않는다. 원장은 있는 그대로 보여 주는 곳이다

**잔액 표시**
- 미납 잔액(매출채권)과 보증금 잔액(임대보증금)을 나누어 표시한다. **합산하지 않는다** → 2.7
- 원장 위에는 `보증금 ○원`만 적는다. 미납·과납은 청구·수납 탭에서 본다.
  과납은 다음 달로 넘어가 다음 청구서를 발행할 때 먼저 배분되어 낼 돈이 준다. 돌려줄 때는 원장 탭의 `환불`로 기록한다 → 4.3.4

**임대료 인상 예약**
- 적용일부터 **새 금액으로 자동 청구한다.** 관리자가 잊어도 계약서대로 청구되게 하기 위해서다
- 적용일이 속한 청구년월의 청구서부터 새 금액이 실린다. 적용일이 달 중간이면 그 달은 전·후 금액을 일수로 나눠 합한다 → 4.2.7
- 적용일이 지나면 적용상태가 `적용완료`가 되고 약정액이 바뀐다. 바뀌기 전 금액은 이력에 남는다 → 3.6
- 임차인과 협의해 시기나 금액이 바뀌면 **적용일 전에 일정을 수정한다.** 별도의 `유예` 상태를 두지 않는다

**계약 해지**
- 요약 탭 계약정보 카드 오른쪽 위의 `해지`(진행중 계약만)를 누르면 오른쪽 패널이 열린다
  해지 정보: 해지유형, 해지일(명도일), 해지사유(필수), 위약금, 원상복구비
  아직 고지되지 않은 기간: 정산 항목마다 `전기요금 08.10 ~ 08.20 · 11일 고지 전`과 예상 금액 입력칸 → 4.1.9
  버튼: 닫기 · 해지 처리. 예상 금액을 넣은 항목은 마지막 청구서에 추가 청구 `○○ 퇴거 예상분 (기간)`으로 붙는다
- 해지유형을 먼저 선택한다. 유형에 따라 계약상태가 결정된다

| 해지유형 | 계약상태 |
|---|---|
| 만기 종료 | 종료됨 |
| 중도 해지(합의) | 종료됨 |
| 중도 해지(위반·분쟁) | 파기됨 |

- 해지일(실제 명도일), 해지사유, 위약금, 원상복구비를 입력받는다
- 해지일 이후의 청구를 중단한다
- **해지일이 입력되면 고정액 항목은 청구서 발행 시 자동으로 일할 계산한다.** 해지일이 당월 청구일 이전이면 당월 청구서를 발행하지 않고, 일할분을 **퇴거 정산 청구서**로 생성해 `보증금상계`로 수납 처리한다 → 4.2.3
- 청구서 발행 후 해지가 확정된 경우 발행된 청구서는 변경하지 않고, 차액을 퇴거 정산에서 보증금 환급액에 가감한다
- 미납금·위약금·원상복구비는 원장에 `보증금 차감`으로, 잔액은 `보증금 환급`으로 기록한다. **퇴거 정산은 별도 화면 없이 원장에서 처리한다**

**계약 삭제**
- 기본적으로 삭제를 금지하며 슈퍼관리자에 한해 조건부로 허용한다
  - 조건 1: 해당 계약에 발행된 청구서가 1건도 없을 것
  - 조건 2: 다른 계약의 연장 계약이 아닐 것
- 경고 메시지: `이 작업은 슈퍼 관리자만 할 수 있으며, 발행된 청구서 및 연장 계약이 없어야 합니다. 삭제하면 복구할 수 없습니다. 계속하시겠습니까?`

**원장**
- **이 계약의 모든 돈 거래를 있는 그대로 보여주는 곳이다.** 수납 내역(PAY-6)·미납 관리(PAY-2)은 원장을 모아 보여줄 뿐이며,
  근거가 필요하면 원장을 본다. 계약 상세의 원장 탭으로 들어오며, 수납 내역(PAY-6) 더보기의 `원장 보기`로도 바로 온다
- **원장은 추가만 하고 고치지 않는다.** 잘못된 거래는 취소 거래(청구 취소·수납 취소)나 감액을 추가해 바로잡는다 → PAY-1, PAY-9
- 청구는 청구 건마다, 수납은 수납 배분마다 1행이다. 입금 1건이 여러 청구에 배분되면 수납 행도 여러 개다
- **수납 행은 합계만 기록한다.** 공급가액·부가세는 청구 행에 있다
- **연체료는 수납 처리에서 받기로 한 금액만 원장에 올라온다.** 받은 날 `청구` 한 줄로 기록하고 내용에 감면액을 적는다
  (`연체료 (08.10까지 · 68,433원 중 13,433원 감면)`). 받기 전에는 미납 관리(PAY-2)에 예상액으로만 보인다 → 4.4.3
- 보증금상계로 수납하면 `보증금 차감`(임대보증금 차변)과 `수납`(매출채권 대변)이 같은 날 함께 기록된다
- `원장 출력`은 선택한 기간·계정의 원장을 거래내역서(PDF)로 만든다. 내려받거나 임차인 담당자에게 발송한다.
  **임차인이 미납·연체료의 근거를 요구하면 이것을 준다.** 별도의 연체료 내역서를 두지 않는다
- 거래유형 9종과 계정 구분, 운용 원칙은 → 2.7
- 청구 거래는 공급가액·부가세·합계를 한 행에 기록한다. 세금계산서의 품목 1줄이 원장 청구 1행에 대응한다
- 매출채권과 임대보증금을 합산하지 않는다
- 청구서를 발행하면(PAY-1) 청구 건마다 본 원장에 `청구` 거래로 기록된다
- 거래번호는 PG 거래 식별자다. [2차] PG 연동 전까지 비워둘 수 있다

**임대정보 · 임대료 인상 예약**
- **계약마다 다른 것은 임대료·고정관리비의 약정 금액뿐이다.** 임대정보 카드에는 청구 금액으로 이 둘만 둔다
- **정산 항목(전기·수도 등)은 계약에 두지 않는다.** 모든 계약이 건물 관리비 탭(PRO-3)의 정산 항목을 그대로 받는다.
  켜고 끄는 스위치가 없다. 전용부를 공급자에게 직접 내는 유닛도 공용분은 낸다 → 4.1.7-2
- **청구 여부는 약정 금액으로만 정한다.** 0원이면 청구하지 않는다. 다시 받게 되면 `수정`에서 금액을 넣는다
- 임대정보 `수정` · 임대료 인상 예약 `+ 일정 추가`는 오른쪽 패널을 연다 → PAY-3
- **별도의 임대료·관리비 탭과 임차인 탭을 두지 않는다.** 같은 계약의 약정이 탭마다 흩어지면 같은 값을 두 곳에서 보게 된다.
  임차인의 사업자 정보(상호 · 대표자 · 주소 · 업태)는 여러 계약에 공통이라 임차인 관리(USER-7)에서 보고 고친다
- 정산액 대납 계약이 지정된 계약은 정산 항목을 자기 청구서에 싣지 않는다. 그 몫은 지정된 계약의 청구서에 `대납`으로 실린다 → 4.1.7-3

**이력**

- 웰컴 메시지 전송 성공 여부와 무관하게 재전송 버튼을 활성화한다

**계약상태 전이**

- 합의에 의한 중도 해지를 `파기됨`으로 분류하지 않는다. 어감이 부정적이며 이력에 그대로 남는다

- 냉난방기 구분을 계약마다 남긴다. 퇴거 때 철거·원상복구를 임차인이 할지, 다음 임차인에게 넘길지, 건물주 설비로 둘지를 가리는 근거다

### 【동작 규칙】

**활성화 조건**
- **진행중인 계약이면 시점 제한 없이 활성화한다.** 입주 도중 조건 변경, 만기 직전 연장 모두 포함한다

**계약 기간**
- 계약시작일 기본값은 기존 계약종료일 다음날이며 수정 가능하다
- **기존 계약 기간 중의 날짜로 지정하면 기존 계약의 종료일이 새 계약 시작일 전날로 자동 조정된다.** 한 유닛에 진행중 계약이 중복되지 않도록 한다
- 계약종료일 기본값은 계약시작일로부터 2년 후의 전날이다

**상태 전환**
- 새 계약 시작일에 자동 전환한다. 기존 계약은 종료됨, 연장 계약은 진행중이 된다
- **동일 임차인이 연속 사용하므로 보증금 입금 여부와 관계없이 전환하며, 유닛상태는 사용중을 유지한다**
- 이는 `보증금 전액 입금 확인 후 진행중`(→ 3.2 계약상태)의 재계약 예외다

**보증금 승계**
- 보증금 기본값은 기존 보증금이며 수정 가능하다
- 기존 보증금은 연장 계약으로 승계한다
  - 기존 계약 원장: `보증금 환급` (실제 입출금 없음. `재계약 승계`로 표시)
  - 연장 계약 원장: `보증금 예치` (동일)
- 증액분은 받았을 때 연장 계약에 `보증금 예치`로, 감액분은 돌려줄 때 `보증금 환급`으로 기록한다

**등록 차량**
- 등록 차량은 연장 계약으로 그대로 이전한다. **기존 계약 종료로 해제되지 않는다**

**자동갱신 계약**
- 확정기간후자동갱신 계약은 만기 30일 전 대시보드에 표시한다 → DASH-1
- 동일 조건 갱신 시 재계약 화면에서 금액을 변경하지 않고 저장한다

**제외 항목**
- **재계약 안내 이메일과 알림톡을 발송하지 않는다**
- 반려동물, 외국인 정보는 사용하지 않는다. 차량은 등록 차량으로 따로 관리한다 → PRO-3 주차 탭
- [2차] 가상계좌는 PG 연동 시 기존 계약의 가상계좌를 승계한다 → PAY-7

### 【설계 의도】

- 재계약은 합의 결과를 담는 기능이다. 합의서 발송과 확인·날인은 시스템 밖에서 진행하므로 안내 메시지를 발송하지 않는다
- 연장 계약을 수동 전환으로 두면 관리자가 전환하기 전까지 유닛이 공실로 집계된다. 동일 임차인이 끊김 없이 사용하므로 자동 전환한다
- 인상률을 자동 표시하지 않는다. 협상 중 금액이 수시로 변동하므로 고정 표시의 실효성이 없다
