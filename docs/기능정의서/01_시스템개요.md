# 1. 시스템 개요

## 1.1 무엇을 하는 시스템인가

**상업용 빌딩(오피스·상가·지식산업센터 등)의 임대 운영을 관리하는 백오피스 시스템**이다.

관리 회사의 담당자가 이 시스템으로 다음을 수행한다.

- 건물과 유닛을 등록하고 공실 현황을 관리한다
- 임차인(사업자)과의 계약을 등록·연장·해지한다
- **매달 관리비를 정산하고 청구서를 발행한다**
- **입금을 기록하고 미납을 관리한다**
- 임대인에게 월간 보고서를 전달한다

### 주거용 임대관리와 다른 점

이 시스템의 설계는 주거용과 구조적으로 다르다. 개발 전에 반드시 인지해야 한다.

| | 주거용 | **상업용 (이 시스템)** |
|---|---|---|
| 임차인 | 개인. 주민등록번호 | **법인·개인사업자. 사업자등록번호. 계약 대표자와 실무 담당자가 별개** |
| 관리비 | 계약서상 정액 | **건물 고지서를 검침·면적으로 안분한 결과** |
| 세금 | 면세 | **과세·면세 혼재. 세금계산서·계산서 구분 발행** |
| 수납 | 월세 1건 전액 | **1건 입금이 다수 청구에 배분. 부분납 상시** |
| 기준일 | 계약일 = 기산일 | **계약일·기산일·정산기간이 각각 상이** |

자세한 내용은 → `02_도메인모델.md`, `04_계산규칙.md`

## 1.2 사용자

| 역할 | 1차 | 설명 |
|---|---|---|
| **슈퍼관리자** | ✅ | 전 기능 사용. 건물·계약 등록·삭제, 사용자 관리 |
| **관리자** | ✅ | 일상 운영. 초기 오픈에서는 슈퍼관리자와 권한 차등 없음 |
| 임대인 | [2차] | 건물주. 1차에서는 계정만 생성되고 로그인하지 않는다 |
| 임차인 | [2차] | 사업자의 실무 담당자. 1차에서는 계정만 생성된다 |

> **초기 오픈은 슈퍼관리자 단독 운영을 전제한다.**
> 관리자 간 권한 세분화(담당 건물 제한 등)는 2차다. → `03_전역규칙.md` 3.7

## 1.3 월 업무 주기

이 시스템의 중심은 **한 달을 한 바퀴 도는 업무**다.
1차 범위는 이 주기가 시스템 안에서 끊기지 않고 완결되도록 구성했다.

```
   ┌─────────────────────────────────────────────────────────────┐
   │                                                             │
   │  ① 검침·고지서 입력          PAY-10 건물 관리비 정산          │
   │     한전·수도 고지서 수령                                     │
   │     유닛별 계량기 검침                                        │
   │            ↓                                                │
   │  ② 안분 계산                 PAY-10                          │
   │     전용부 확정 → 공용부 산출 → 유닛별 배분                   │
   │     공실분은 건축주 부담                                      │
   │            ↓                                                │
   │  ③ 정산 확정 → 청구 생성      PAY-10 → PAY-3                 │
   │     고정액 항목(임대료·고정관리비)은 스케줄러가 생성            │
   │     정산 항목은 정산 확정 시 생성                             │
   │     → 계약당 청구서 1장으로 묶임                              │
   │            ↓                                                │
   │  ④ 청구서 발송               청구일 (예: 매월 19일)           │
   │     임차인 담당자 이메일로 발송      NTF-6에 기록              │
   │            ↓                                                │
   │  ⑤ 입금                      납부마감일 (예: 매월 말일)        │
   │     임차인이 건물 운영계좌로 입금                              │
   │            ↓                                                │
   │  ⑥ 수납 기록                 PAY-6 수납 기록 생성             │
   │     은행 거래내역 파일 업로드 → 입금자명 별칭으로 자동 매칭     │
   │     관리자 승인 → 청구 항목별로 배분 → 원장 기록               │
   │            ↓                                                │
   │  ⑦ 미납 관리                 PAY-2 청구·수납 현황             │
   │     미납 건 확인 → 독촉 메일 일괄 발송                         │
   │     연체료는 계산해 표시만. 청구는 관리자가 판단                │
   │            ↓                                                │
   │  ⑧ 임대인 보고               REP-1 핵심 정보 요약             │
   │     임대 현황·수입·미납·보증금 증감 → PDF 발송                │
   │                                                             │
   └─────────────────────────────────────────────────────────────┘

   상시    DASH-1 대시보드에서 처리 대기 업무 확인
           정산 미확정 · 미매칭 입금 · 만료 임박 계약 · 조정 예정
```

### 이 주기에서 놓치면 안 되는 두 가지

1. **정산을 하지 않으면 그 달 청구서가 아예 나가지 않는다.** (②③ 단계)
2. **계약이 지정되지 않은 입금은 임차인이 냈는데 미납으로 잡힌다.** (⑥ 단계)

두 항목은 대시보드 「확인이 필요한 일」 맨 앞에 배치한다. → `DASH-1`

## 1.4 계약 생애주기

```
  계약 등록          CTR-2      계약상태: 준비중
      │                         유닛상태: 공실 (임대료 미발생)
      │
      │  보증금 전액 입금 확인 → 관리자가 수동 전환
      ↓
  계약 개시          CTR-3      계약상태: 진행중
      │                         유닛상태: 사용중
      │                         청구 스케줄 가동
      │
      ├─ 임대조건 조정 일정 도래 → 알림 → 관리자가 "조정 적용"  CTR-3
      │
      ├─ 재계약 (진행중이면 언제든)  CTR-4
      │     새 계약 생성 · 보증금 승계 · 주차면 이전
      │     새 계약 시작일에 자동 전환 (기존→종료됨, 신규→진행중)
      │
      ↓
  계약 종료          CTR-3      만기 종료 / 중도 해지(합의) → 종료됨
                                중도 해지(위반·분쟁)       → 파기됨
                                유닛상태: 공실
                                퇴거 정산은 원장의 보증금 차감·환급으로 처리
```

상태 정의와 전이 규칙 → `03_전역규칙.md` 3.2

## 1.6 외부 서비스 연동

**1차에는 외부 서비스 연동이 없다.** 통제 불가능한 외부 일정을 개발 일정에서 제거하기 위한 결정이다.

| 항목 | 1차 | 2차 |
|---|---|---|
| 결제(PG) · 가상계좌 | 없음 | 도입 |
| 입금 확인 | **은행 거래내역 파일 업로드 + 입금자명 매칭** | PG 웹훅 자동 처리 |
| 임차인 발송 | **이메일만** (8종) | 알림톡 추가 |
| 세금계산서·계산서 | 금액 산출과 내역서 출력까지 | 발행 연동 |

1차 대체 수단의 상세 → `07_화면명세_청구수납.md` PAY-6

> 2차에 PG를 연동할 때 **구조를 바꾸지 않아도 되도록** 결제수단 `가상계좌`,
> 등록방식 `PG자동`, 원장의 `거래번호` 항목을 1차 설계에 미리 확보한다.
