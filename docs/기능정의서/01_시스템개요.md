# 1. 시스템 개요

## 1.1 시스템 정의

상업용 빌딩(오피스·상가·지식산업센터 등)의 임대 운영을 관리하는 백오피스 시스템이다.
관리 회사의 담당자가 다음 업무를 수행한다.

- 건물·유닛 등록 및 공실 현황 관리
- 임차인(사업자)과의 계약 등록·연장·해지
- **월 단위 관리비 정산 및 청구서 발행**
- **입금 기록 및 미납 확인**
- 임대인 월간 보고서 작성·발송

### 주거용 임대관리와의 차이

본 시스템은 주거용과 데이터 구조가 상이하다. 개발 착수 전 반드시 확인한다.

| 영역 | 주거용 | 상업용 (본 시스템) |
|---|---|---|
| 임차인 | 개인. 주민등록번호 식별 | **법인·개인사업자. 사업자등록번호 식별. 계약 대표자와 실무 담당자 분리** |
| 관리비 | 계약서상 정액 | **건물 고지서를 검침·면적 기준으로 안분한 결과** |
| 세금 | 면세 | **과세·면세 혼재. 세금계산서·계산서 구분 발행** |
| 수납 | 월세 1건 전액 입금 | **1건 입금이 다수 청구에 배분. 부분납 상시 발생** |
| 기준일 | 계약일 = 기산일 | **계약일·기산일·정산기간 상이** |

상세 정의 → `02_도메인모델.md`, `04_계산규칙.md`

## 1.2 사용자

| 역할 | 1차 | 설명 |
|---|---|---|
| 시스템 운영자 | ✅ | 테온하우스. 운영사 생성과 슈퍼관리자 계정 발급 (SYS-1·2) |
| 슈퍼관리자 | ✅ | 운영사당 1명. 소속 운영사 전체를 관리 |
| 관리자 | ✅ | 운영사당 복수. **배정된 건물만** 조회·수정 |
| 임대인 | [2차] | 건물주. 1차는 계정만 생성. 로그인 미지원 |
| 임차인 | [2차] | 사업자의 실무 담당자. 1차는 계정만 생성 |

관리자별 담당 건물은 슈퍼관리자가 배정한다. → `03_전역규칙.md` 3.7
역할 정의·기능별 권한 부여(USER-4·5)는 2차다.

### 다중 운영사

본 시스템은 **하나의 시스템 위에서 복수의 운영사가 각자의 건물을 관리하는 구조**다.
1차에서 운영사 3개를 운용한다. 1개는 실 데이터, 2개는 검증용 가상 데이터를 사용한다.

운영사 간 데이터 격리는 데이터베이스 수준에서 강제한다. 가입 절차·요금제는 1차 범위가
아니다. → `11_비기능요건.md` 7.2

## 1.3 월 업무 주기

임대관리 업무는 월 단위로 순환한다. 1차 범위는 본 주기가 시스템 내에서 완결되도록 구성했다.

```
  ① 검침·고지서 입력         PAY-10
     한전·수도 고지서 수령, 유닛별 계량기 검침, 일회성 청구 입력. 항목별로 저장
            ↓
  ② 안분 계산                PAY-10
     전용부 확정 → 공용부 산출 → 유닛별 배분. 공실분은 건축주 부담
            ↓
  ③ 정산 확정                PAY-10
     정산 항목의 유닛별 금액을 고정한다. 정산할 항목이 없는 회차는 건너뛴다
            ↓
  ④ 청구서 발행·발송          PAY-1
     고정액(약정) + 정산액(PAY-10)을 계약당 1장으로 합쳐 확인 후 발행
     임차인 담당자 이메일로 발송. 발송 결과는 NTF-6에 기록
            ↓
  ⑤ 입금                     납부마감일 (예: 매월 말일)
     임차인이 건물 운영계좌로 입금
            ↓
  ⑥ 입금 매칭                PAY-13
     은행 거래내역 업로드 → 입금 한 건씩 임차인 확인 → 배분 미리보기 확인 → 확정
     → 청구항목별 배분 → 원장 기록. 기록된 입금은 PAY-13 대기열에서 통장과 대조. 계약별 납부상태는 PAY-6
            ↓
  ⑦ 미납 관리                PAY-2
     미납 건 확인, 찾아와서 낸 돈(현금·카드)·보증금상계 수납 처리, 미납 안내 메일 매달 발송
     ※ 발행 전 관문이 아니라 상시 업무다. 미납을 확정하는 단계는 없다
       청구서 발행(④) 화면에서 계약별 미납 잔액을 확인할 수 있다
     연체료는 산출·표시만. 수납 처리 때 받을지·얼마 받을지 관리자가 정한다
            ↓
  ⑧ 임대인 보고              REP-1
     임대 현황·수입·미납·보증금 증감 → PDF 발송
            ↓
  ⑨ 월 마감                  PAY-11
     건물 × 월 단위로 장부 잠금. 이후 해당 월 거래 변경 차단

  상시  DASH-1에서 처리 대기 업무 확인
        정산 미확정 · 처리하지 않은 입금 · 만료 임박 계약 · 임대료 인상 예약 도래 · 마감 대기
```

### 결손 시 영향이 큰 단계

| 단계 | 결손 시 결과 |
|---|---|
| ②③ 정산 확정 | 정산 미확정 시 해당 월 청구서 미발행 |
| ⑥ 수납 기록 | 처리하지 않은 입금은 수납 처리되지 않아 미납으로 집계 |

두 항목은 대시보드 「확인이 필요한 일」 최상단에 배치한다. → `DASH-1`

## 1.4 계약 생애주기

```
  계약 등록          CTR-2     계약상태: 준비중  /  유닛상태: 공실
      │                        계약금만 입금된 상태. 임대료 미발생
      │
      │   보증금 전액 입금 확인 → 관리자 수동 전환
      ↓
  계약 개시          CTR-3     계약상태: 진행중  /  유닛상태: 사용중
      │                        청구 약정에 따라 청구 시작
      │
      ├─ 임대료 인상 예약 도래 → 적용일부터 새 금액 자동 청구   CTR-3
      │
      ├─ 재계약 (진행중이면 시점 제한 없음)                    CTR-4
      │     새 계약 생성 · 보증금 승계 · 주차면 이전
      │     새 계약 시작일에 자동 전환 (기존 → 종료됨, 신규 → 진행중)
      ↓
  계약 종료          CTR-3     만기 종료 · 중도 해지(합의)   → 종료됨
                               중도 해지(위반·분쟁)         → 파기됨
                               유닛상태: 공실
                               퇴거 정산은 원장의 보증금 차감·환급으로 처리
```

상태 정의 및 전이 규칙 → `03_전역규칙.md` 3.2

## 1.6 외부 서비스 연동

1차에는 외부 서비스 연동이 없다. 통제 불가능한 외부 일정을 개발 일정에서 제거한 결정이다.

| 항목 | 1차 | 2차 |
|---|---|---|
| 결제(PG) · 가상계좌 | 없음 | 도입 |
| 입금 확인 | **은행 거래내역 파일 업로드 + 입금자명 매칭** | PG 웹훅 자동 처리 |
| 임차인 발송 | **이메일 8종** | 알림톡 추가 |
| 세금계산서·계산서 | 금액 산출 및 내역서 출력 | 발행 연동 |

1차 대체 수단 상세 → `07_화면명세_청구수납.md` PAY-13

2차 PG 연동 시 구조 변경이 발생하지 않도록, 결제수단 `가상계좌`·등록방식 `PG자동`·
원장 `거래번호` 항목을 1차 설계에 사전 확보한다.
