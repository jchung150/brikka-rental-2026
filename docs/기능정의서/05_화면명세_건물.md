# 5-1. 화면 명세 — 건물 관리 (PRO)

| 화면 | 명칭 | 주요 액션 |
|---|---|---|
| PRO-1 | 건물 정보 조회 | 조회 |
| PRO-2 | 건물 정보 등록 | 생성 |
| PRO-3 | 건물 정보 조회(상세) 및 수정 | 조회, 수정, 삭제 |
| PRO-4 | 유닛 정보 조회(상세) 및 수정 | 조회, 수정, 삭제 |

본 장은 3부 전역 규칙과 4부 계산 규칙을 참조한다.

---

## PRO-1 · 건물 정보 조회

**목적** 등록된 모든 건물을 목록으로 조회한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 건물 관리

### 【입출력 항목】

```
필터: 건물구분, 공실(전체 / 공실 있음 / 공실 없음)

[목록]
건물고유이름(아래에 건물별칭 · 건물구분), 건물주소(아래에 지번), 건물주이름(아래에 사업자등록번호),
건물관리자(아래에 연락처), 임대가능면적(아래에 연면적), 공실률(아래에 `전체 N · 공실 N`),
더보기(상세보기, 수정, 삭제)
  ※ 건물구분: 오피스빌딩/근린생활시설(상가)/지식산업센터/복합상가/물류창고/기타
  ※ 모든 열을 정렬할 수 있다
```

### 【동작 규칙】

- 상단에 `새로운 건물 등록` 버튼을 배치한다. → PRO-2
- 행 클릭 시 건물 상세로 이동한다. → PRO-3
- **건물주소는 전체 주소를 표시한다.** 마스킹하지 않는다
- 공실률 = 공실 유닛 수 ÷ (전체 유닛 수 − 비운영중 유닛 수) → 4.5
- 임대가능면적은 PRO-2에서 직접 입력한 값을 표시한다. 유닛 면적 합계로 계산하지 않는다
- **관리자는 배정된 담당 건물만 조회한다.** 슈퍼관리자는 소속 운영사 전체를 조회한다 → 3.7
- 타 운영사의 건물은 조회되지 않는다 → `11_비기능요건.md` 7.2

### 【설계 의도】

- 상업용 빌딩의 주소는 자산 정보이므로 마스킹 대상이 아니다. 주거용과 다른 점이다
- 공실률을 면적이 아닌 유닛 수 기준으로 산정한다

### 【연관 화면】 PRO-2, PRO-3
### 【알림】 없음

## PRO-2 · 건물 정보 등록

**목적** 신규 건물을 등록한다.
**사용자** 슈퍼관리자
**진입 경로** PRO-1 → `새로운 건물 등록`

### 【입출력 항목】

```
(기본 정보)
건물고유이름, **건물별칭**, 건물구분, 건물주소, 건축일, 사용승인일, 건물썸네일사진

(건물 제원)
연면적, 임대가능면적, 지상층수, 지하층수, 총 주차면수,
냉난방 방식(중앙공조/EHP(시스템에어컨)/지역난방/개별냉난방)

(건물주)  선택 또는 신규 등록. 복수 등록 가능
 → 신규 등록 시
   건물주이름, 건물주구분(개인/법인/개인사업자),
   상호(법인·개인사업자인 경우), 사업자등록번호, 대표자명,
   이메일, 연락처, 보유지분(%)

(건물운영계좌)  선택 또는 신규 등록
 → 신규 등록 시  은행명, 계좌번호

(채권정보)
은행명, 지점명, 연락처, 채권최고금액, 실제채권금액

(건물관리자)  선택 또는 신규 등록. 복수 등록 가능
 → 신규 등록 시  관리자이름, 회사이름, 이메일, 연락처
```

### 【동작 규칙】

- 등록 시에는 필수 정보만 입력하고, 세부 정보는 상세 화면에서 추가 입력한다 → PRO-3
- **건물고유이름**은 관리자가 부여하는 식별용 명칭이다 (예: 카리나빌딩)
- **건물별칭**은 계약고유이름에 사용하는 축약형이다 (예: 카리나). 짧을수록 목록 화면에서 유리하다 → 3.1
  운영사 안에서 중복될 수 없다
- 건물주·건물관리자 드롭다운에 대상이 없으면 `새 건물주 등록` / `새 건물 관리자 등록`을 선택해 인라인으로 즉시 입력한다
- **건물주 사업자등록번호는 유일값이다.** 입력 시 기존 임대인을 조회해 표시하고, 없을 때만 신규 등록한다 → USER-8
- **임대인 계정은 이 화면에서만 생성한다.** 사용자 등록(USER-3)에서는 생성하지 않는다 → 3.7
- 임대가능면적은 직접 입력한다. 유닛 면적 합계와 자동 일치시키지 않는다
- 총 주차면수는 계약별 주차 배정의 상한 기준이 된다
- 청구항목 구성은 상세 화면의 관리비 탭에서, 청구 주기 기본값은 요약탭에서 설정한다 → PRO-3
- **채권정보는 등기부등본 기준값이다.** 등기 변동 시 담당자가 상세 화면에서 직접 갱신한다. 갱신 주기를 두지 않으며 수정 내역은 건물 이력에 기록한다 → PRO-3
- 가전·가구 마스터 등록 기능은 사용하지 않는다
- [2차] PG 연계에 필요한 가맹점 정보는 PG사 선정 후 확정한다 → PAY-7

### 【설계 의도】

- 임대료 세금계산서가 **임대인 명의로 발행**되므로 사업자등록번호를 필수로 수집한다
- 계정 생성 경로를 하나로 제한해 동일 임대인의 중복 등록을 방지한다

### 【연관 화면】 PRO-1, PRO-3, USER-8
### 【알림】 없음

## PRO-3 · 건물 정보 조회(상세) 및 수정

**목적** 건물의 전체 정보를 조회하고 수정한다. 유닛·자료·관리비 설정을 관리한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PRO-1 행 클릭 또는 더보기 → 상세보기
**화면 구성** 요약 · 유닛 · 관리비 · 자료보관 — **4개 탭**

```

(기본 정보)
건물썸네일사진, 건물고유이름, 건물별칭, 건물구분, 건물주소,

### 【동작 규칙】

**탭 구성**
- 탭 순서는 **요약 → 유닛 → 관리비 → 자료보관**이다
- **탭 이름에 건수를 병기하지 않는다.** 각 탭 내부에서 확인한다
- 요약탭의 카드 순서는 **기본 정보 → 건물 제원 → 채권 정보 → 공용시설 → 주차장 → 관리위임계약**이다.
  건물 정보를 우선 배치한다. 건물주가 직접 관리하는 경우 위임계약이 없을 수 있다

**수정 방식**
- **카드 단위로 수정한다.** 각 카드 우측 상단에 수정 버튼을 배치한다
- **화면 전체를 수정 모드로 전환하지 않는다.** 등록된 건물 정보 전부를 한 번에 여는 것은
  실제 수정 범위와 맞지 않는다
- 화면 상단에 전체 수정·목록 버튼을 두지 않는다

**공통**
- 계약 정보 및 임대 조건은 본 화면에서 관리하지 않는다. 계약 관리 화면에서만 관리한다 → CTR
- **화면 제목 옆에서 다른 건물로 전환한다.** 목록을 거치지 않고 이동할 수 있어야 한다.
  담당 건물만 표시하며 건물 수가 늘어도 목록 안에서 찾을 수 있어야 한다
- **전환 수단은 제목과 구분되는 독립 버튼으로 배치한다.** 제목 자체를 클릭 대상으로 삼으면
  조작할 수 있다는 사실이 드러나지 않는다
- 건물을 전환해도 **현재 탭을 유지한다.** 건물별 설정을 비교할 때 탭을 다시 찾지 않아도 된다

**요약탭**
- **청구일은 계약 등록 시 상속된다.** 건물 청구일 변경은 이후 등록되는 계약에만 적용한다.
  **납부마감일은 건물 규칙이다.** 계약마다 따로 두지 않는다 → 3.5
- 공용시설은 목록에서 체크박스로 추가·제거한다. 드롭다운 상단의 `새로운 공용시설 등록`으로 인라인 추가한다
- **주차면은 계약 단위로 배정한다.** 계약 하나에 복수 배정이 가능하며, 계약 만료 시 배정이 자동 해제된다
- 차량번호는 관리하지 않는다
- **관리위임계약은 건물 단위로 관리한다.** 임대인이 여러 건물을 위임하더라도 계약서를 건물마다 별도로 작성하며 기간과 수수료가 건물마다 다르다
- 관리위임계약 만료 시 해당 건물의 관리 권한이 소멸한다. 남은 일수를 표시하고 **만료 90일 전부터 대시보드에 표시한다** → DASH-1.
  만료 90일 이내이면 카드에 `만료 90일 이내입니다. 갱신하지 않으면 이 건물의 관리 권한이 소멸합니다`를 경고색으로 표시한다
- 위임계약서는 본 건물의 자료보관 탭에 첨부한다
- 초기 오픈은 임대인 직수취 방식을 전제한다. 관리 수수료는 정보로만 기록한다 → USER-9

**유닛탭**
- 상단에 `유닛 등록` 버튼을 배치한다
- **계약이 있는 유닛을 누르면 계약 상세(CTR-3) 요약 탭으로 간다.** 진행중 계약, 없으면 준비중 계약이다. 계약이 없는 유닛(공실·비운영중)을 누르면 **같은 탭 안에서** 유닛 상세로 전환한다 → PRO-4
- 유닛은 카드 형태로 표시하며 개수 제한이 없다. 탭 머리에 `전체 · 사용중 · 공실 · 비운영중` 수를 표시한다
- 지하층은 `지하 N층`으로 표기한다
- 건물의 계약 목록 탭을 따로 두지 않는다. 계약 1건은 유닛 1개이므로 유닛 카드에서 바로 계약으로 들어간다. 여러 건물의 계약은 계약 목록(CTR-1)에서 본다
- 유닛상태는 계약상태와 자동 연동한다 → 3.2
- 임차인은 진행중 계약의 대표 임차인이다. 진행중 계약이 없으면 준비중 계약의 대표 임차인을 표시하며, 종료됨·파기됨 계약의 임차인은 표시하지 않는다
- 임대면적·전용면적 단위는 제곱미터다
- **건물 사진(건물썸네일사진)은 한 장이다.** 건물을 쉽게 알아보기 위한 용도일 뿐 다른 쓰임은 없다.
  기본 정보 카드는 화면 폭 전체를 쓰고, 사진은 카드 오른쪽 끝에 세로로 긴 사진(가로:세로 3:4)으로 보인다. 없으면 그 자리에 `건물 사진 올리기`를 두고, 있으면 사진 위에 `바꾸기` · `삭제`를 둔다.
  JPG·PNG만 받는다. 비율이 다른 사진은 가운데를 기준으로 잘라 칸을 채운다

**자료보관 탭**
- 상단에 `파일 업로드` 버튼을 배치한다
- 카테고리는 전 화면 공통 10종을 사용한다 → 3.1

**관리비 탭**
- **본 설정은 슈퍼관리자만 변경할 수 있다.** 전 임차인의 청구 금액이 달라지기 때문이다 → 3.7
- 건물마다 공과금 부과 방식이 다르므로 청구항목 구성을 건물 단위로 설정한다
- **기준표에 없는 항목을 본 화면에서 바로 생성할 수 있다.** 공용 회의실 사용료처럼
  건물 운영 중에 발생하는 항목은 미리 정의할 수 없다.
  **새로 만든 항목은 이 건물에만 생긴다.** 청구항목은 건물마다 따로 관리한다 → 3.3
- **건물당 청구항목은 최대 99개다.** 99개가 차면 `항목 추가`를 막는다
- **발행 문서와 반복주기는 건물마다 다르게 정할 수 있다.** 기준표 값이 기본으로 채워지며 덮어쓴다.
  고정액 항목(임대료·고정관리비)의 반복주기는 건물에서 정하지 않고 계약마다 정한다 → CTR-3
- `미사용` 항목은 `수정`에서 저장하면 다시 `사용`이 된다
- **과세 여부를 따로 묻지 않는다.** 발행 문서가 결정한다 → 3.3
- **입력 순서는 배분 기준 → 보유 유닛이다.** `계량기 사용 여부`를 따로 묻지 않는다.
  배분 기준이 계량기를 요구하면 보유 유닛 선택을 표시하고 기본값으로 전 유닛을 선택한다
- **`사용량` 기준에서 일부 유닛만 계량기를 보유하면 경고한다.** 계량기 없는 유닛의 기준값이
  0이 되어 공용분을 부담하지 않게 되므로 `사용량+임대면적`을 쓰도록 안내한다 → 4.1.3-1.
  계량기 공유로 지정한 유닛은 경고 대상에서 제외한다 → 4.1.3-4
- **`사용분 청구 여부` 설정을 두지 않는다.** 계량기가 있으면 개별분을 청구한다.
  공용부만 고지되는 건물은 계량기 없이 `임대면적`으로 나눈다 → 4.1.5
- **배분 기준이 `직접 입력`이면 계량기·참조 항목을 표시하지 않는다** → 4.1.3-2
- **공용분 부담 대상은 설정 항목이 아니다.** 언제나 전 유닛이다.
  계량기가 있어도 복도·화장실을 쓰기 때문이다. 특정 유닛을 빼려면 정산 시 배율을
  `0`으로 둔다 → 4.1.2 · 4.1.7
- **설정의 결과를 문장으로 표시한다.** 설정 조합이 어떤 배분을 만드는지 화면에서 확인할 수 있어야 한다.
  성립하지 않는 조합(계량기 없이 사용량 기준 등)은 경고로 전환한다
- **청구한 적이 있는 항목은 삭제하지 않고 `미사용`으로 전환한다.** 항목은 남아 있으며
  과거 회차의 정산 결과와 원장 기록은 유지된다. 언제든 다시 사용할 수 있다
- **청구항목명과 발행 문서는 기준표를 따른다** → 3.3
- **배분 우선순위는 건물 단위로 정한다.** 입금이 청구 합계보다 모자랄 때 어느 항목부터 채울지다 → 4.3.
  기본값은 기준표(3.3)에서 오며 건물마다 바꾼다. 계약마다 따로 정하지 않는다.
  **같은 건물 안에서 우선순위는 겹칠 수 없다.** 이미 쓰는 번호를 넣으면 저장을 막고 어느 항목이 쓰는지 알린다
- **계량기 보유 유닛은 항목별로 지정한다.** 항목마다 보유 양상이 다르다.
  전기는 전 유닛 보유가 일반적이나 수도는 1층 상가에만 있는 건물이 많다.
  유닛 하나씩 설정하면 반복 작업이 되므로 **본 화면에서 항목 단위로 일괄 지정**한다.
  개별 유닛만 변경할 때는 PRO-4 검침 설정을 사용한다. 두 화면은 동일한 데이터를 편집한다
- **참조 항목**은 배분 기준이 `사용량`이면서 자체 계량기가 없는 항목에 지정한다.
  전력기금·TV수신료는 전기요금의 부담 비율을 따른다 → 4.1.3
- **전용부를 임차인이 직접 납부하는 유닛**(한전 직접 계약 등)은 계량기를 지정하지 않는다.
  전용부는 고지서에 없고, 공용분은 다른 유닛과 똑같이 면적대로 낸다. 따로 빼는 설정을 두지 않는다 → 4.1.7-2
- **정산 항목은 계약마다 정하지 않는다.** 이 탭의 정산 항목은 건물의 모든 계약에 그대로 적용된다.
  계약마다 다른 것은 임대료·고정관리비의 약정 금액뿐이며 계약 상세 임대료·관리비 탭에서 정한다 → CTR-3
- 배분 계산은 → 4.1
- **미확정 정산 회차가 있으면 변경 전에 경고한다.** 임대면적·배분 기준·계량기 보유 유닛·
  계량기 배율·계량기 공유·참조 항목을 바꾸면 미확정 회차의 산출이 즉시 바뀐다.
  영향받는 회차를 명시하고 확인을 받는다. 확정된 회차는 스냅샷이므로 영향이 없다 → PAY-10
- **미확정 회차에 검침값이 있는 유닛은 계량기 보유 유닛에서 뺄 수 없다.** 검침값을 먼저 지우도록 안내한다 → 4.1.3-3
- 격월·연 1~2회 발생 항목(수도요금·교통유발부담금·정화조청소비)은 청구 주기를 사전 고정하지 않는다. 해당 회차 정산에서 항목을 추가한다 → PAY-10

### 【설계 의도】

- `공실이면서 임차인명이 있는 유닛`은 계약 준비중 상태다. 유닛상태를 별도로 나누지 않고 임차인명으로 구분한다
- 관리비 설정을 건물별로 분리한 이유는 부과 방식이 건물마다 다르기 때문이다
- 계약에 약정하는 고정액은 임대료·고정관리비 둘뿐이다. 승강기유지비·경비비·청소비 같은 비용은 보통 고정관리비에 포함해 받는다.
  따로 받는 경우에도 관리비 정산(임대면적 비율·직접 입력)으로 충분하므로 계약 등록 화면에 항목을 늘리지 않는다
  (예: A건물은 한전 고지서가 건물 전체분이고, B건물은 전용부를 임차인이 직접 납부)

### 【연관 화면】 PRO-1, PRO-4, CTR-1, PAY-10
### 【알림】 없음

**사용자** 슈퍼관리자, 관리자
**진입 경로** PRO-3 유닛탭에서 유닛 클릭 (같은 탭 내 화면 전환)

### 【입출력 항목】

```

### 【동작 규칙】

**표시**
- 유닛주소는 `건물주소 + 유닛고유번호`를 조합해 표시한다. 유닛별로 입력받지 않는다
- 전용률 = 전용면적 ÷ 임대면적. 자동 산출하며 직접 입력하지 않는다
- 임대면적·전용면적 단위는 제곱미터다
- 썸네일 사진은 1개만 업로드한다
- 메모는 단일 입력 항목이다. 작성자·작성 이력을 남기지 않는다

**유닛상태**
- 계약상태와 자동 연동한다 → 3.2
- 비운영중은 수동 지정이며 자동 연동보다 우선한다. 계약이 생성되어도 자동 전환되지 않으며 슈퍼관리자가 먼저 해제해야 한다

**검침 설정**
- **본 화면은 개별 유닛의 설정을 변경할 때 사용한다.** 항목 단위 일괄 지정은 PRO-3 관리비 탭에서
  수행하며 두 화면은 동일한 데이터를 편집한다
- 계량기 보유 여부의 기본값은 PRO-3에서 배분 기준을 정할 때 정해진다(기본 전 유닛 선택)
- **계량기 배율(계기배율)**은 계량기가 실사용량을 축소해 표시할 때의 환산 계수다.
  기본 1이며 계량기를 교체할 때만 바꾼다 → 4.1.3-3
- 공용분 부담을 회차별로 가감하는 **배율(배분배율)**은 유닛 설정이 아니다. 정산 화면에서 회차마다 조정한다 → PAY-10
- 계산은 → 4.1

**계약정보**
- 해당 유닛의 모든 계약을 과거부터 현재까지 표시한다. 추가·수정·삭제할 수 없다
- 계약 클릭 시 계약 상세로 이동한다 → CTR-3
- 임대료와 관리비는 각각 구분해 월 금액으로 표시하고 `(부가세 포함)`을 병기한다 → 3.4

**삭제**
- **계약 이력이 하나라도 있는 유닛은 삭제할 수 없다.** 계약이 전혀 없는 유닛만 삭제 가능하다
- 삭제할 수 없는 유닛을 쓰지 않게 되면 공실로 둔다. 건물주가 직접 쓰거나 공사 중일 때만 비운영중으로 지정한다 → 3.2

### 【설계 의도】

- 유닛상태에 `예약중`·`공사중`을 두지 않는다. 상업용은 계약 체결 후 임차인이 직접 인테리어를 수행하므로, 계약이 진행중이 된 시점부터 사용중으로 본다
- 준비중 계약(계약금만 입금)은 임대료가 발생하지 않으므로 공실로 집계한다. 임대인 보고 수치를 실제 임대수익과 일치시키기 위함이다
