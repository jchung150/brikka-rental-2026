# 5-1. 화면 명세 — 건물 관리 (PRO)

| 화면 | 명칭 | 주요 액션 |
|---|---|---|
| PRO-1 | 건물 정보 조회 | 조회 |
| PRO-2 | 건물 정보 등록 | 생성 |
| PRO-3 | 건물 정보 조회(상세) 및 수정 | 조회, 수정, 삭제 |
| PRO-4 | 유닛 정보 조회(상세) 및 수정 | 조회, 수정, 삭제 |

본 장은 3부 전역 규칙과 4부 계산 규칙을 참조한다.

---

## PRO-1 · 건물 정보 조회

**목적** 등록된 모든 건물을 목록으로 조회한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 건물 관리

### 【입출력 항목】

```
필터: 건물고유이름

[목록]
건물고유이름, 건물주소, 건물주이름, 건물관리자,
건물구분(오피스빌딩/근린생활시설(상가)/지식산업센터/복합상가/물류창고/기타),
임대가능면적, 공실률,
더보기(상세보기, 수정, 삭제)
```

### 【동작 규칙】

- 상단에 `새로운 건물 등록` 버튼을 배치한다. → PRO-2
- 행 클릭 시 건물 상세로 이동한다. → PRO-3
- **건물주소는 전체 주소를 표시한다.** 마스킹하지 않는다
- 공실률 = 공실 유닛 수 ÷ (전체 유닛 수 − 비운영중 유닛 수) → 4.5
- 임대가능면적은 PRO-2에서 직접 입력한 값을 표시한다. 유닛 면적 합계로 계산하지 않는다
- **관리자는 배정된 담당 건물만 조회한다.** 슈퍼관리자는 소속 운영사 전체를 조회한다 → 3.7
- 타 운영사의 건물은 조회되지 않는다 → `11_비기능요건.md` 7.2

### 【설계 의도】

- 상업용 빌딩의 주소는 자산 정보이므로 마스킹 대상이 아니다. 주거용과 다른 점이다
- 공실률을 면적이 아닌 유닛 수 기준으로 산정한다

### 【연관 화면】 PRO-2, PRO-3
### 【알림】 없음

## PRO-2 · 건물 정보 등록

**목적** 신규 건물을 등록한다.
**사용자** 슈퍼관리자
**진입 경로** PRO-1 → `새로운 건물 등록`

### 【입출력 항목】

```
(기본 정보)
건물고유이름, 건물구분, 건물주소, 건축일, 사용승인일, 건물썸네일사진

(건물 제원)
연면적, 임대가능면적, 지상층수, 지하층수, 총 주차면수,
냉난방 방식(중앙공조/EHP(시스템에어컨)/지역난방/개별냉난방)

(건물주)  선택 또는 신규 등록. 복수 등록 가능
 → 신규 등록 시
   건물주이름, 건물주구분(개인/법인/개인사업자),
   상호(법인·개인사업자인 경우), 사업자등록번호, 대표자명,
   이메일, 연락처, 보유지분(%)

(건물운영계좌)  선택 또는 신규 등록
 → 신규 등록 시  은행명, 계좌번호

(채권정보)
은행명, 지점명, 연락처, 채권최고금액, 실제채권금액

(건물관리자)  선택 또는 신규 등록. 복수 등록 가능
 → 신규 등록 시  관리자이름, 회사이름, 이메일, 연락처
```

### 【동작 규칙】

- 등록 시에는 필수 정보만 입력하고, 세부 정보는 상세 화면에서 추가 입력한다 → PRO-3
- **건물고유이름**은 관리자가 부여하는 식별용 명칭이다 (예: 동교동 영준빌딩)
- 건물주·건물관리자 드롭다운에 대상이 없으면 `새 건물주 등록` / `새 건물 관리자 등록`을 선택해 인라인으로 즉시 입력한다
- **건물주 사업자등록번호는 유일값이다.** 입력 시 기존 임대인을 조회해 표시하고, 없을 때만 신규 등록한다 → USER-8
- **임대인 계정은 이 화면에서만 생성한다.** 사용자 등록(USER-3)에서는 생성하지 않는다 → 3.7
- 임대가능면적은 직접 입력한다. 유닛 면적 합계와 자동 일치시키지 않는다
- 총 주차면수는 계약별 주차 배정의 상한 기준이 된다
- 청구 항목 구성과 청구 주기 기본값은 상세 화면의 청구설정탭에서 설정한다 → PRO-3
- **채권정보는 등기부등본 기준값이다.** 등기 변동 시 담당자가 상세 화면에서 직접 갱신한다. 갱신 주기를 두지 않으며 수정 내역은 건물 이력에 기록한다 → PRO-3
- 가전·가구 마스터 등록 기능은 사용하지 않는다
- [2차] PG 연계에 필요한 가맹점 정보는 PG사 선정 후 확정한다 → PAY-7

### 【설계 의도】

- 임대료 세금계산서가 **임대인 명의로 발행**되므로 사업자등록번호를 필수로 수집한다
- 계정 생성 경로를 하나로 제한해 동일 임대인의 중복 등록을 방지한다

### 【연관 화면】 PRO-1, PRO-3, USER-8
### 【알림】 없음

## PRO-3 · 건물 정보 조회(상세) 및 수정

**목적** 건물의 전체 정보를 조회하고 수정한다. 유닛·자료·청구 설정을 관리한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PRO-1 행 클릭 또는 더보기 → 상세보기
**화면 구성** 요약 · 유닛 · 자료보관 · 청구설정 — **4개 탭**

### 【입출력 항목】

```
(제목)
건물고유이름, 건물구분

───── 요약탭 ─────
(기본정보)
건물썸네일사진, 건물주소, 건물주이름, 건물관리자

(건물정보)
건물운영계좌, 연면적, 임대가능면적, 지상층수, 지하층수, 총 주차면수,
냉난방 방식, 채권정보

(관리위임계약) - 수정 가능
관리계약시작일, 관리계약종료일, 남은 일수, 관리 수수료(정액 또는 요율),
운영방식(임대인 직수취 / [2차] 위탁사 수취 후 정산)

(공용시설) - 추가/수정/삭제
[태그] 공용시설명

(주차장정보) - 추가/수정/삭제

       더보기(상세 보기, 수납기록생성)
[생성시] 유닛고유번호, 유닛용도(사무실/근린생활/창고/기타), 유닛층,
        임대면적(계약면적), 전용면적, 보증금, 월세, 유닛썸네일사진, 메모

───── 자료보관탭 ─────
(자료정보) - 추가/수정/삭제

───── 청구설정탭 ─────

       잔여분 부담대상, 잔여분 배분기준, 참조 항목, 안분 제외 유닛 수
```

### 【동작 규칙】

**공통**
- 계약 정보 및 임대 조건은 본 화면에서 관리하지 않는다. 계약 관리 화면에서만 관리한다 → CTR
- [2차] `슈퍼관리자만 수정` 권한 구분은 권한 세분화와 함께 구현한다 → 3.7

**요약탭**
- 공용시설은 목록에서 체크박스로 추가·제거한다. 드롭다운 상단의 `새로운 공용시설 등록`으로 인라인 추가한다
- **주차면은 계약 단위로 배정한다.** 계약 하나에 복수 배정이 가능하며, 계약 만료 시 배정이 자동 해제된다
- 차량번호는 관리하지 않는다
- **관리위임계약은 건물 단위로 관리한다.** 임대인이 여러 건물을 위임하더라도 계약서를 건물마다 별도로 작성하며 기간과 수수료가 건물마다 다르다
- 관리위임계약 만료 시 해당 건물의 관리 권한이 소멸한다. 남은 일수를 표시하고 **만료 90일 전부터 대시보드에 표시한다** → DASH-1
- 위임계약서는 본 건물의 자료보관탭에 첨부한다
- 초기 오픈은 임대인 직수취 방식을 전제한다. 관리 수수료는 정보로만 기록한다 → USER-9

**유닛탭**
- 상단에 `유닛 등록` 버튼을 배치한다
- 유닛 클릭 시 **같은 탭 내에서 상세 화면으로 전환**한다. 별도 페이지로 이동하지 않는다 → PRO-4
- 유닛은 카드 형태로 표시하며 개수 제한이 없다
- 유닛상태는 계약상태와 자동 연동한다 → 3.2
- 임차인명은 진행중 계약의 대표 임차인을 표시한다. 진행중 계약이 없으면 준비중 계약의 대표 임차인을 표시하며, 종료됨·파기됨 계약의 임차인은 표시하지 않는다
- 임대면적·전용면적 단위는 제곱미터다
- 썸네일 사진은 1개만 업로드한다

**자료보관탭**
- 상단에 `파일 업로드` 버튼을 배치한다
- 카테고리는 전 화면 공통 10종을 사용한다 → 3.1

**청구설정탭**
- 건물마다 공과금 부과 방식이 다르므로 청구 항목 구성을 건물 단위로 설정한다
- **청구 항목명과 묶음은 기준표를 따른다** → 3.3
- **계량기 보유 유닛은 항목별로 지정한다.** 항목마다 보유 양상이 다르다.
  전기는 전 유닛 보유가 일반적이나 수도는 1층 상가에만 있는 건물이 많다.
  유닛 하나씩 설정하면 반복 작업이 되므로 **본 화면에서 항목 단위로 일괄 지정**한다.
  개별 유닛만 변경할 때는 PRO-4 검침 설정을 사용한다. 두 화면은 동일한 데이터를 편집한다
- **참조 항목**은 배분 기준이 `검침 사용량`이면서 자체 계량기가 없는 항목에 지정한다.
  전력기금·TV수신료는 전기요금 검침값을 참조한다 → 4.1.3
- **안분 제외 유닛**은 임차인이 공급자와 직접 계약해 건물 고지서에 포함되지 않는 유닛을 지정한다.
  사유와 적용 시작일을 필수로 입력하며 형평성 문의 시 근거가 된다 → 4.1.7-2
  건물 계량기 내부에 있으면서 별도 정산하는 경우는 제외 대상이 아니다
- `자동` 판정 규칙과 배분 계산은 → 4.1
- 격월·연 1~2회 발생 항목(상하수도요금·교통유발부담금·정화조청소비)은 청구 주기를 사전 고정하지 않는다. 해당 회차 정산에서 항목을 추가한다 → PAY-10
- 청구 주기 기본값은 계약 등록 시 상속된다. **건물 기본값 변경은 이후 등록되는 계약에만 적용**하며 기존 계약은 유지한다 → 3.5

### 【설계 의도】

- `공실이면서 임차인명이 있는 유닛`은 계약 준비중 상태다. 유닛상태를 별도로 나누지 않고 임차인명으로 구분한다
- 건물별 청구 설정을 분리한 이유는 부과 방식이 건물마다 다르기 때문이다
  (예: A건물은 한전 고지서가 건물 전체분이고, B건물은 전용부를 임차인이 직접 납부)

### 【연관 화면】 PRO-1, PRO-4, CTR-1, PAY-4, PAY-10
### 【알림】 없음

## PRO-4 · 유닛 정보 조회(상세) 및 수정

**목적** 개별 유닛 정보를 조회하고 수정한다. 계약 이력과 자료를 확인한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PRO-3 유닛탭에서 유닛 클릭 (같은 탭 내 화면 전환)

### 【입출력 항목】

```
(기본정보) - 수정/삭제
유닛썸네일사진, 유닛상태(공실/사용중/비운영중), 유닛고유번호,
유닛주소(건물주소 + 유닛고유번호, 읽기 전용)

(유닛정보) - 수정 가능
유닛용도(사무실/근린생활/창고/기타), 유닛층, 임대면적(계약면적), 전용면적,
전용률(자동 산출, 읽기 전용), 기본 보증금, 기본 월세, 메모

(검침 설정) - 수정 가능
[목록] 청구항목, 검침기 유무(디폴트: 있음), 기본 조정 배수(디폴트: 1.0)

(계약정보) - 조회 전용
[목록] 계약상태(준비중/진행중/종료됨/파기됨), 계약시작일, 계약종료일, 임차인,
       임대료, 관리비 (각 부가세 별도)

(자료정보) - 추가/수정/삭제
[목록] 제목, 카테고리(10종 → 3.1), 업로드한사람, 등록일시,
       더보기(삭제, 다운로드, 상세보기)
[업로드시] 제목, 카테고리, 메모

───── [2차] 요청이력 ─────
요청 관리(REQ 계열)와 함께 구현한다.
```

### 【동작 규칙】

**표시**
- 유닛주소는 `건물주소 + 유닛고유번호`를 조합해 표시한다. 유닛별로 입력받지 않는다
- 전용률 = 전용면적 ÷ 임대면적. 자동 산출하며 직접 입력하지 않는다
- 임대면적·전용면적 단위는 제곱미터다
- 썸네일 사진은 1개만 업로드한다
- 메모는 단일 입력 항목이다. 작성자·작성 이력을 남기지 않는다

**유닛상태**
- 계약상태와 자동 연동한다 → 3.2
- 비운영중은 수동 지정이며 자동 연동보다 우선한다. 계약이 생성되어도 자동 전환되지 않으며 슈퍼관리자가 먼저 해제해야 한다

**검침 설정**
- **본 화면은 개별 유닛의 설정을 변경할 때 사용한다.** 항목 단위 일괄 지정은 PRO-3 청구설정탭에서
  수행하며 두 화면은 동일한 데이터를 편집한다
- 유닛에는 기본적으로 계량기가 있다고 본다. 없는 유닛만 항목별로 `없음`을 지정한다
- 기본 조정 배수는 계량기 모델 차이 등의 보정에 사용한다. 기본값 1.0이며 변경 시까지 유지된다
- 회차별로 다르게 적용하려면 정산 화면에서 조정한다 → PAY-10
- 조정 배수의 적용 범위와 계산은 → 4.1

**계약정보**
- 해당 유닛의 모든 계약을 과거부터 현재까지 표시한다. 추가·수정·삭제할 수 없다
- 계약 클릭 시 계약 상세로 이동한다 → CTR-3
- 임대료와 관리비는 각각 구분해 월 금액으로 표시하고 `(부가세 별도)`를 병기한다 → 3.4

**삭제**
- **계약 이력이 하나라도 있는 유닛은 삭제할 수 없다.** 계약이 전혀 없는 유닛만 삭제 가능하다
- 사용하지 않는 유닛은 비운영중으로 지정한다

### 【설계 의도】

- 유닛상태에 `예약중`·`공사중`을 두지 않는다. 상업용은 계약 체결 후 임차인이 직접 인테리어를 수행하므로, 계약이 진행중이 된 시점부터 사용중으로 본다
- 준비중 계약(계약금만 입금)은 임대료가 발생하지 않으므로 공실로 집계한다. 임대인 보고 수치를 실제 임대수익과 일치시키기 위함이다

### 【연관 화면】 PRO-3, CTR-3, PAY-10
### 【알림】 없음
