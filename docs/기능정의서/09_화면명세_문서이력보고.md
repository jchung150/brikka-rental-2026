# 문서 보관함 (DOC)

문서는 건물·유닛·계약·임차인·임대인 중 하나에 **귀속되어** 저장한다.
업로드는 각 화면의 자료보관 탭에서 수행하며, DOC 계열은 이를 가로질러 검색한다.

```
PRO-3 자료보관 탭    건물 문서
PRO-4 자료정보      유닛 문서
CTR-3 자료보관 탭    계약 문서
USER-7 자료보관 탭   임차인 문서 (사업자등록증 등)
USER-9 자료보관 탭   임대인 문서 (위탁운영계약서 등)
```

---

## DOC-1 · 문서 목록 조회

**목적** 건물·유닛·계약·임차인·임대인에 귀속된 모든 문서를 한 곳에서 검색한다.
**사용자** 슈퍼관리자, 관리자 / [2차] 임대인, 임차인
**진입 경로** 메인 메뉴 → 문서 보관함

### 【입출력 항목】

```
필터: 카테고리(10종 → 3.1),
      귀속 대상 종류(건물/유닛/계약/임차인/임대인), 건물고유이름,
      등록기간, 업로드한사람, 파일형식

[목록]
체크박스, 제목, 카테고리,
귀속 대상(예: 건물 카리나빌딩 / 계약 (주)한빛 8층 전체 / 임차인 (주)비씨에이),
파일형식, 파일크기, 업로드한사람, 등록일시,
더보기(상세보기, 내려받기, 삭제)

[일괄] 선택한 문서 ZIP 내려받기
```

### 【동작 규칙】

- 상단에 `문서 업로드` 버튼을 배치한다 → DOC-3
- 카테고리는 전 화면 공통 10종을 사용한다 → 3.1
- 선택한 여러 문서를 ZIP으로 한 번에 내려받는다
- **문서 삭제 시 이력을 기록한다** → 3.6. 사유 입력이 필수다
- 문서에는 사업자등록증·계약서·위탁운영계약서가 포함되므로 접근 권한을 제한한다
- [2차] 임대인·임차인은 포털 오픈 후 각자에게 공개된 문서만 열람한다. 초기 오픈에서는 슈퍼관리자와 관리자만 접근하며 관리자 간 권한 차등을 두지 않는다 → 3.7

### 【설계 의도】

- 문서는 항상 무언가에 귀속되어 업로드되나, 검색 시점에는 귀속 대상을 알지 못하는 경우가 많다
  (예: `작년 소방점검 보고서가 어느 건물 것인가`)
- 목록의 검색 기준을 주소가 아닌 귀속 대상으로 둔다. 어느 계약의 문서인지가 주소보다 유용하다

### 【연관 화면】 DOC-2, DOC-3, REC-1
### 【알림】 없음

---

## DOC-2 · 개별 문서 조회

**목적** 문서 정보를 보고 내려받는다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** DOC-1 목록에서 문서 선택 / 각 화면 자료보관 탭

### 【입출력 항목】

```
[문서 정보]
제목, 카테고리, 귀속 대상, 업로드한사람, 등록일시, 파일형식, 파일크기, 메모

[액션]
내려받기, 삭제
```

### 【동작 규칙】

- 목록에서 문서를 고르면 **오른쪽 패널로 연다.** 다른 상세(유닛·청구항목)와 같은 방식이다. 목록 내 펼침 방식으로는 화면이 부족하다
- **파일은 권한 확인 후에만 내려받을 수 있다.** 파일 주소만으로 접근되어서는 안 된다

### 【연관 화면】 DOC-1
### 【알림】 없음

---

## DOC-3 · 문서 업로드

**목적** 문서를 업로드하고 귀속 대상을 지정한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** DOC-1 → `문서 업로드`

### 【입출력 항목】

```
[업로드]
파일 (`파일 찾기`로 고른다. 여러 개는 `+ 파일 추가`로 칸을 늘린다. 모든 칸은 처음부터 보인다)
귀속 대상 종류(건물/유닛/계약/임차인/임대인) → 대상 선택    ※ 필수
카테고리 (귀속 대상에 맞는 것만 → 3.1)    ※ 필수
제목    ※ 필수. 파일 이름으로 미리 채운다
메모

[2차] 공개 대상 사용자 지정
```

### 【동작 규칙】

- 여러 파일을 일괄 업로드하며 귀속 대상을 직접 지정한다. 각 화면의 자료보관 탭은 대상이 확정된 상태에서 업로드하는 경로다(같은 패널, 귀속 대상만 읽기 전용) → PRO-3
- 제목은 파일 이름으로 미리 채운다. 제목과 카테고리는 필수다
- 계약서·사업자등록증·신분증·건물서류 카테고리 문서는 내려받은 사람과 시각을 기록한다 → `11_비기능요건.md`. 화면에서 따로 정하지 않는다
- **귀속 대상은 필수다.** 귀속되지 않은 문서는 추후 검색이 불가능하다
- 복수 파일 업로드 시 카테고리와 귀속 대상을 파일별로 다르게 지정할 수 있다
- [2차] 문서를 특정 사용자에게 공개하는 기능은 포털 오픈 후 구현한다. 초기 오픈에서는 모든 관리자가 모든 문서를 열람한다

### 【연관 화면】 DOC-1, DOC-2
### 【알림】 없음

# 이력 관리 (REC)

---

## REC-1 · 이력 목록 조회

**목적** 주요 대상의 변경 이력과 처리 행위를 조회한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 이력 관리 / DASH-1 최근 작업 이력

### 【입출력 항목】

```
필터: 대상 종류, 대상 검색(건물고유이름/계약고유이름/유닛고유번호),
      변경 유형, 처리자, 기간

[목록]
발생일시
대상 종류(건물/유닛/계약/청구/수납/정산/청구항목/건물 관리비 설정/사용자/문서/월 마감)
대상 이름
변경 유형(등록/수정/삭제/상태변경/무효처리/청구서취소/감액/배분재조정/사용중지/배율조정/마감/마감취소)
변경 요약
처리자
사유
더보기(상세 보기, 해당 화면으로 이동)

  ▸ 행 펼침 시 REC-2 상세 표시
```

### 【동작 규칙】

- **이력은 "누가·언제·무엇을·왜"를 기록한다.** 금액의 흐름은 계약 원장에서 확인한다 → CTR-3
- 두 기록은 상호 연결한다. 이력에서 관련 원장 거래로, 원장에서 해당 행위의 이력으로 이동한다
- 대상 종류 11종과 변경 유형 12종, 사유 필수 범위는 → 3.6
- [2차] 요청·예약은 해당 기능 구현 시 대상 종류에 추가한다
- **이력은 조회 전용이다. 수정·삭제할 수 없다**
- 대상 이름 클릭 시 해당 화면으로 이동한다
  계약 → CTR-3 / 청구 → PAY-1 / 수납 → PAY-9 / 정산 → PAY-10

### 【설계 의도】

- 원장은 금액을, 이력은 행위를 기록한다. 분쟁 시 양쪽이 모두 필요하므로 각각 남기고 연결한다
- 수납 기록조차 완전 삭제를 금지했으므로, 그 근거가 되는 이력을 수정 가능하게 두면 일관성이 없다

### 【연관 화면】 REC-2, CTR-3, PAY-1, PAY-9, PAY-10, DASH-1
### 【알림】 없음

---

## REC-2 · 이력 상세 조회

**목적** 선택한 이력의 변경 전후 정보와 연결된 거래를 조회한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** REC-1 목록에서 행 펼침

### 【입출력 항목】

```
[기본 정보]
발생일시, 대상 종류, 대상 이름, 변경 유형, 처리자, 사유

[변경 항목]
필드명, 변경 전, 변경 후

[연결]
관련 원장 거래(거래유형, 금액, 청구년월)
관련 청구 건 / 수납 건 / 정산 회차
→ 클릭 시 해당 화면으로 이동
```

### 【동작 규칙】

- **별도 페이지로 이동하지 않고 REC-1 목록에서 행을 펼쳐 같은 위치에 표시한다**
- 변경 항목은 필드 단위로 변경 전후를 나란히 표시한다. 상태 변경처럼 단일 값만 변경되는 경우에도 동일 형식을 사용한다
- 처리자는 관리자 이름을 표시하며, 시스템 자동 처리 건은 `admin_system`으로 표시한다
- 연결된 원장 거래가 있으면 함께 표시한다. 무효 처리·배분 재조정처럼 취소 거래가 기록되는 행위는 이력과 거래를 병렬 확인할 수 있어야 한다

### 【설계 의도】

- 이력은 탐색하며 찾는 화면이므로 건별 페이지 이동 시 흐름이 단절된다

### 【연관 화면】 REC-1
### 【알림】 없음

# 리포트 (REP)

---

## REP-1 · 핵심 정보 요약

**목적** 임대인에게 전달할 월간 보고서를 조회하고 출력·발송한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 보고서 / USER-8·USER-9 `보고서 뽑기`

### 【입출력 항목】

```
필터: 임대인, 건물고유이름, 기간(디폴트: 당월)

[1. 임대 현황 요약]
전체 유닛 수, 사용중, 공실, 비운영중, 공실률, 전체 임대면적, 공실 면적

[2. 수입 현황]
청구항목별 청구액, 수납액, 미납액, 수납률
(임대료 / 고정관리비 / 정산 항목 / 기타)

[3. 미납·연체 현황]
계약고유이름, 임차인, 미납액, 연체일수, 연체료(예상)

[4. 보증금 현황]
기초 잔액, 당월 예치, 당월 차감, 당월 반환, 기말 잔액
[내역] 계약고유이름, 임차인, 구분(예치/차감/반환), 금액, 사유

[5. 계약 현황]
진행중 계약 수, 당월 신규 계약, 당월 종료 계약
만료 임박: 90일 이내 00건 / 60일 이내 00건 / 30일 이내 00건

[6. 임차인 명세]
유닛고유번호, 임차인(상호), 계약기간, 임대료, 고정관리비, 보증금, 계약상태

[7. 관리비 정산 요약]
청구항목별 고지서 총액, 임차인 청구분, 공실 미청구분(건축주 부담)

[2차] 8. 비용 및 수지 요약
[2차] 9. 수선 요청 처리 현황

출력: PDF 출력, 엑셀 출력, 메일 발송
```

### 【동작 규칙】

**보고 단위**
- **임대인 × 월을 기본 단위로 한다.** 한 임대인이 여러 건물을 보유하는 경우가 많으므로 전체 합계를 선두에 두고 건물별 섹션으로 구분한다. 건물 단일 선택도 가능하다
- 기간은 당월이 기본이며 직접 지정할 수 있다. 분기·연간 보고는 기간 지정으로 산출한다

**산출**
- 공실률 → 4.5
- 수납률 = 수납액 ÷ 청구액
- **금액은 부가세 포함 합계 기준으로 표시한다** → 3.4. 실제 수수 금액을 확인하는 문서이기 때문이다
- **보증금 현황은 계약 원장의 임대보증금 계정에서 산출한다.** 보증금 예치·차감·환급 거래가 그대로 증감 내역이 된다 → 2.7
- 관리비 정산 요약의 `공실 미청구분`은 공실 유닛에 안분되었으나 청구하지 않은 금액이며 건축주 부담액이다 → 4.1.7

**공동소유**
- 공동소유 건물이라도 **건물 전체 기준으로 산출한다.** 지분별 분할 금액은 표시하지 않는다. 지분 분할은 정산·세무와 연계되므로 임대인 포털 구현 시 함께 결정한다 → OWN 계열

**출력·발송**
- PDF·엑셀로 출력한다
- `메일 발송` 실행 시 임대인 이메일로 보고서를 첨부 발송하고 발송 내역에 기록한다 → NTF-6
- [2차] 임대인 포털(OWN-7)이 열리면 임대인이 직접 열람한다

**2차 섹션**
- [2차] 비용 및 수지 요약은 비용 관리 기능 구현 시 추가한다. 비용을 부분적으로만 관리하면 시스템과 엑셀의 이중 관리가 발생하므로 초기 오픈 범위에서 제외한다
- [2차] 수선 요청 처리 현황은 REQ 계열과 함께 추가한다

### 【설계 의도】

- 관리자가 직접 메일을 발송하면 이력이 남지 않아 사후에 발송 여부를 확인할 수 없다. 이메일 발송 경로가 이미 존재하므로 시스템에서 발송한다

### 【연관 화면】 USER-8, USER-9, PAY-10, NTF-6
### 【알림】 이메일 — 임대인에게 월간 보고서 발송

## NTF-6 · 발송 내역 조회

**목적** 시스템이 발송한 메일의 결과를 조회하고 재발송한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 발송 내역 / DASH-1 발송 실패 카드

### 【입출력 항목】

```
필터: 발송종류, 채널, 발송방식(자동/수동), 상태(성공/실패/대기),
      기간, 수신자 검색

[목록]
발송일시
발송종류(계정초대 / 비밀번호재설정 / 웰컴메시지 / 청구내역서 / 납부안내 /
        미납안내 / 청구내역서재발송 / 임대인보고서)
채널(이메일 / [2차] 알림톡)
수신자(이름, 이메일 주소)
관련 대상(계약고유이름 / 청구년월 / 사용자 / 건물고유이름)
발송방식(자동 / 수동)
발송자(시스템 / 관리자명)
상태(성공/실패/대기), 실패사유
더보기(내용 보기, 재발송)

[내용 보기]
발송 당시의 제목과 본문, 첨부파일
```

### 【동작 규칙】

**1차 발송 종류 — 8종 (전부 이메일)**

| 발송종류 | 발생 시점 | 화면 |
|---|---|---|
| 계정 초대 | 관리자 계정 등록 | USER-3 |
| 비밀번호 재설정 | 재설정 메일 발송 | USER-2 |
| 웰컴 메시지 | 계약 등록 (선택) | CTR-2 |
| 청구 내역서 | 청구서 발행 | PAY-1 |
| 납부 안내 | 납부마감일 N일 전. **그때까지 내지 않은 계약에만** | 설정 위치 미확정 → 4.7 |
| 미납 안내 | 관리자 일괄 발송 | PAY-2 |
| 청구 내역서 재발송 | 청구서 취소 후 다시 발행(`메일 보내고 발행`) | PAY-1 |
| 임대인 보고서 | 메일 발송 실행 | REP-1 |

- [2차] 알림톡은 NTF 계열 정비 시 채널로 추가한다

**기록**
- **발송 당시의 제목·본문·첨부파일을 그대로 보관한다.** 임차인이 수신 내용에 이의를 제기할 때 당시 발송본을 제시할 수 있어야 한다. 현재 템플릿으로 재생성하면 변경된 내용이 표시된다
- 수신자 이메일 주소도 **발송 당시 값**으로 보관한다. 담당자 변경 시 현재 주소와 상이하다
- `관련 대상`으로 무엇에 대한 발송인지 확인한다. 본 화면의 주 용도는 `해당 임차인에게 당월 청구서가 발송되었는가`의 확인이다

**재발송**
- 성공·실패와 무관하게 재발송이 가능하다. 전송에 성공했더라도 임차인 요청으로 재발송하는 사례가 있다
- **재발송은 새로운 발송 건으로 기록한다.** 원 발송 건을 덮어쓰지 않는다

**실패 처리**
- **발송 실패 시 자동 재시도하지 않는다.** 주소 오류로 인한 실패는 재시도해도 동일하게 실패한다
- 발송 실패 시 관리자에게 내부 알림을 발송한다 → DASH-1
- 실패 사유는 메일 서버 응답을 그대로 보관한다 (주소 없음, 수신 거부 등)

**보존**
- **발송 내역은 삭제하지 않는다.** 청구와 미납 안내의 발송 증빙이며 분쟁 시 사용된다

### 【연관 화면】 PAY-1, PAY-2, PAY-3, REP-1, USER-2, USER-3, CTR-2, DASH-1
### 【알림】 내부 — 발송 실패 시 알림

# 대시보드 (DASH)

---

## DASH-1 · 핵심 지표 정리

**목적** 현재 상태와 처리 대기 업무를 한 화면에서 확인한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 로그인 후 초기 화면

### 【입출력 항목】

```
필터: 건물고유이름(전체 / 개별 선택)

───── 1단. 요약 카드 ─────
(공실률)            공실률(%), 공실 유닛 수 / 전체 유닛 수        → PRO-1
(이번 달 청구·수납)  청구액, 수납액, 수납률(%)                    → PAY-12
(미납)              미납액 합계, 연체료(예상) 합계, 미납 계약 수     → PAY-2
(만료 임박 계약)     90일 이내 00건 / 60일 이내 00건 / 30일 이내 00건
                                                                → CTR-1 (일수 필터)

───── 2단. 확인이 필요한 일 ─────
[목록] 항목, 건수, 가장 오래된 건의 경과일수, 전체보기
 · 정산이 확정되지 않은 건물                → PAY-10
 · 처리하지 않은 입금 (자동 매칭·미매칭)     → PAY-13
 · 보증금 미입금 상태의 준비중 계약          → CTR-1 (준비중 필터)
 · 임대료 인상 예약 도래 (30일 이내)            → CTR-3
 · 위탁운영계약 만료 임박 건물 (90일 이내)   → USER-8
 · 메일 발송 실패                           → NTF-6 (실패 필터)
 · 마감을 기다리는 달 (납부마감일이 지난 열린 달) → PAY-11
 · [2차] 새로운 요청(분류전), 지연된 요청     → REQ-1

───── 3단. 최근 작업 이력 ─────
[목록] 발생일시, 대상, 변경 유형, 처리자 (최근 10건)   → REC-1
```

### 【동작 규칙】

**화면 구성**
- 모든 지표는 카드 형태로 표시한다
- 각 카드 하단에 `전체보기` 버튼을 고정 배치하며 클릭 시 해당 화면으로 이동한다
- 3단으로 구성한다

| 단 | 역할 |
|---|---|
| 1단 요약 카드 | 현재 상태 |
| **2단 확인이 필요한 일** | **관리자가 처리해야 할 업무. 본 화면의 핵심** |
| 3단 최근 작업 이력 | 처리 내역 |

**2단 규칙**
- **건수가 0인 항목은 행을 숨긴다.** 처리할 업무가 없으면 비어 있어야 한다
- `정산이 확정되지 않은 건물`과 `처리하지 않은 입금`을 최상단에 배치한다

| 항목 | 방치 시 결과 |
|---|---|
| 정산 미확정 | 해당 월 청구서 미발행 |
| 처리하지 않은 입금 | 임차인이 납부했으나 미납으로 집계 |

- 2단 전체에 경과일수를 표시한다. 등록일 기준으로 며칠 경과했는지 표시해 우선순위를 판단한다
  예: 등록일시가 2024년 5월 12일이고 오늘이 5월 14일이면 `2일 경과`

**필터**
- 상단에 건물 선택 필터를 배치한다. 전체 선택 시 건물별 소계로 표시하고 펼치면 계약별로 표시한다. 건물 단일 선택 시 계약별로 직접 표시한다

**2차 항목**
- [2차] 수선 요청·지연된 요청 카드는 REQ 계열과 함께 구현하며 **초기 오픈에서는 표시하지 않는다.** 빈 카드를 노출하면 반복 확인이 발생한다

### 【설계 의도】

- 상태 조회보다 처리해야 할 업무를 확인하는 화면으로 구성한다
- 여러 화면에서 `대시보드에 표시`로 정의한 항목을 2단에 통합한다
  (만료 임박 → CTR-1 / 임대료 인상 예약 도래 → CTR-3 / 위탁운영계약 만료 → USER-9 / 발송 실패 → NTF-6 / 자동갱신 만기 → CTR-4)

### 【연관 화면】 PRO-1, CTR-1, CTR-3, PAY-2, PAY-13, PAY-10, USER-8, NTF-6, REC-1
### 【알림】 없음
