# 6. 데이터 요구사항

본 장은 시스템이 저장해야 할 대상(엔터티)과 속성, 관계를 정의한다.
**스키마 설계의 입력물이며 스키마 자체가 아니다.** 컬럼 타입·인덱스·테이블 분할은 스키마 설계에서 결정한다.

---

## 6.1 설계 원칙

| # | 원칙 | 내용 |
|---|---|---|
| 1 | **원장이 원본이다** | 잔액·수납액·미납액·납부상태는 원장 거래에서 산출하는 파생값이다. 파생값은 원장 거래를 기록하는 시점에 갱신한다. 상태를 변경하는 경로는 원장 거래와 수납 배분·전월 잔액 이월 데이터뿐이다(잔액을 바꾸지 않는 옮김은 원장 거래 없이 이 데이터로 남는다 → 2.7). 별도 보관하더라도 원장과 불일치 시 원장이 기준이다 |
| 2 | **기록은 수정·삭제하지 않는다** | 원장 거래·이력·검침 기록·발송 내역은 추가만 허용한다. 오류는 취소 거래 또는 조정 기록으로 정정한다 |
| 3 | **식별자는 유일해야 한다** | 임차인·임대인은 사업자등록번호로 식별한다. 동일 사업자의 중복 등록을 허용하지 않는다 |
| 4 | **마감된 기간은 잠긴다** | 마감된 건물 × 월에는 원장 거래를 추가할 수 없다 |
| 5 | **계층을 유지한다** | 건물 → 유닛 → 계약 → 청구 → 수납의 계층 관계를 전제로 설계한다 |
| 6 | **모든 업무 데이터는 운영사에 속한다** | 운영사 식별값을 보유하고, 격리는 데이터베이스가 강제한다 → `11_비기능요건.md` 7.2 |

| 대상 | 사유 |
|---|---|
| 차량 정보 | 차량번호를 관리하지 않는다. 주차면을 계약에 직접 배정한다 |

## 6.3 운영사

### 운영사

| 속성 | 필수 | 비고 |
|---|---|---|
| 운영사명 | ● | 화면 상단과 발송 문서에 표시 |
| 운영사구분 | ● | 실운영 / 검증용. **등록 후 변경 불가** |
| 사업자등록번호 · 대표자명 · 주소 · 연락처 | | |
| 로고 | | |
| 구글 로그인 사용 여부 | ● | 기본값 미사용 → `11_비기능요건.md` 7.4.1 |
| 상태 | ● | 정상 / 중지. 삭제하지 않는다 |

**모든 업무 데이터는 운영사에 속한다.** 건물·유닛·계약·청구·수납·원장·정산·문서·이력·
발송 내역이 대상이며, 각 엔터티는 소속 운영사 식별값을 보유한다.

격리는 데이터베이스 수준에서 강제한다. 응용 프로그램의 조회 조건에 의존하지 않는다.
→ `11_비기능요건.md` 7.2.2

### 관리자 담당 건물

| 속성 | 필수 | 비고 |
|---|---|---|
| 사용자 | ● | 역할이 `관리자`인 계정만 |
| 건물 | ● | |

사용자 × 건물의 다대다 관계다. 슈퍼관리자와 시스템 운영자는 본 엔터티를 사용하지 않는다.
슈퍼관리자는 소속 운영사 전체가 대상이며, 시스템 운영자는 업무 데이터를 조회하지 않는다.

관리자의 모든 조회는 **소속 운영사 조건과 담당 건물 조건을 함께 충족**해야 한다.

### 관리위임계약 (건물 소속)

| 속성 | 비고 |
|---|---|
| 관리계약시작일 · 관리계약종료일 | 남은 일수는 파생값 |

| 운영방식 | 임대인 직수취 / [2차] 위탁사 수취 후 정산 |

건물당 유효 1건. 계약서를 건물마다 별도로 작성하므로 임대인이 아닌 건물에 둔다.
위임계약서 파일은 건물에 귀속된 문서로 보관한다.

### 건물 청구항목 설정 (건물 × 청구항목)

| 속성 | 비고 |
|---|---|
| 사용여부 · 발행 문서 | 세금계산서 / 계산서 / 일반내역서 → 3.3. 기준표 값을 덮어쓴다 |
| 반복주기 | 5종 → 3.3. 기준표 값을 덮어쓴다 |
| 배분 우선순위 | 1~99. 기준표 기본 우선순위를 덮어쓴다 → 4.3 |
| 배분 기준 | 사용량 / 임대면적 / 사용량+임대면적 / 직접 입력 → 4.1.3-1. 미지정 시 임대면적 |
| 참조 항목 | 같은 건물의 다른 청구항목. 배분 기준이 `사용량`이고 자체 계량기가 없을 때 → 4.1.3-1 |
| 근거 문서 | 고지서 / 내역서 / 계약서 / 집계표 |
| 발행처 | 한국전력 · 상수도사업본부 · 경비실 등 |

> 공용분 부담 대상은 저장하지 않는다. 언제나 전 유닛이다. 빼려면 회차 배율 0 → 4.1.2 · 4.1.7

### 유닛 검침 설정 (유닛 × 청구항목)

| 속성 | 비고 |
|---|---|
| 계량기 보유 여부 | 배분 기준 지정 시 기본 전 유닛 선택 |
| **계기배율** | 기본 1. 1/30 계량기는 30 → 4.1.3-3 |
| **계량기 공유 대상** | 이 유닛의 사용분이 포함된 상대 유닛. 미지정이 기본 → 4.1.3-4 |

배분배율은 유닛 설정이 아니다. 정산 회차마다 조정 기록에 둔다.

## 6.6 계약

### 계약

| 속성 | 필수 | 비고 |
|---|---|---|
| 유닛 · 임차인 | ● | **유닛은 수정 불가.** 계약 1건은 유닛 1개다. 여러 유닛을 쓰는 임차인은 계약이 여러 건이다 |
| 계약상태 · 계약유형 | ● | 4종 / 2종 |
| 계약시작일 · 계약종료일 | ● | 종료일 기본값 2년 후 전날 |
| 청구일 | ● | 건물 기본값 상속 |
| 보증금 약정액 · 납부마감일 · 반환예정일 | | |
| 무상 주차 대수 · 초과 1대당 월 단가 | | |
| 연체이자율 | | 연 %. 계약마다 입력. 기본 8% |
| 렌트프리 여부 · 끝나는 날 · 대상 항목 | ● | 있음/없음 필수. 대상(임대료 / 고정관리비 / 그 밖의 청구항목). 기산일 = 끝나는 날 다음 날 → 3.5 |
| 연체료 정리일 | | 수납 처리에서 연체료를 받거나 감면한 날. 그날까지의 연체료는 다시 세지 않는다 → 4.4.3 |
| **기존 계약** | | 연장 계약인 경우 원 계약 연결 |
| 정산액 대납 계약 | | 이 계약의 정산액을 대신 부담하는 계약. 미지정이 기본 → 4.1.7-3 |
| 해지유형 · 해지일 · 해지사유 · 위약금 · 원상복구비 | | 해지 처리 시 |
| 메모 | | |

계약고유이름은 파생값이다(`건물별칭|유닛고유번호|대표임차인명`). 저장하지 않는다 → 3.1
임차인 상호가 바뀌면 계약고유이름도 따라 바뀐다. 다만 **이력에는 스냅샷으로 남긴다** → 3.6

관계: 계약 1 — N 담당자 / 청구 약정 / 임대료 인상 예약 / 청구서 / 입금 / 원장 거래 / 배정 주차면.
계약 1 — 0..1 계약자(환불계좌 포함) / 대리인 / 중개사.

## 6.7 청구

### 청구항목 — 건물 소속

청구항목은 **건물 청구항목 설정**(6.4)이 그 자체다. 운영사 공통 목록을 두지 않는다.

| 속성 | 비고 |
|---|---|
| 건물 · 청구항목명 | 건물 안에서 유일 |
| 기준 항목 | 기준표 19종 중 무엇인지. 새로 만든 항목은 비어 있다. **건물 간 집계는 이 값으로 한다** |
| 산정방식 | 고정액 / 정산. 고정액은 임대료·고정관리비뿐이며 고칠 수 없다. 새로 만든 항목은 정산. 연체료는 산정방식이 없다(수납 처리 때 정함) → 3.2-2 |

- **건물당 최대 99개.** 배분 우선순위는 건물 안에서 유일(1~99)
- 기준표 19종은 시스템 고정값이다. 항목을 추가할 때 기본값을 채우는 데만 쓴다 → 3.3

### 청구 약정 (계약 소속)

| 속성 | 비고 |
|---|---|
| 청구항목 | **고정액 항목만**(임대료 · 고정관리비). 정산 항목은 계약에 저장하지 않고 건물 청구항목 설정을 따른다 |
| 약정액 | **부가세 포함 금액**. 공급가액·부가세는 역산 → 3.4. **0원이면 청구하지 않는다** |
| 반복주기 | 반복 종료 조건은 두지 않는다. 과세 여부는 청구항목의 발행 문서를 따른다 |
| **기산일** | 기본값 계약시작일. 렌트프리·소급은 이 값으로 표현. 렌트프리 대상이 아닌 항목은 계약시작일 |
| 메모 | 배분 우선순위는 약정에 두지 않는다. 건물 청구항목 설정을 따른다 |

### 청구서 (계약 × 청구년월)

| 속성 | 비고 |
|---|---|
| 계약 · 청구년월 | 동일 계약·청구년월에 유효 청구서는 1건. 취소 후 다시 발행하면 새 청구서 |
| 발행일 · 납부마감일 | 납부마감일은 건물 설정에서 온다. 바꾸지 않는다 |
| 구분 | 정기 / 퇴거 정산 / 연체료. 연체료는 수납 처리(PAY-2) 때 받은 날로 생성한다. 계약 × 청구년월 유일성에서 제외한다 → 4.4.3 |
| 상태 | 유효 / 취소 |
| 원 청구서 | 취소 뒤 다시 발행한 경우 취소된 청구서 연결 |
| 메일 발송 여부 | 발행 확인에서 `메일 보내고 발행`을 골랐는지 → PAY-1 |

합계·수납액·미납액은 파생값이다.
일할 발행(청구일 경과 후 계약 시작)의 경우 청구년월이 다른 청구서 2건이 같은 날 발행된다.

### 청구 건 (청구서 소속)

| 속성 | 비고 |
|---|---|
| 청구항목 · 청구 약정 | 연체료·추가 청구는 약정 없음 |
| 대납 출처 계약 | 정산액 대납으로 실린 청구 건만. 산출 유닛의 계약 → 4.1.7-3 |
| 공급가액 · 부가세 · 합계 | 절사 후 금액 |
| 감액 | 파생값(감액 거래 합계). 받을 금액 = 합계 − 감액 → CTR-3 |
| 단수 절사액 | 청구서 합계 100원 미만 절사분. 우선순위 최하위 항목에 기록 |
| 산출 근거 | 고정액 / 일할(대상 일수·총일수) / 정산 회차 연결 / 추가 청구 / 수동 입력(사유) |

납부상태는 파생값이다(→ 3.2). 저장하더라도 원장이 기준이다.

|---|---|
