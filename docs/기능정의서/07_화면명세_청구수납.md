## PAY-12 · 청구·수납 현황

**목적** 건물별로 이번 회차의 청구·수납 업무가 어디까지 진행되었는지 조회한다.

> 계약 단위 미납 관리는 PAY-2에서 수행한다. 본 화면은 **건물 단위 진행 상태**를 다룬다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 청구·수납 그룹 클릭

> **사이드바 하위 메뉴에 별도 항목을 두지 않는다.** 그룹 진입 시 표시되는 화면이므로
> 하위 목록에 중복으로 노출할 필요가 없다.

### 【입출력 항목】

```
필터: 정산회차(년월)

(요약)
청구 금액, 수납 금액, 미납 금액, 수납률, 정산 미확정 건물 수

(건물별 진행)
[목록] 건물고유이름, 건물구분, 유닛 수,
       정산 상태(미착수 / 작성중 / 확정),
       청구서(발행 건수 / 대상 건수),
       청구 금액,
       수납(수납 완료 건수 / 발행 건수, 진행률),
       미납 금액,
       마감 여부
[합계] 전 건물 합산
```

### 【동작 규칙】

- **담당 건물만 표시한다.** 관리자는 배정된 건물, 슈퍼관리자는 운영사 전체 → 3.7
- 각 칸을 클릭하면 해당 업무 화면으로 이동하며 **해당 건물과 회차가 선택된 상태**로 진입한다

| 칸 | 이동 |
|---|---|
| 정산 상태 | PAY-10 관리비 정산 |
| 청구서 · 수납 | PAY-2 미납 관리 |
| 마감 | PAY-11 월 마감 |

- 정산 상태가 `확정`이 아니면 청구서를 발행할 수 없다. 해당 건물의 청구서 칸은 `미발행`으로 표시한다
- 수납 진행률은 **건수 기준**이다. 금액 기준 수납률은 요약에 별도로 표시한다
- **마감 열은 `월 마감` 여부다. 완납 여부가 아니다.** 상태는 `열림` / `마감`으로 표기하고
  마감된 건물은 마감일을 함께 보여준다
- **미납이 남아 있어도 마감한다.** 미납액은 채권으로 이월되며 마감 여부와 무관하다 → PAY-11
- 마감된 건물은 해당 회차의 거래를 변경할 수 없다 → PAY-11

### 【설계 의도】

- 대시보드(DASH-1)가 **처리가 필요한 예외**를 모으는 화면인 반면,
  본 화면은 **전 건물의 진행 상태 전부**를 보여준다. 월중에 업무 진척을 확인하는 용도다
- 건물 수가 늘어날수록 "어느 건물이 어디까지 됐는지"를 화면을 옮겨 다니며 확인하는 비용이 커진다
- 청구·수납 영역은 화면이 8개로 가장 많다. 그룹 진입 시 첫 화면을 두어
  어느 화면으로 갈지 판단할 근거를 제공한다

### 【연관 화면】 PAY-2, PAY-10, PAY-11, DASH-1
### 【알림】 없음

## PAY-1 · 청구 스케줄 조회

**목적** 계약별로 등록된 청구 스케줄(약정)을 조회한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 청구 관리

### 【입출력 항목】

```
필터: 건물고유이름, 계약상태(디폴트: 진행중), 청구항목, 산정방식(고정액/정산)

[목록]
계약고유이름(건물별칭|유닛고유번호|대표임차인명)
계약상태
청구항목(→ 3.3 기준표. 새로 등록 가능)
산정방식(고정액 / 정산)
반복주기(이번만 / 매월 / 격월 / 분기 / 반기 / 연1회)
기산일
청구액(정산 항목은 "정산"으로 표시)
부가세대상여부(과세 / 면세)
더보기(수납기록생성, 계약정보, 임차인정보)
```

### 【동작 규칙】

- **본 화면은 약정만 표시한다. 납부 상태를 알 수 없다.** 회차별 실제 청구액과 수납 현황, 미납 내역은 PAY-2에서 확인한다
- 계약별로 그룹핑한다
  예: `영준|801호|(주)한빛 임대료` / `… 고정관리비` / `… 전기요금`
- 산정방식이 `고정액`인 항목은 계약 약정액을 표시한다
- 산정방식이 `정산`인 항목은 회차마다 금액이 달라지므로 청구액 칸에 **`정산`** 으로 표시한다. 실제 금액은 PAY-10에서 산출된다. 정산 주기는 반복주기 칸에서 확인한다
  예: 전기요금 매월 / 상하수도요금 격월 / 교통유발부담금 연1회 / 정화조청소비 반기
- **금액은 부가세 별도로 표시한다** → 3.4
- 상단에 `미납 조회 화면으로 이동` 버튼을 배치한다 → PAY-2
- 상단에 `새로운 청구 스케줄 등록` 버튼을 배치한다 → PAY-3
- 행 클릭 시 계약 상세의 청구항목정보탭으로 이동한다 → CTR-3
- **연체료는 미납이 발생한 계약에만 표시한다.** 연체이자율은 계약에 등록하며 금액은 PAY-2에서 산출한다. 자동 청구하지 않는다 → 4.4

### 【설계 의도】

- 화면명을 `청구 내역 조회`에서 변경했다. 실제 내용이 약정 조회이며, 정산 항목은 약정액이 없어 본 화면만으로는 실제 청구액을 알 수 없다

### 【연관 화면】 PAY-2, PAY-3, PAY-10, CTR-3
### 【알림】 없음

## PAY-2 · 미납 관리

**목적** 회차별 청구·수납 현황과 미납 내역을 조회하고, 일괄 수납 처리와 독촉 발송을 수행한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 미납 관리 / DASH-1 미납 카드 / PAY-1 상단 버튼

### 【입출력 항목】

```
필터: 건물고유이름, 계약상태(디폴트: 진행중),
      납부상태(디폴트: 납부전 + 부분납)

[목록]  청구별 체크박스. 일괄 처리와 이메일 발송에 사용
(체크박스)
계약고유이름, 계약상태, 청구항목, 반복주기, 납부마감일,
공급가액, 부가세, 청구액(합계),
수납액, 미납액,
납부상태(납부전/부분납/완납/무효), 연체일수, 연체료(예상),
더보기(수납기록생성, 계약정보, 임차인정보)

[계약별 소계]
계약고유이름, 미납 건수, 미납액 합계

상단 버튼: 일괄 수납 처리, 연체료 청구, 이메일 일괄 발송, 미납만 보기
```

### 【동작 규칙】

**상태와 집계**
- 미납액 = 청구액 − 수납액. 미납액이 0이 되면 납부상태가 완납으로 변경된다
- **납부상태는 금액 기준으로만 판단한다.** 기한 경과는 연체일수 칸에서 별도 표시한다 → 3.2
- `미납만 보기`는 납부상태 `납부전 + 부분납` 필터를 적용한다
- 연체일수 = 오늘 − 납부마감일. 마감 전이면 `-`로 표시한다
- **납부상태는 직접 수정할 수 없다.** 수납 거래를 기록하면 상태가 따라온다

**금액 표시**
- **부가세를 포함한 합계 기준으로 표시하며 공급가액·부가세를 함께 보여준다** → 3.4
  실제로 받아야 할 금액을 확인하는 화면이며 세금계산서와 대조할 수 있어야 한다
- 약정액을 보는 화면(CTR-1, PAY-1)과 기준이 다르다

**연체료**
- 산출식과 예시는 → 4.4
- **표시만 하며 자동 청구하지 않는다.** `연체료 청구` 실행 시에만 청구 항목이 생성되고 원장에 기록된다
- 연체료는 과세 항목이다

**일괄 수납 처리**
- 선택한 청구 건에 대해 수납일, 수납수단(계좌이체/카드/현금/보증금상계), 입금자명을 입력받아 원장에 수납 거래로 기록한다
- **납부상태를 직접 변경하는 것이 아니라, 거래를 기록하면 상태가 따라온다** → PAY-6

**발송**
- `이메일 일괄 발송`은 선택한 미납 건의 내역을 담은 독촉 메일을 임차인 담당자에게 발송한다
- [2차] `알림톡 일괄전송`은 NTF 계열과 함께 구현한다

**표시 단위**
- 계약별로 그룹핑하고 계약별 미납 소계를 표시한다. 한 임차인이 여러 항목을 연체한 경우 총액을 즉시 확인할 수 있어야 한다

### 【설계 의도】

- `완납 처리` 버튼을 두지 않는다. 상태만 변경하면 장부에 없는 돈이 발생한다
- 납부상태에서 기한 개념을 분리한다. 금액과 시점을 하나의 상태로 표현하면 부분납을 구분할 수 없다

### 【연관 화면】 PAY-1, PAY-6, PAY-8, CTR-3, DASH-1
### 【알림】 이메일 — 미납 독촉 일괄 발송 / [2차] 알림톡 — 동일

## PAY-3 · 청구 스케줄 생성

**목적** 계약에 청구 스케줄을 등록하고 수정·삭제한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PAY-1 상단 버튼 / CTR-3 청구항목정보탭 → 고정액 항목 수정

### 【입출력 항목】

```
(생성)
청구항목(→ 3.3 기준표. 새로 등록 가능)
산정방식(고정액 / 정산)
청구액       ※ 고정액 항목만 입력. 정산 항목은 PAY-10에서 산출
메모
반복주기(이번만 / 매월 / 격월 / 분기 / 반기 / 연1회)
부가세대상여부(과세 / 면세, 디폴트: 과세)
청구알림설정(00일 전에 보내기)
반복종료조건(계약종료시까지 / 00번 반복 후 종료)
우선순위     ※ 수납 배분 순서

※ 청구일과 납부마감일은 계약 단위로 관리한다 (건물 기본값을 계약이 상속)

(반복 스케줄 수정 시)
적용 범위: 이 항목만 수정 / 이후 반복 모두 수정 / 전체 반복 수정

(반복 스케줄 삭제 시)
적용 범위: 이 항목만 삭제 / 이후 반복 모두 삭제
```

### 【동작 규칙】

**등록과 발행의 구분**
- **스케줄 등록은 계약상태가 준비중일 때도 가능하다**
- **실제 청구 회차는 계약이 진행중이 된 뒤부터 생성된다.** 보증금 입금 전에 청구서가 발행되지 않도록 한다

**회차 생성**
- 반복 항목은 청구일에 맞춰 백그라운드 스케줄러가 회차를 생성한다
- 고정액 항목(임대료·고정관리비)은 금액이 확정되어 있으므로 스케줄러가 자동 생성한다
- 정산 항목은 PAY-10에서 금액이 확정될 때 회차가 생성된다
- **두 항목은 같은 청구년월로 묶여 계약당 청구서 1장이 된다**
- 관리자가 임의로 스케줄을 중지할 수 있다

**청구서 발행 단위**
- 회차(청구년월)마다 **계약당 청구서 1장**을 발행하며 그 안에 항목별 명세를 담는다
- **청구서는 독립된 개체이며 발행일·납부마감일·합계·발송 상태를 보유한다** → 2.5
- 원장에는 청구 건(항목) 단위로 청구 거래가 각각 기록된다 → CTR-3

**청구일·납부마감일**
- 건물에 기본값을 두고 계약에서 덮어쓴다. **계약 단위로 1쌍만 두며 청구 항목별로 두지 않는다** → 3.5
  예: 8월분 임대료·관리비를 8월 19일에 청구하고 8월 31일까지 납부
- 건물 기본값 변경은 이후 등록되는 계약에만 적용한다

**단수 처리**
- **청구서 합계는 100원 미만을 자동 절사한다.** 절사액은 청구서 내 우선순위가 가장 낮은 항목에서 차감하고 청구서에 `단수 절사` 행으로 표시한다 → 4.2.6

**일할 계산**
- 산출식과 예시는 → 4.2
- 해지일이 입력된 계약은 고정액 항목을 자동으로 일할 계산한다. 해지일이 당월 청구일 이전이면 당월 청구서를 발행하지 않는다 → 4.2.3
- 계약이 시작된 회차의 청구일이 이미 경과한 경우 **다음 회차 청구일에 청구서를 2장 발행한다.** 지난 회차 일할분과 당월 전액을 각각 발행하며 납부마감일은 둘 다 당월 마감일로 한다

**정산 항목의 부분 기간**
- 임차인이 산정 기간 중 일부만 사용한 경우(입주·퇴거) 담당자가 해당 유닛의 금액을 직접 계산해 입력한다. 시스템은 검침과 안분까지만 처리한다 → 4.1.9

**공실**
- 공실 유닛도 공용분 안분 대상에 포함하되 청구서를 생성하지 않는다 → 4.1.7

**수납 배분 우선순위**
- 청구항목마다 우선순위가 존재한다 (예: 임대료=1, 고정관리비=2, 주차비=3)
- 우선순위는 하나의 계약 내에서만 유효하며 계약마다 다를 수 있다
- 기본값은 3.3 기준표를 따른다. 연체료는 99(최후순위)다
- 배분 순서는 → 4.3

**반복 스케줄 수정·삭제**
- 수정·삭제 시 적용 범위를 선택한다
- **이미 발행된 회차는 본 화면에서 변경하지 않는다.** 발행된 청구의 수정·무효 처리는 PAY-5에서 수행한다
- 스케줄 수정은 앞으로 생성될 회차부터 적용하며 이미 발행된 회차에 소급하지 않는다
- 수정·삭제 시 이력을 기록한다 → 3.6

### 【설계 의도】

- 등록과 발행을 분리한다. 계약 등록 화면에서 청구 항목을 함께 입력받으므로 준비중 상태에서도 스케줄이 존재해야 한다

### 【연관 화면】 PAY-1, PAY-5, PAY-10, CTR-2, CTR-3
### 【알림】 이메일 — 청구일에 청구 내역서 발송, 청구알림설정에 따른 납부 안내 / [2차] 알림톡 / 내부 — 청구 회차 생성 결과, 발송 성공 여부

[목록]
청구항목명, 묶음, 기본 산정방식, 기본 부가세대상여부, 기본 우선순위,
사용여부, 기본제공여부,
더보기(수정, 사용 중지, 삭제)

청구항목명

PAY-4   "전기요금이라는 항목이 존재한다"              — 시스템 전체

- 기본 제공 19종의 목록과 기본값은 → 3.3

**수정·삭제 제한**

- 사용 중인 항목은 삭제 대신 **사용 중지**로 처리한다. 사용 중지된 항목은 새 계약과 새 건물 설정에서 선택할 수 없으나 기존 계약과 과거 원장 기록은 유지된다

**배치**
- 매일 사용하는 화면이 아닌 초기 설정 화면이므로 관리자 `설정` 메뉴 아래에 배치한다
- [2차] `슈퍼관리자만 등록·수정·삭제` 권한 구분은 권한 세분화와 함께 구현한다 → 3.7

### 【설계 의도】

- 건물마다 항목을 별도 생성하면 동일 항목이 건물 수만큼 발생해 건물 간 집계·비교가 불가능해진다
- 이름 수정을 막는 이유는 과거 원장 기록과의 대조가 불가능해지기 때문이다
- `청구 항목`(마스터)과 `청구 내역`(발행 건)의 혼동을 방지하기 위해 화면명을 `청구 항목 관리`로 변경했다

## PAY-5 · 발행 청구 수정 및 취소

**목적** 이미 발행되어 원장에 기록된 청구 회차를 수정하거나 무효 처리한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PAY-2 더보기 / CTR-3 원장정보탭

### 【입출력 항목】

```
필터: 건물고유이름, 청구년월, 계약상태, 납부상태

[목록]
청구년월, 계약고유이름, 청구항목,
공급가액, 부가세, 청구액(합계),
납부액, 미납액, 납부상태      ※ 읽기 전용
납부마감일,
더보기(납부마감일 변경, 메모 수정, 무효 처리, 재발행, 변경 이력 보기)

[납부마감일 변경시]  변경할 납부마감일, 변경 사유
[무효 처리시]        무효 사유
[재발행시]           무효 처리한 청구의 내용이 채워진 상태로 열리며 수정해 발행
```

### 【동작 규칙】

**적용 대상**
- **본 화면은 이미 발행되어 원장에 기록된 청구 회차만 다룬다.** 반복주기·약정액 등 스케줄 수정은 PAY-3에서 수행한다

**수정 범위**

| 구분 | 항목 | 단위 |
|---|---|---|
| 수정 가능 | 납부마감일(사유 필수), 메모 | 청구서 |
| **수정 불가** | 청구년월, 청구항목, 청구액, 부가세대상여부 | — |

- 수정 불가 항목을 변경해야 하는 경우 **청구서를 무효 처리한 뒤 재발행**한다
- 납부마감일은 임차인 요청으로 연장하는 사례가 있으므로 사유를 입력받아 수정한다
- 납부액·미납액·납부상태는 수납 거래의 결과이므로 직접 수정할 수 없다. 수납 기록을 수정한다 → PAY-9

**무효 처리 — 청구서 단위**
- **발행된 청구는 삭제하지 않는다. 무효 처리만 수행한다**
- **무효 처리와 재발행은 청구서 단위로 수행한다.** 항목 1건만 취소하면 임차인이 수령한 청구서와 시스템 기록이 불일치한다
- 청구서를 무효 처리하면 포함된 **청구 건 전체에 대해 원장에 `청구 취소` 거래가 기록**된다. 원 청구 거래는 삭제하지 않는다
- 재발행 시 올바른 내용으로 청구서를 새로 발행하고 임차인에게 재발송한다
- **수납이 1건이라도 존재하는 청구서는 무효 처리할 수 없다.** 수납 기록을 먼저 취소해야 한다
- **마감된 월의 청구서는 무효 처리할 수 없다.** 정정이 필요하면 당월에 조정 거래로 처리한다 → PAY-11

**이력**
- 수정·무효 처리·재발행 시 누가·언제·무엇을·왜 처리했는지 이력을 기록한다. 사유 입력이 필수다 → 3.6
- 변경 이력은 더보기에서 조회한다

- [2차] 청구알림설정에 따른 알림톡 발송은 NTF 계열과 함께 구현한다

### 【설계 의도】

- 발행 금액을 직접 수정하면 과거 잔액이 재계산되고 이미 발행한 세금계산서와 어긋난다. 무효 처리 시 원장에 `청구 → 취소 → 재청구` 흐름이 남으며, 이는 수정세금계산서 실무와 동일한 구조다
- 화면명을 `청구 내역 수정 및 삭제`에서 변경했다. 삭제를 제거하고 무효 처리로 일원화했다

### 【연관 화면】 PAY-2, PAY-3, PAY-9, CTR-3, REC-1
### 【알림】 이메일 — 재발행 시 청구 내역서 재발송 / 내부 — 수정·무효·재발행 결과

## PAY-6 · 수납 기록 생성

**목적** 임차인에게 받은 입금을 기록하고 청구 건에 배분한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PAY-2 일괄 수납 처리 / PAY-1·PAY-2 더보기 → 수납기록생성 / CTR-3 원장정보탭 → 수납 처리

### 【입출력 항목】

```
(입금 기록)  입금 1건당 1개
계약ID, 입금일, 입금액, 결제수단, 입금자명, 거래번호, 메모,
등록방식, 등록관리자

(수납 배분)  입금 1건에 N개
청구ID, 배분액        ※ 자동 배분 후 화면에서 수정 가능

(미배분 잔액)
미배분 금액, 처리 방법(환불 / 다음 회차 배분 보류)

[은행 거래내역 업로드시]
파일, 건물 선택, 컬럼 매핑(거래일시/거래구분/입금자명/입금액), 은행 선택

[매칭 결과 확인]
입금일, 입금자명, 입금액, 매칭된 계약, 매칭 근거, 배분 미리보기,
승인 / 수동 지정

상태 정의
  결제수단   계좌이체 / 카드 / 현금 / 보증금상계 / [2차] 가상계좌
  등록방식   수동 / 은행거래내역매칭 / [2차] PG자동
```

### 【동작 규칙】

**2단 구조**
- **입금은 1건, 수납 배분은 N건이다** → 2.6
- 원장에는 배분된 항목별로 수납 거래가 각각 기록된다 → CTR-3
- 수납 배분 후 각 청구의 납부상태가 자동 갱신된다 → PAY-2

**자동 배분**
- 배분 순서와 검산 예시는 → 4.3
- 배분 결과는 화면에서 수정할 수 있다

**미배분 잔액**
- 입금액이 청구액보다 적으면 배분되지 않은 청구가 남아 부분납이 된다
- 입금액이 청구액보다 많으면 잔액을 **미배분 상태로 입금 기록에 보관**한다. 관리자가 환불 또는 다음 회차 배분 중 하나를 선택해 처리한다. **자동 처리하지 않는다** → 4.3.4

**은행 거래내역 업로드**
- 처리 절차·정규화·매칭 규칙은 → 4.6
- 업로드 시 **어느 건물의 운영계좌 내역인지 선택한다.** 건물마다 운영계좌가 다르므로 매칭 대상을 해당 건물의 계약으로 한정한다
- 컬럼 매핑은 은행별로 저장해 재사용한다
- **자동 매칭은 임차인(사업자)에 등록된 입금자명 별칭과 일치하는 경우에만 수행한다.** 별칭이 없거나 다르면 미매칭으로 남긴다
- 선택한 건물에 해당 사업자의 계약이 복수이면 자동 확정하지 않고 계약 후보를 제시한다 → 4.6.3
- 미매칭 건은 관리자가 계약을 직접 지정하며, 이때 입금자명을 해당 사업자의 별칭으로 등록할지 묻는다
- 동일 입금자명의 입금이 여러 건이면 묶어서 한 계약에 배분할 수 있다
- **매칭 결과는 관리자 승인 후에만 원장에 기록한다**

**계약 상태 연동**
- 보증금 전액이 수납으로 기록되면 `이 계약을 진행중으로 전환하시겠습니까?`를 안내한다. **자동 전환하지 않는다** → 3.2

**기록**
- 등록관리자를 함께 저장한다
- [2차] 수납 확인 알림톡 발송은 NTF 계열과 함께 검토한다. 상업용은 세금계산서가 영수 확인을 겸하므로 초기 오픈에서 수납 알림을 발송하지 않는다
- [2차] PG 연동 시 가상계좌 입금은 등록방식 `PG자동`으로 기록된다 → PAY-7

### 【설계 의도】

- 청구에 입금을 직접 연결하지 않는다. 임차인은 청구서 합계를 일괄 입금하지만 청구는 항목별 다건이므로, 청구에 직접 붙이면 실제 입금 시점과 금액이 소실된다
- 자동 매칭을 별칭 기준으로만 수행하는 이유는 은행 적요에 상호가 절단되거나 영문 약어로 표기되며, 임차인 입금이 아닌 수입이 혼재하기 때문이다
- 승인 절차를 두는 이유는 매칭 오류 시 다른 계약에 입금이 기록되고 원장은 사후 정정이 어렵기 때문이다

### 【연관 화면】 PAY-2, PAY-8, PAY-9, CTR-2, CTR-3
### 【알림】 없음 / 내부 — 수납 기록 생성 결과, 은행 거래내역 매칭 결과(자동/후보/미매칭 건수)

## PAY-8 · 수납 내역 조회

**목적** 입금 건과 각 입금의 배분 내역을 조회한다. 은행 거래내역과 대조한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 수납 관리

### 【입출력 항목】

```
필터: 건물고유이름, 유닛고유번호, 입금일자, 등록방식, 결제수단

[입금 목록]
입금일, 계약고유이름, 입금자명, 입금액,
결제수단, 등록방식, 등록관리자, 거래번호,
배분현황(전액 배분 / 일부 미배분 00원), 메모

[일자별 소계]
입금일, 입금 건수, 입금액 합계

  ▸ 행 펼침 시 [배분 내역]
    청구년월, 청구항목, 우선순위, 청구액, 배분액, 배분 후 납부상태
```

### 【동작 규칙】

- 수납 기록(수동, 은행거래내역매칭, [2차] PG자동)을 모두 조회한다
- **입금 1건과 수납 배분 N건의 2단 구조를 그대로 표시한다.** 목록에는 입금 건을 한 행씩 표시하고, 펼치면 배분 내역이 나온다
- **은행 거래내역 한 행이 목록 한 행에 대응하므로 통장과 직접 대조할 수 있다**
- **우선순위는 배분 내역에만 표시한다.** 입금 하나에 여러 청구가 배분되므로 입금 목록에는 단일 값으로 표시할 수 없다
- 배분현황은 입금액의 전액 배분 여부를 표시한다. 잔액이 있으면 `일부 미배분 00원`으로 표시한다
- 일자별 입금 건수와 합계를 표시한다. 은행 통장의 당일 입금 합계와 대조할 수 있어야 한다
- 건물마다 운영계좌가 다르므로 필터에 건물을 둔다
- **본 화면은 입금 건을 조회한다.** 회차별 미납 내역은 PAY-2에서, 계약 단위 거래 이력은 CTR-3 원장정보탭에서 확인한다

### 【설계 의도】

- 같은 돈을 네 관점으로 조회한다. 약정(PAY-1) / 회차(PAY-2) / 입금(PAY-8) / 계약 원장(CTR-3)

### 【연관 화면】 PAY-2, PAY-6, PAY-9, CTR-3
### 【알림】 없음

## PAY-9 · 수납 내역 수정 및 취소

**목적** 잘못 등록된 입금 기록을 수정·무효 처리하고 배분을 재조정한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PAY-8 더보기

### 【입출력 항목】

```
[수정]           입금일, 입금자명, 결제수단, 메모, 변경 사유
[배분 재조정]    청구ID별 배분액    ※ 입금액 총액 고정
[무효 처리]      무효 사유
[계약 재지정]    변경할 계약, 변경 사유   ※ 등록방식이 은행거래내역매칭인 경우
[변경 이력]      변경일시, 변경자, 변경 항목, 변경 전/후 값, 사유
```

### 【동작 규칙】

**무효 처리**
- **수납 기록은 완전 삭제하지 않는다. 무효 처리만 수행한다**
- 무효 처리 시 원장에 `수납 취소` 거래를 기록해 미수금을 원복한다. 원 수납 거래는 삭제하지 않는다

**수정 범위**

| 구분 | 항목 |
|---|---|
| 수정 가능 | 입금일, 입금자명, 결제수단, 메모 (사유 필수) |
| **수정 불가** | 입금액 — 무효 처리 후 재등록 |
| 수정 불가 | 등록방식, 등록관리자, 거래번호 (시스템 기록) |

**배분 재조정**
- **입금액 총액을 고정한 채 배분처만 다시 지정한다**
- 실무에서 가장 빈번한 수정이 `관리비 입금이 임대료로 배분된 경우`이며, 무효 처리 없이 해결된다
- 재조정 시 원장의 기존 수납 거래를 `수납 취소`로 되돌리고 새 배분대로 수납 거래를 다시 기록한다

**등록방식별 제한**

| 등록방식 | 수정 범위 |
|---|---|
| 수동 | 전체 |
| 은행거래내역매칭 | 수동과 동일. **계약 재지정 허용** |
| [2차] PG자동 | 메모 외 수정 불가. 무효 처리는 사유 입력 시에만. 화면에 `자동 수납건은 수정 불가` 명시 |

**무효 처리 시 연동**
- 미배분 잔액이 있으면 함께 회수한다
- 보증금 수납이었고 해당 계약이 진행중이면 `이 계약이 진행중 상태입니다. 계속하시겠습니까?` 경고를 표시한다
- 관련 청구의 납부상태와 미납액을 자동 재계산한다

**이력**
- 모든 변경 사항을 이력으로 보존한다. 누가·언제·무엇을·왜 처리했는지 기록하며 화면에서 조회한다 → 3.6

### 【설계 의도】

- 임차인이 입금을 주장하는데 데이터가 없으면 분쟁이 발생하므로 완전 삭제를 금지한다
- 입금액 수정을 막는 이유는 금액 변경 시 배분이 전부 재계산되고 원장의 수납 거래가 모두 변경되기 때문이다. PAY-5와 동일한 원칙이다
- PG 자동 건의 수정을 제한하는 이유는 외부 시스템 기록이므로 변경 시 PG 정산과 어긋나기 때문이다

### 【연관 화면】 PAY-8, PAY-2, CTR-3, REC-1
### 【알림】 없음 / 내부 — 수납 수정·무효 처리·배분 재조정 결과

## PAY-10 · 건물 관리비 정산

**목적** 건물 단위로 공과금 고지서와 유닛별 검침값을 입력해 유닛별 청구 금액을 산출한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 관리비 정산 / DASH-1 정산 미확정 카드

> **매월 수행하는 필수 업무이며 청구 발행의 선행 조건이다.** 본 화면의 산출 결과가 확정되어야 해당 월의 청구서를 발행할 수 있다.

### 【입출력 항목】

```
필터: 건물고유이름, 정산회차(년월)

───── 1단계 · 청구 항목 선택 및 고지서 입력 ─────
[목록] 청구항목, 배분 기준, 고지서 수령일, 고지서 총사용량, 공급가액, 부가세, 소계
[하단] 합계 — 소계의 총합. 입력하지 않는다
[캡션] 청구 항목은 건물 관리비 설정(PRO-3)에서 정의한 목록에서 가져온다는 안내
[항목 추가] 미선택 청구 항목 중 복수 선택
[항목 제외] 행 단위로 이번 회차에서 제외

※ 입력 필드는 항목의 성격에 따라 달라진다
   과세 항목      공급가액 + 부가세
   면세 항목      금액만. 부가세란은 잠근다
   사용량 없는 항목  총사용량란을 표시하지 않는다

───── 2단계 · 검침 입력 ─────
**계량기를 보유한 유닛이 있는 항목만 대상이다.** 계량기 보유 유닛만 목록에 표시한다

[목록] **계약고유이름**, 유닛상태, 전월 검침값, 당월 검침값, 검침 사용량(자동 산출)
       ※ 계약이 없는 유닛은 `건물별칭|유닛고유번호` 두 요소로 표기한다 → 3.1
[입력] 검침일(항목 단위), 당월 검침값(유닛별)
[미입력 표시] 계량기 보유 유닛 중 당월 검침값이 입력되지 않은 건수
[캡션] 계량기 보유 유닛 수, 계량기 없는 유닛의 잔여 사용량 배분 방식, 검침 원본 불변 원칙
       — 별도 카드로 분리하지 않는다
※ 전월 검침값은 직전 회차의 당월 검침값이며 수정할 수 없다
※ 검침 기록은 원본이며 수정하지 않는다

───── 3단계 · 조정 ─────
**계량기 보유 유닛만 표시한다**
[목록] **계약고유이름**, 검침 사용량, 조정 배수, 정산 사용량, 사유, 작성자, 작성일시
[입력] 조정 배수(0.1 단위, 기본값 1.0), 사유
※ 배수가 1.0이 아닌 경우 사유 입력이 필수다. 사유는 담당자가 직접 작성하며 자동 생성하지 않는다
※ 배수를 1.0으로 되돌리면 조정 기록이 삭제된다

───── 4단계 · 산출 결과 ─────
[목록] **계약고유이름**, 청구항목,
       검침 사용량, 잔여 배분 사용량, 정산 사용량, 배분 비율, 청구금액
[별도 행] 공실·미청구분 (건축주 부담)
[제외 유닛] 목록에 표시하되 금액란은 `제외`로 표기하고 사유를 함께 보여준다
합계 검증: 청구항목별 (임차인 청구액 합계 + 공실·미청구분 = 고지서 총금액)

───── 정산 확정 ─────
정산 확정 → 계약별 청구서 생성
```

### 【동작 규칙】

**적용 범위**
- 임대료와 고정관리비는 계약 약정액이므로 본 화면에서 다루지 않는다. **사용량에 따라 금액이 달라지는 항목만 정산한다** → 3.2-2
- **이번 회차의 청구 항목을 고르는 것이 첫 단계다.** 담당자는 정산할 항목을 정한 뒤 고지서를 입력한다
- **건물 관리비 설정(PRO-3)에 등록된 항목만 선택할 수 있다.** 목록에 없는 항목은 이 화면에서 추가할 수 없다
- 사용 중인 항목이 초기 선택으로 표시되며 회차마다 제외하거나 다시 추가한다
- **청구 항목을 하나도 선택하지 않을 수 있다.** 전기·수도를 포함한 모든 비용을 고정관리비로
  받는 운영사가 있다. 이 경우 정산 절차를 생략하고 고정액 항목만으로 청구서를 발행한다

**고지서 입력**
- **고지서 총금액은 입력하지 않는다.** 공급가액·부가세 등 구성 항목의 합계로 산출한다
- 부가세는 공급가액의 10%로 자동 계산하되 수정할 수 있다. 고지서 표기와 다를 수 있다
- 면세 항목은 부가세란을 잠근다. 과세 여부는 항목의 묶음에서 결정된다 → 3.3
- **고지서 수령일을 입력한다**
- **고지서 한 건에서 청구 항목이 복수로 도출될 수 있다.**
  한국전력 고지서에는 전기요금·부가세·전력산업기반기금·TV수신료가 함께 표기되나,
  전력기금과 TV수신료는 묶음이 `기타-일반내역서`인 독립 청구 항목이다.
  각각을 별도 청구 항목으로 선택해 입력한다 → 3.3, 4.1.2

**설정의 소재**
- **본 화면에서는 배분 설정을 변경하지 않는다.** 매월 반복하는 작업이므로 회차마다
  설정을 확인하게 하지 않는다
- 항목 자체의 정의(이름·묶음·산정방식·부가세·우선순위)는 PAY-4에서 관리한다
- 건물별 배분 설정(검침분 청구여부·잔여분 부담대상·배분 기준·참조 항목·안분 제외 유닛)의
  **정본은 PRO-3 관리비 설정탭**이다
- 건물에 설정이 없는 항목은 **임대면적 비율을 기본값으로 적용**하고 화면에 표시한다.
  변경하려면 PRO-3으로 이동한다

**산정**
- 산정 규칙·건물별 설정·검산 예시는 **→ 4.1**

**검침 대상**
- **계량기 유무는 유닛 × 청구항목 단위로 판정한다** → 6부 유닛 검침 설정
  동일 항목이라도 유닛마다 계량기 보유 여부가 다르다
- **계량기 보유는 등록된 설정으로 판정한다.** 검침값의 존재 여부로 판단하지 않는다.
  계량기가 있으나 당월 검침값이 아직 입력되지 않은 상태를 구분할 수 있어야 한다
- **왜 이 유닛만 검침 대상인지 화면에서 확인할 수 있어야 한다.**
  다만 설정값을 카드로 재현하지 않고 **캡션으로 간략히 안내한다.**
  설정 자체는 PRO-3 관리비 설정탭이 정본이며 본 화면에서 변경하지 않는다
- **계량기를 보유한 유닛이 하나라도 있는 항목만 검침 단계에 표시한다.**
  목록에는 계량기 보유 유닛만 나열하며 나머지는 참고 정보로 표시한다
- 배분 기준이 `검침 사용량`이더라도 자체 계량기가 없는 항목(전력기금·TV수신료)은
  참조 항목의 검침값을 사용하므로 검침하지 않는다 → 4.1.3
- 검침 대상 항목이 하나도 없으면 2단계를 건너뛴다

> **일부 유닛만 계량기를 보유한 경우** — 1층 상가에만 수도 계량기가 있는 건물이 해당한다.
> 해당 유닛은 검침 사용량만큼 청구받고, `잔여분 부담대상`을 `검침기 없는 유닛만`으로 두면
> 잔여 배분에서 제외된다. 산정 예시는 → 4.1.6

**검침과 조정**
- **조정 대상은 계량기 보유 유닛이다.** 계량기가 없는 유닛은 조정 목록에 표시하지 않는다.
  계량기를 추가하려면 건물 관리비 설정(PRO-3)에서 지정한다
- **검침 기록은 원본이며 수정하지 않는다.** 보정이 필요하면 조정 배수를 별도 기록으로 남기고 사유와 작성자를 함께 저장한다
- 조정은 해제할 수 있으며 회차별로 이력이 축적된다
- 조정 배수의 기본값은 유닛에 설정된 기본 조정 배수다 → PRO-4. 해당 회차에만 다르게 적용할 수 있다

**안분 제외**
- 임차인이 공급자와 직접 계약한 유닛은 해당 항목의 안분에서 제외한다 → 4.1.7-2
- 제외 유닛은 배분 모수에서 빠지며 청구 건을 생성하지 않는다. 공실·미청구분에도 포함하지 않는다
- **산출 결과 목록에서 행을 감추지 않는다.** 제외 표시와 사유를 함께 노출해
  누락과 의도적 제외를 구분할 수 있게 한다
- 제외 대상은 건물 관리비 설정(PRO-3)에서 항목별로 지정한다

**공실 처리**
- 공실 유닛도 공용분 안분 대상에 포함하되 청구서를 생성하지 않는다 → 4.1.7
- 공실 유닛은 별도 규칙 없이 가중치대로 참여한다. 배분 기준이 사용량이면 공실 몫은 0에 가깝고, 면적이면 공실 면적만큼 발생한다. 기준은 건물·항목별 설정을 따른다 → PRO-3
- 산출 결과에 **`공실·미청구분`을 별도 행으로 표시**해 건축주 부담액을 확인할 수 있게 한다

**부분 기간**
- 임차인이 산정 기간 중 일부만 사용한 경우(입주·퇴거) 담당자가 해당 유닛의 금액을 직접 계산해 덮어쓰고 사유를 남긴다. **시스템은 검침과 안분까지만 처리하며 일할 계산은 하지 않는다** → 4.1.9

**확정**
- 정산 확정 전까지 고지서 금액이나 검침값을 수정하면 전체가 재계산된다
- 확정 시 청구항목별로 **(임차인 청구액 합계 + 공실·미청구분 = 고지서 총금액)** 을 검증한다. 불일치 시 확정할 수 없다 → 4.1.8
- 확정 시 계약별로 청구 회차가 생성되며 원장에 `청구` 거래로 기록된다 → PAY-3

**주기**
- 정산 주기는 항목마다 다르다 (예: 전기요금 매월 / 상하수도요금 격월 / 교통유발부담금 연1회 / 정화조청소비 반기)
- 격월 또는 연 1~2회 발생 항목은 청구 주기를 사전 고정하지 않고 **해당 회차에서 항목을 추가해 정산한다**

**주차요금**
- 방문 차량 요금은 경비원이 현장에서 계산한 결과를 유닛별 월 합계 금액으로 입력한다
- [2차] 입·출차 시간 기록과 시간제 자동 계산은 주차 관제 연동 시 검토한다

**범위 밖**
- [2차] 세금계산서·계산서 발행과 은행 입금 자동 확인은 초기 오픈 범위에서 제외한다. 청구 내역서를 임차인 담당자 이메일로 발송하는 것까지가 초기 오픈 범위다

### 【설계 의도】

- 본 업무는 단일 계약 정보만으로 금액 산출이 불가능하다. 동일 건물 내 타 유닛의 면적과 검침값이 필요하다
- **입력 중 화면 위치가 유지되어야 한다.** 검침값·배수·사유는 유닛 수만큼 연속 입력하므로
  한 칸을 채울 때마다 화면이 이동하면 작업이 불가능하다
- 검침 원본을 보존하는 이유는 금액 산출 근거의 추적과 조정 해제를 가능하게 하기 위함이다
- 정산 미확정은 해당 월 청구서 미발행으로 이어지므로 대시보드 최상단에 표시한다 → DASH-1

### 【연관 화면】 PRO-3, PRO-4, PAY-3, CTR-3, DASH-1, REC-1
### 【알림】 없음 / 내부 — 정산 확정 결과, 검증 불일치 경고

## PAY-11 · 월 마감

**목적** 건물 × 월 단위로 장부를 마감해 이후 거래 변경을 차단한다.
**사용자** 슈퍼관리자
**진입 경로** 메인 메뉴 → 월 마감 / DASH-1 마감 대기 카드

> 원장을 기록 중심으로 운용하면 취소 거래를 되돌릴 수 없다. 과거 회차를 수정하면 이미
> 산출한 임대인 보고서와 어긋나므로, 월 단위로 장부를 잠근다.

### 【입출력 항목】

```
필터: 건물고유이름, 년월, 마감상태(열림 / 마감)

[목록]
건물고유이름, 년월, 마감상태, 마감일시, 마감자,
청구 건수, 청구액 합계, 수납액 합계, 미납액 합계,
더보기(마감, 마감 취소, 이력 보기)

[마감 전 확인 항목]  ※ 미해결 항목이 있으면 경고를 표시
 · 정산이 확정되지 않은 회차
 · 계약이 지정되지 않은 입금
 · 미배분 잔액이 남은 입금

[마감 실행시]   확인 문구
[마감 취소시]   취소 사유    ※ 필수
```

### 【동작 규칙】

**마감 단위**
- **건물 × 월 단위로 마감한다.** 건물마다 임대인과 운영계좌가 다르므로 건물 단위가 기준이다
- 마감 시 해당 건물의 그 월 원장 거래가 잠긴다

**마감 효과**

| 마감 후 차단되는 행위 | 대응 화면 |
|---|---|
| 해당 월 청구의 무효 처리·재발행 | PAY-5 |
| 해당 월 수납의 무효 처리·배분 재조정 | PAY-9 |
| 해당 월 정산 내용 수정 | PAY-10 |
| 해당 월 원장 거래 추가 | CTR-3 |

- 마감 후 정정이 필요하면 **당월에 조정 거래로 처리한다.** 과거 월을 소급 수정하지 않는다

**마감 전 확인**
- 미해결 항목이 있으면 경고를 표시한다. 강제로 차단하지는 않으며 관리자가 판단한다
- 정산 미확정 회차가 있으면 해당 월 청구서가 발행되지 않은 상태이므로 특히 주의한다

**마감 취소**
- **슈퍼관리자만 수행하며 사유 입력이 필수다**
- 마감·마감 취소 모두 이력에 기록한다 → 3.6

**권장 순서**
```
정산 확정(PAY-10) → 청구 발행 → 수납 기록 → 미납 확인(PAY-2)
→ 임대인 보고서 발송(REP-1) → 월 마감(PAY-11)
```

### 【설계 의도】

- 취소 거래는 삭제할 수 없으므로 잘못된 취소가 누적되면 원장 가독성이 떨어진다. 마감으로 정정 가능 기간을 제한한다
- 임대인 보고서를 발송한 뒤 과거 수치가 변경되면 신뢰 문제가 발생한다

### 【연관 화면】 PAY-2, PAY-5, PAY-9, PAY-10, REP-1, DASH-1
### 【알림】 없음 / 내부 — 마감 결과, 마감 취소 발생
