## PAY-12 · 청구·수납 현황

**목적** 건물별로 이번 회차의 청구·수납 업무가 어디까지 진행되었는지 조회한다.

> 계약 단위 미납은 PAY-2에서 본다. 본 화면은 **건물 단위 진행 상태**를 다룬다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 청구·수납 그룹 클릭

> **사이드바 하위 메뉴에 별도 항목을 두지 않는다.** 그룹 진입 시 표시되는 화면이므로
> 하위 목록에 중복으로 노출할 필요가 없다.

### 【입출력 항목】

```
필터: 정산회차(년월)

(요약)
청구 금액, 수납 금액, 미납 금액, 수납률, 정산 미확정 건물 수

(건물별 진행)
[목록] 건물고유이름, 건물구분, 유닛 수,
       정산 상태(미착수 / 작성중 / 확정 / 해당 없음),
       청구서(발행 건수 / 대상 건수),
       청구 금액,
       수납(수납 완료 건수 / 발행 건수, 진행률),
       미납 금액,
       마감 여부
[합계] 전 건물 합산
```

### 【동작 규칙】

- **담당 건물만 표시한다.** 관리자는 배정된 건물, 슈퍼관리자는 운영사 전체 → 3.7
- 각 칸을 클릭하면 해당 업무 화면으로 이동하며 **해당 건물과 회차가 선택된 상태**로 진입한다

| 칸 | 이동 |
|---|---|
| 정산 상태 | PAY-10 관리비 정산 |
| 청구서 | PAY-1 청구서 발행 |
| 수납 | PAY-6 수납 내역 |
| 미납 금액 | PAY-2 미납 관리 |
| 마감 | PAY-11 월 마감 |

- 정산 상태가 `확정`이 아니면 청구서를 발행할 수 없다. 해당 건물의 청구서 칸은 `미발행`으로 표시한다
- **`해당 없음`은 이번 회차에 정산할 항목이 하나도 없는 건물이다.** 고정액 항목만으로
  청구서를 발행하므로 발행 제한을 적용하지 않는다 → PAY-10
- 수납 진행률은 **건수 기준**이다. 금액 기준 수납률은 요약에 별도로 표시한다
- **마감 열은 `월 마감` 여부다. 완납 여부가 아니다.** 상태는 `열림` / `마감`으로 표기하고
  마감된 건물은 마감일을 함께 보여준다
- **미납이 남아 있어도 마감한다.** 미납액은 채권으로 이월되며 마감 여부와 무관하다 → PAY-11
- 마감된 건물은 해당 회차의 거래를 변경할 수 없다 → PAY-11

### 【설계 의도】

- 대시보드(DASH-1)가 **처리가 필요한 예외**를 모으는 화면인 반면,
  본 화면은 **전 건물의 진행 상태 전부**를 보여준다. 월중에 업무 진척을 확인하는 용도다
- 건물 수가 늘어날수록 "어느 건물이 어디까지 됐는지"를 화면을 옮겨 다니며 확인하는 비용이 커진다
- 청구·수납 영역은 화면이 10개로 가장 많다. 그룹 진입 시 첫 화면을 두어
  어느 화면으로 갈지 판단할 근거를 제공한다

### 【연관 화면】 PAY-1, PAY-2, PAY-10, PAY-11, DASH-1
### 【알림】 없음

## PAY-1 · 청구서 발행

**목적** 이번 회차에 발행할 청구서를 계약별로 확인하고 발행·발송한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 청구 · 수납 → 청구서 발행

### 【입출력 항목】

```
필터: 건물(단일 선택), 청구년월, 발행상태(전체 / 발행 대기 / 발행 완료)

[목록] 계약별 그룹. 접고 펼칠 수 있으며 기본은 접힘
  그룹 행   선택 체크박스, 계약고유이름, 청구 건수, 미산출 수,
            미납 잔액, 공급가액 합계, 부가세 합계, 청구 합계, 발행상태
  항목 행   청구항목, 발행 문서, 근거 문서, 공급가액, 부가세, 합계, 상태

  ※ 그룹 행과 항목 행이 같은 열을 다르게 쓴다. 머리글에 둘을 함께 적는다
     2열  발행 문서         (그룹 행은 비움)
     3열  미납 잔액 · 근거 문서

  ※ **모든 행은 한 줄이다. 줄바꿈으로 보조 정보를 덧붙이지 않는다.**
     계약고유이름에 건물명이 이미 들어 있으므로 건물명을 따로 적지 않는다 → 3.2-2
     `청구 N건`·`미산출 N`은 계약고유이름 **오른쪽**에, `VAT 포함`은 청구 합계
     **왼쪽**에 옅은 글씨로 붙인다. 금액의 오른쪽 정렬이 깨지지 않게 하려는 것이다
     발행 문서의 과세 구분도 같은 줄에 옅은 글씨로 붙인다 → `세금계산서 과세`

[상단] 미납 조회 · 미리보기 · 선택 발행 / 전체 발행
[하단] 합계 — 대상 계약 수, 청구 합계
```

### 【동작 규칙】

**지난 회차**
- 청구년월 필터로 지난 달(최근 3개월)을 고르면 **이번 달과 같은 표**로 그 달에 발행한 청구서를 본다.
  금액은 그 달의 정산 결과에서 나온다. 모두 `발행 완료`이므로 선택 체크박스와 발행 버튼이 눌리지 않는다
- **마감한 달은 잠겼음을 화면 안에 알린다**(`마감된 회차입니다 — 고치려면 월 마감에서 마감 취소`, 월 마감 링크) → PAY-11
- 마감이 풀린 달이라도 여기서 고치지 않는다. 발행한 청구서의 수정·취소는 PAY-5에서 한다

**청구서 조립**
- **청구서는 계약 × 청구년월 단위로 1장이다.** 고정액 항목과 정산 항목을 함께 담는다 → 2부
- **발송하는 청구서 PDF는 합칠 수 있다.** 임차인에 `청구서 합쳐 보내기`가 설정되어 있으면 같은 건물의
  그 임차인 계약들을 PDF 한 장에 계약별 구획으로 담아 한 번에 발송한다 → USER-7
  시스템 안의 청구와 원장은 **계약별 그대로**다. 합치는 것은 임차인이 받는 문서뿐이다
  예: (주)아이씨비 본관7층·본관8층 — 계약 2건, 청구 2건, 발송 PDF 1장
- 금액의 출처가 둘이다

| 산정방식 | 금액 출처 | 근거 문서 |
|---|---|---|
| 고정액 | 계약에 등록된 청구 약정의 약정액 → PAY-3 · CTR-3 | 임대차계약서 |
| 정산 | 관리비 정산 확정 결과 → PAY-10 | PRO-3에서 항목별로 지정한 문서 → 4.1.3 |

- **`근거` 열에는 금액을 뒷받침하는 문서를 표시한다.** 정산 회차는 근거 열에 적지 않는다.
  청구년월 필터가 이미 회차를 정한다
- **대납 항목은 출처 유닛을 항목명 오른쪽, 같은 줄에 표시한다** → 4.1.7-3
- **대납 금액이 0원인 항목은 싣지 않는다.** 계량기 공유로 기준값이 0인 유닛 등에서 생긴다 → 4.1.3-4

```
전기요금                            한국전력 고지서    641,693   64,169   705,862  정산 미확정
전기요금  본관301호|고우컴퍼니 대납   한국전력 고지서    136,142   13,614   149,756  정산 미확정
```

- **대납 표시는 항목 행에만 둔다.** 그룹 행에는 적지 않는다. 대납은 항목 단위로 일어나며
  그룹 행에 계약 단위 문장을 덧붙이면 계약마다 행 모양이 달라진다

**항목 상태 — 3종**

| 상태 | 뜻 |
|---|---|
| **약정** | 계약에 등록된 약정액. 계약서 값이므로 회차와 무관하게 변하지 않는다 |
| **정산 미확정** | 관리비 정산이 확정되지 않았다. 확정 시 금액이 바뀔 수 있다 |
| **정산 확정** | 관리비 정산이 확정되어 금액이 고정되었다 |

- **고정액 항목은 언제나 `약정`이다.** 정산과 무관하므로 고정액만 있는 건물의 청구서는
  정산 없이 바로 발행할 수 있다
- 정산 항목의 상태는 **해당 건물·회차의 정산 상태를 그대로 따른다**
- **미납 잔액은 칩이 아니라 평문으로 적고 경고색만 준다.** 이번 회차 청구가 아니므로
  청구 금액들과 같은 형태로 두되 색으로만 구분한다 → PAY-2
- **`미산출`은 상태가 아니라 금액 칸의 표시다.** 이번 회차 대상인데 금액이 없다는 뜻이며,
  상태 열에 섞지 않는다. 상태와 금액 유무는 서로 다른 축이다
- **청구서에 싣는 항목은 한 가지 기준으로 정한다.**

  | 항목 | 싣는 조건 |
  |---|---|
  | 고정액(임대료·고정관리비) | 약정 금액이 0원이 아니고, 반복주기·기산일상 이번 회차 대상 → PAY-3 |
  | 정산 항목(전기·수도 등) | 건물 관리비 탭에서 `사용` 중이고, 이번 회차 정산 금액이 0원이 아님 |

  약정 금액 0원은 `청구하지 않음`이라는 뜻이다. 입력 누락으로 보지 않으며 청구서에 올리지 않는다.

```
임대료      약정   임대차계약서           4,280,000원
전기요금     정산   한국전력 고지서           235,387원   2026-09 정산
수도요금     정산   상수도사업본부 고지서      213,839원   2026-09 정산
주차비      정산   경비실 내역서            100,000원   2026-09 정산
```

- 정산 항목의 근거 문서는 **건물 관리비 탭(PRO-3)**에서 항목별로 지정한다 → 4.1.3
- 고정액 항목의 근거는 계약서다
- **임차인이 산출 근거를 물으면 이 문서를 보여준다.** 근거를 지정하지 않은 항목은
  설명할 수단이 없으므로 설정에서 필수로 받는다

- **공급가액·부가세·합계를 모두 표시한다.** 합계는 **부가세 포함**이며 임차인이 실제로
  납부하는 금액이다
- **부가세는 발행 문서가 `세금계산서`인 항목에만 붙는다** → 3.3
  계산서(면세)·일반내역서(비과세)는 부가세란을 `—`로 둔다
- 항목마다 과세 구분이 다르므로 **한 계약의 청구서 안에 과세·면세·비과세가 섞인다.**
  합계는 셋을 모두 더한 값이다

> **⚠️ 화면에서 `부가세 별도`와 `부가세 포함`을 섞지 않는다.**
> 약정액과 정산 항목 모두 부가세 포함 금액에서 출발하지만, 과세·면세·비과세가 섞이므로
> 공급가액과 부가세를 분리해 표시하고 합계를 따로 둔다 → 3.4

**이번 회차 대상 항목만 올린다**

청구서에 올라오는 항목은 이번 회차 대상뿐이다. 대상 여부는 산정방식에 따라 다르게 정한다.

| 산정방식 | 대상 판정 | 근거 |
|---|---|---|
| 고정액 | 청구 약정의 **반복주기·기산일**로 자동 판정 | 금액이 약정에 있으므로 시스템이 판단할 수 있다 |
| 정산 | **PAY-10 항목 탭에 올라온 항목**(매월 항목은 자동, 가끔 오는 항목은 담당자가 추가) | 고지서 수령 여부를 시스템이 알 수 없다 |

- **대상이 아닌 항목은 화면에 올리지 않는다.** 격월·반기·연1회 항목의 비대상 회차는
  PAY-10 항목 선택에서 이미 제외되었다
- 「이번 달엔 수도요금이 없다」를 확인하는 자리는 **PAY-10 항목 탭**이다.
  발행 화면에서 다시 보여주면 중복이며, **실제 청구서에 없는 줄을 보여주게 되어**
  미리보기·발행물과 어긋난다

```
PRO-3 관리비 탭    이 건물이 쓰는 청구항목을 정의한다
      ↓
PAY-10 항목 탭       매월 항목은 자동으로 올라오고, 가끔 오는 고지서만 추가한다
      ↓
PAY-1 청구서 발행    선택된 정산 항목 + 이번 회차 대상 고정액만 올라온다
```

**상태 — 두 층위를 섞지 않는다**

청구서(계약) 상태는 **배타적인 둘**이다.

| 상태 | 뜻 |
|---|---|
| 발행 대기 | 아직 발행하지 않았다 |
| 발행 완료 | 발행·발송되어 원장에 기록되었다 |

항목 상태는 위의 3종(`약정` / `정산 미확정` / `정산 확정`)이며 청구서 상태와 섞지 않는다.

**미산출 — 상태가 아니라 경고다**

```
미산출 = 이번 회차 대상인데 금액이 없는 항목
사유   고지서 금액 미입력 · 산출 결과 없음
```

- 그룹 행에 `미산출 N`을 **경고색으로** 표시하고, 해당 항목 행의 비고를 강조한다
- **그대로 발행하면 그 항목이 빠진 청구서가 나간다.** 발행을 막지는 않는다.
  고지서가 늦게 도착해 다음 회차에 합산하는 경우가 있기 때문이다
- 그룹 행의 `미납 잔액`에는 금액만 표시한다. 시작 회차·건수는 미납 관리에서 본다 → PAY-2

**미납 잔액 — 확인만 하고 합계에 넣지 않는다**

```
[목록] 그룹 행에 계약별 미납 잔액을 금액만 표시한다
[상단] 미납이 있는 계약 수와 합계를 배너로 표시하고 미납 관리로 가는 링크를 둔다
[합계] 미납 합계를 청구 합계와 나란히, 그러나 더하지 않는다
```

| | 이번 회차 청구 | 미납 잔액 |
|---|---|---|
| 출처 | 약정 + 정산 확정 결과 | **원장** (청구액 − 수납액) |
| 청구 합계 | 포함 | **포함하지 않는다** |
| 청구 안내서 | 항목별 내역 | **별도 안내로 표기.** 내역이 다르다 |
| 세금계산서·계산서 | 포함 | **넣지 않는다.** 전월분은 이미 발행되었다. 이중 발행이 된다 |

> **설계 의도 — 미납을 「확정」하는 단계를 두지 않는다.**
> 미납액은 `청구액 − 수납액`으로 원장에서 계산되는 값이다(→ PAY-2). 확정 시점을 두면
> 확정 후 들어온 입금과 어긋나고, 어느 쪽이 맞는지 판단할 근거가 없어진다.
> 발행 화면에서는 **발행 시점의 잔액을 보여주기만 한다.**
> 발행 후 들어온 입금은 다음 회차 청구서에 반영된다.

> **⚠️ 세금계산서에 미납액을 넣지 않는다.**
> 세금계산서·계산서는 **그 달 공급분에 대한 증빙**이다. 전월 미납은 이미 전월에
> 발행되었으므로 다시 넣으면 이중 발행이다.
> 따라서 **임차인에게 보내는 청구 안내서와 세금계산서의 금액이 다를 수 있다.**

**발행 조건**
- **해당 건물·회차의 정산이 `확정`이 아니면 발행 버튼을 잠근다.** 상단에 사유와
  관리비 정산으로 가는 링크를 배너로 표시한다
- 고정액 항목만 있는 건물은 정산 없이 발행할 수 있다. 이 경우 정산 확정 조건을 적용하지 않는다
- **아직 수납 기록되지 않은 은행 입금이 있으면 미납 안내 배너에 그 건수를 함께 표시한다.**
  기록 전에 발행하면 이미 낸 임차인도 미납으로 안내되기 때문이다. 발행을 막지는 않는다 → PAY-13
- 발행하면 계약별로 청구 회차가 생성되어 **원장에 `청구` 거래로 기록**되고,
  임차인 담당자 이메일로 청구서가 발송된다 → 7.11.3
- 발행 후에는 이 화면에서 수정할 수 없다. 정정은 PAY-5에서 처리한다

**선택 발행**
- 그룹 행의 체크박스로 계약을 선택한다. 선택이 없으면 `전체 N건 발행`으로 동작한다
- `발행 완료`인 계약은 선택할 수 없다

### 【설계 의도】

- **화면의 성격을 바꿨다.** 본래 `청구 약정 조회`였으나 조회 전용이라 실제로 할 일이 없었다.
  약정의 등록·수정은 계약 상세(CTR-3)에서 하고, 조회도 거기서 된다
- 반대로 **월 업무 주기 ④단계(청구서 발송)에 대응하는 화면이 없었다.** 정산 확정(PAY-10)으로
  정산 항목의 금액이 고정되고 고정액 항목은 약정대로 정해지는데, **그 결과를 모아 확인하고
  발행하는 화면이 비어 있었다.** 이 화면이 그 자리를 채운다. 청구 건 생성과 원장 기록은 발행 시점이다
- 약정 정보가 사라지지 않는다. 각 항목 행의 `산정방식`과 `근거`가 그 항목이 약정에서 온 것인지
  정산에서 온 것인지 보여주므로, 회차 맥락 안에서 약정을 확인할 수 있다
- 계약별 그룹을 접고 펴는 구조는 **표(`<table>`)로 구현하지 않는다.** 그룹 행과 항목 행이
  같은 열을 다르게 쓰므로 표로 만들면 열 정렬과 클릭 영역이 깨진다. 그리드로 구현한다

## PAY-2 · 미납 관리

**목적** **미납이 있는 계약만 따로 모아 관리한다.** 계약별로 지금까지 쌓인 미납액 전부를 보고,
찾아와서 낸 돈을 바로 수납 처리하거나 미납 안내 메일을 보낸다.
관리자가 가장 자주 여는 청구·수납 화면이다.
한 달의 계약별 수납 확인은 수납 내역(PAY-6)에서 한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 미납 관리 / DASH-1 미납 카드 / PAY-1 미납 안내 / PAY-12 미납 금액 칸

```
필터: 건물(단일 선택), 계약상태(전체 / 진행중 / 종료됨·파기됨), 보기(미납 있는 계약 / 전체 계약)

[상단] 미납 안내 메일(선택 N)

### 【동작 규칙】

**범위**
- **청구년월을 고르지 않는다. 미납액이 남은 청구를 달에 상관없이 모두 올린다.** 이 화면의 존재 이유다
- 계약상태 기본값은 `전체`다. **종료·파기된 계약의 미납도 채권이다.** 퇴거 후 남은 미납을 놓치지 않는다
- 기본 보기는 **미납이 있는 계약**을 올린다. 이 화면의 대상은 미납이 있는 임차인이다
- **연체료도 미납이다.** 계약서에 정한 돈이기 때문이다. 청구액을 다 냈어도 늦게 내서 연체료가 남았으면 올린다.
  계약고유이름 옆에 `연체료 미납 · 26.06월분 31일 늦게 완납`처럼 **어느 달을 며칠 늦게 냈는지** 표시한다
- 연체료는 이 화면의 수납 처리에서 받거나 감면해 정리한다 → 4.4.3
- `전체 계약`을 고르면 미납액과 연체료가 모두 0인 계약도 올린다. 계약고유이름 옆에 `미납 없음`으로 표시한다
- 정렬 기본값은 미납액 큰 순이다

**상태와 집계**
- 미납액 = 청구액 − 수납액 → 3.2
- 월 행의 납부상태는 부분납 · 납부전 · 미납 중 하나다. **수납이 0이고 납부마감일이 지났으면 `미납`**
- 연체일수 = 오늘 − 납부마감일. 월마다 다르다. 계약 행에는 가장 긴 연체일수를 표시한다
- **입금은 오래된 달부터 채운다** → 4.3. 따라서 미납액은 보통 최근 달에 남는다.
  여러 달에 걸쳐 남아 있다면 그 사이 입금이 한 달 치에도 못 미쳤다는 뜻이다
- **납부상태는 직접 수정할 수 없다.** 수납 거래를 기록하면 상태가 따라온다

**금액 표시**
- **부가세를 포함한 합계 기준으로 표시한다** → 3.4

**연체료**
- 산출식과 예시는 → 4.4. 월 행에 달별 연체료를, 계약 행에 그 합을 보인다. 계산 과정은 화면에 펼치지 않는다
- 연체이자율은 계약마다 다르다(CTR-2). 별도 칸으로 표시한다
- **자동으로 청구하지 않는다.** 수납 처리에서 받기로 한 금액만 원장에 청구로 올라간다 → 4.4.3
- 처리는 다섯 가지다: 이번엔 안 함 · 전액 받기 · 50% 감면 · 직접 입력 · 전액 감면. 줄여 준 차액은 감면이며, 그날까지의 연체료는 다시 세지 않는다
- 연체료만 남은 계약은 `수납`을 누르면 `전액 받기`가 기본으로 선택된다

**수납 처리** — 현금·카드처럼 은행 거래내역에 없는 돈은 여기서 바로 기록한다
- 임차인이 밀린 돈을 들고 찾아오면 그 계약 행의 `수납`을 눌러 기록한다. **입금 매칭(PAY-13)은 은행 거래내역을 한꺼번에 처리할 때만 쓴다**
- 배분 규칙은 입금 매칭과 같다. **오래된 달부터, 같은 달 안에서는 배분 우선순위대로** 채운다 → 4.3
- 현금·카드·계좌이체는 **같은 임차인의 이 건물 계약 전체**에 배분한다. 보증금상계는 **그 보증금이 걸린 이 계약에만** 배분한다
- **미납보다 많이 받으면 확정할 수 없다.** 금액을 미납액에 맞춘다. 남는 돈을 받아 두는 일(선수금)은 이 화면에서 하지 않는다
- 보증금상계는 보증금 잔액까지만 가능하다. 확정하면 원장에 `보증금 차감`(임대보증금 차변)과 `수납`(매출채권 대변)이 함께 기록된다 → 2.7
- 확정하면 원장에 수납으로 기록되고(내용: `08.10 현금 수납`), 미납액·납부상태가 바로 바뀐다
- 등록방식은 `수동`이다. 결제수단·메모·등록 관리자를 함께 기록한다. 카드는 승인번호, 현금은 영수증 번호를 메모에 남기도록 안내한다
- 잘못 기록했으면 PAY-9에서 무효 처리 후 다시 기록한다
- 같은 패널을 계약 상세(CTR-3)의 `수납 처리` 버튼으로도 연다

**근거 자료**
- 임차인이 미납·연체료의 근거를 요구하면 **계약 원장**(CTR-3 원장 탭)을 출력해 준다.
  언제 무엇을 청구했고 언제 얼마가 들어와 어디에 채워졌는지가 한 장에 나온다. 별도의 연체료 내역서를 두지 않는다

**발송**
- `미납 안내 메일`은 선택한 계약의 미납 내역(월별 미납액·연체일수·연체료(예상))을 담은 메일을 임차인 담당자에게 발송한다.
  **매달 보내는 것이 실무다.** "현재 미납 금액은 ○○원입니다"를 알리는 것이 목적이다
- [2차] `알림톡 일괄전송`은 NTF 계열과 함께 구현한다

### 【설계 의도】

- `완납 처리` 버튼을 두지 않는다. 상태만 변경하면 장부에 없는 돈이 발생한다
- 한 푼도 받지 못한 청구만 납부마감일로 `납부전`/`미납`을 나눈다. 부분납은 마감 후에도 부분납이며
  기한 경과는 연체일수 칸이 보여준다 → 3.2
- 청구년월로 자르지 않는다. 밀린 돈은 여러 달에 걸쳐 있으며, 달별로 나눠 보면 한 임차인의 총 채권을 알 수 없다
- 수납 처리를 이 화면에 둔다. 관리자가 가장 자주 여는 화면이고, 현금·카드로 밀린 돈을 들고 오는 임차인이 있기 때문이다.
  은행 입금은 입금 매칭(PAY-13)에서 한꺼번에 처리한다
- 연체료를 받을지와 금액을 수납 순간에 정한다. 연체료를 실제로 받는 경우는 드물고, 받더라도 퇴거를 앞둔 임차인이
  보증금을 더 돌려받으려 감면을 요청하는 등 협의 끝에 금액이 정해지기 때문이다

### 【연관 화면】 PAY-1, PAY-6, PAY-13, CTR-3, DASH-1
### 【알림】 이메일 — 미납 안내 일괄 발송 / [2차] 알림톡 — 동일

## PAY-3 · 청구 약정 등록

**목적** 계약의 임대료·고정관리비 약정을 고친다. 임대료 인상 일정을 넣는다. 정산액 대납 계약을 정한다.
**사용자** 슈퍼관리자(금액 수정 · 인상 예약), 관리자(정산액 대납 계약)
**진입 경로** 계약 상세(CTR-3) › 임대료·관리비 탭 → `수정` · `+ 일정 추가` · `정산액 대납 계약 변경`
**화면 형태** **별도 화면이 아니라 임대료·관리비 탭 오른쪽에 열리는 패널이다.** 목록은 CTR-3 임대료·관리비 탭에 있다

> 임대료·고정관리비, 렌트프리·기산일, 임대료 인상 예약은 **계약 등록(CTR-2)에서 처음 입력한다.**
> 이 패널은 계약이 시작된 뒤에 그 값을 고치는 곳이다.
> **정산 항목(전기·수도 등)은 계약에 두지 않는다.** 모든 계약이 건물 관리비 탭(PRO-3)의 설정을 그대로 받는다.
> 청구항목을 새로 만들거나 쓰지 않게 하는 곳은 건물 관리비 탭뿐이다 → 3.3

### 【입출력 항목】

```
[수정]   임대료 · 고정관리비 각각. ※ 슈퍼관리자만 연다(관리자에게는 수정 버튼이 없다) → 3.7
  금액(부가세 포함, 옆에 읽기 쉬운 금액), 사유(금액을 바꿨을 때만 필수. 0원이던 금액을 처음 넣을 때는 묻지 않는다)
  반복주기, 기산일, 메모
  ※ **금액 0원 = 청구하지 않음.** 켜고 끄는 스위치를 따로 두지 않는다. 다시 받게 되면 금액을 넣는다

[임대료 인상 예약 추가·수정]   탭의 `+ 일정 추가` · 행의 `수정`. 저장하면 패널을 닫는다. 슈퍼관리자만 → 3.7
  적용일, 임대료(부가세 포함), 고정관리비(부가세 포함), 메모   ※ 비워 둔 항목은 그대로
  삭제는 행의 `삭제`. 적용완료된 일정은 고치거나 지우지 않는다

[정산액 대납 계약]   탭의 `정산액 대납 계약` 카드 `변경` 버튼
  대신 낼 계약(같은 건물의 진행중·준비중, 기본 없음) → 4.1.7-3

반복주기: 매월 / 격월 / 분기 / 반기 / 연1회   ※ `이번만`은 두지 않는다 → PAY-10 일회성 청구
```

### 【동작 규칙】

**등록과 발행의 구분**
- **약정 등록은 계약상태가 준비중일 때도 가능하다**
- **실제 청구 회차는 계약이 진행중이 된 뒤부터 생성된다.** 보증금 입금 전에 청구서가 발행되지 않도록 한다

**회차 생성**
- **청구 회차는 청구서 발행(PAY-1) 시점에 생성된다.** 별도의 백그라운드 생성 작업을 두지 않는다
- 고정액 항목은 약정의 반복주기·기산일로 이번 회차 대상인지 판정해 PAY-1에 올린다
- 정산 항목은 PAY-10 정산 확정 결과를 PAY-1에 올린다
- **두 항목은 같은 청구년월로 묶여 계약당 청구서 1장이 된다**
- 약정 금액이 0원인 고정액은 PAY-1에 올라오지 않는다

**청구서 발행 단위**
- 회차(청구년월)마다 **계약당 청구서 1장**을 발행하며 그 안에 항목별 명세를 담는다
- **청구서는 독립된 개체이며 발행일·납부마감일·합계·발송 상태를 보유한다** → 2.5
- 원장에는 청구 건(항목) 단위로 청구 거래가 각각 기록된다 → CTR-3

**청구일·납부마감일**
- 건물에 기본값을 두고 계약에서 덮어쓴다. **계약 단위로 1쌍만 두며 청구항목별로 두지 않는다** → 3.5
  예: 8월분 임대료·관리비를 8월 19일에 청구하고 8월 31일까지 납부
- 건물 기본값 변경은 이후 등록되는 계약에만 적용한다

**단수 처리**
- **청구서 합계는 100원 미만을 자동 절사한다.** 절사액은 청구서 내 우선순위가 가장 낮은 항목에서 차감하고 청구서에 `단수 절사` 행으로 표시한다 → 4.2.6

**일할 계산**
- 산출식과 예시는 → 4.2
- 해지일이 입력된 계약은 고정액 항목을 자동으로 일할 계산한다. 해지일이 당월 청구일 이전이면 당월 청구서를 발행하지 않는다 → 4.2.3
- 계약이 시작된 회차의 청구일이 이미 경과한 경우 **다음 회차 청구일에 청구서를 2장 발행한다.** 지난 회차 일할분과 당월 전액을 각각 발행하며 납부마감일은 둘 다 당월 마감일로 한다

**정산 항목의 부분 기간**
- 임차인이 산정 기간 중 일부만 사용한 경우(입주·퇴거) 담당자가 해당 유닛의 금액을 직접 계산해 입력한다. 시스템은 검침과 안분까지만 처리한다 → 4.1.9

**공실**
- 공실 유닛도 공용분 안분 대상에 포함하되 청구서를 생성하지 않는다 → 4.1.7

**수납 배분 우선순위**
- 청구항목마다 우선순위가 존재한다 (예: 임대료=1, 고정관리비=2, 주차비=3)
- **우선순위는 건물 관리비 탭(PRO-3)에서 건물 단위로 정한다.** 약정에서 따로 정하지 않는다
- 기본값은 3.3 기준표를 따른다. 연체료는 99(최후순위)다
- 배분 순서는 → 4.3

**수정**
- **약정을 고치면 앞으로 발행하는 청구서부터 적용한다.** 이미 발행한 청구서는 바뀌지 않는다. 발행한 청구의 수정·무효는 PAY-5에서 한다
- 적용 범위(이것만 / 이후 모두 / 전체)를 묻지 않는다. 발행한 청구는 어차피 바뀌지 않으므로 늘 `앞으로 발행분부터`다
- **임대료·고정관리비는 슈퍼관리자만 수정한다.** 금액을 바로 고치면 다음에 발행하는 청구서부터 적용되고, 사유를 남긴다(이력)
- **날짜가 정해진 인상은 임대료 인상 예약으로 넣는다.** 적용일부터 자동으로 새 금액을 청구한다 → CTR-3 · 4.2.7
- 항목은 지우지 않는다. 청구를 멈추려면 금액을 0원으로 고친다(사유 필수)
- 반복 종료 조건을 두지 않는다. 계약이 끝나면 청구도 끝난다
- 금액·반복주기·기산일 수정, 인상 예약 추가·수정·삭제, 정산액 대납 계약 변경은 이력에 기록한다 → 3.6

**반복주기**
- 고정액 항목은 **기산일이 속한 달부터 반복주기마다** 청구한다. 예: 분기 · 기산일 2026.08.01 → 8월 · 11월 · 2월 …
- 카리나빌딩에는 매월 외의 고정액 항목이 없지만, 다른 운영사를 위해 격월·분기·반기·연1회를 둔다. 반복주기는 고정액 항목의 `수정`에서 바꾼다

### 【설계 의도】

- 등록과 발행을 분리한다. 계약 등록 화면에서 청구항목을 함께 입력받으므로 준비중 상태에서도 약정이 존재해야 한다
- 별도 화면을 두지 않는다. 약정은 계약에 딸린 것이라 계약 상세에서 보고 바로 고치는 것이 자연스럽다
- 계약마다 다른 것은 임대료·고정관리비의 약정 금액뿐이다. 정산 항목까지 계약마다 켜고 끄게 하면
  같은 건물 안에서 계약마다 규칙이 달라지고, 관리비 정산의 안분과 어긋날 수 있다. 그래서 정산 항목은 건물 설정 한 곳에서만 정한다
- 청구 여부의 기준은 약정 금액 하나다(0원이면 청구 안 함). 스위치와 금액이 따로 있으면 「켜져 있는데 0원」 같은 모순이 생긴다
- 계약서에 적힌 인상은 예약으로 받는다. 언제부터 얼마로 바뀌었는지 기록이 남고, 달 중간 변경도 일할로 계산된다.
  바로 고치기는 계약서 금액 오기나 재협의처럼 예약이 맞지 않는 경우를 위해 슈퍼관리자에게만 연다

## PAY-5 · 발행 청구 수정 및 취소

**목적** 이미 발행되어 원장에 기록된 청구 회차를 수정하거나 무효 처리한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PAY-2 더보기 / CTR-3 원장 탭

### 【입출력 항목】

```
필터: 건물고유이름, 청구년월, 계약상태, 납부상태

[목록]
청구년월, 계약고유이름, 청구항목,
공급가액, 부가세, 청구액(합계),
납부액, 미납액, 납부상태      ※ 읽기 전용
납부마감일,
더보기(납부마감일 변경, 메모 수정, 무효 처리, 재발행, 변경 이력 보기)

[납부마감일 변경시]  변경할 납부마감일, 변경 사유
[무효 처리시]        무효 사유
[재발행시]           무효 처리한 청구의 내용이 채워진 상태로 열리며 수정해 발행
```

### 【동작 규칙】

**적용 대상**
- **본 화면은 이미 발행되어 원장에 기록된 청구 회차만 다룬다.** 반복주기·약정액 등 약정 수정은 PAY-3에서 수행한다

**수정 범위**

| 구분 | 항목 | 단위 |
|---|---|---|
| 수정 가능 | 납부마감일(사유 필수), 메모 | 청구서 |
| **수정 불가** | 청구년월, 청구항목, 청구액, 발행 문서 | — |

- 수정 불가 항목을 변경해야 하는 경우 **청구서를 무효 처리한 뒤 재발행**한다
- 납부마감일은 임차인 요청으로 연장하는 사례가 있으므로 사유를 입력받아 수정한다
- 납부액·미납액·납부상태는 수납 거래의 결과이므로 직접 수정할 수 없다. 수납 기록을 수정한다 → PAY-9

**무효 처리 — 청구서 단위**
- **발행된 청구는 삭제하지 않는다. 무효 처리만 수행한다**
- **무효 처리와 재발행은 청구서 단위로 수행한다.** 항목 1건만 취소하면 임차인이 수령한 청구서와 시스템 기록이 불일치한다
- 청구서를 무효 처리하면 포함된 **청구 건 전체에 대해 원장에 `청구 취소` 거래가 기록**된다. 원 청구 거래는 삭제하지 않는다
- 재발행 시 올바른 내용으로 청구서를 새로 발행하고 임차인에게 재발송한다
- **수납이 1건이라도 존재하는 청구서는 무효 처리할 수 없다.** 수납 기록을 먼저 취소해야 한다
- **마감된 월의 청구서는 무효 처리할 수 없다.** 정정이 필요하면 당월에 조정 거래로 처리한다 → PAY-11

**이력**
- 수정·무효 처리·재발행 시 누가·언제·무엇을·왜 처리했는지 이력을 기록한다. 사유 입력이 필수다 → 3.6
- 변경 이력은 더보기에서 조회한다


### 【설계 의도】

- 발행 금액을 직접 수정하면 과거 잔액이 재계산되고 이미 발행한 세금계산서와 어긋난다. 무효 처리 시 원장에 `청구 → 취소 → 재청구` 흐름이 남으며, 이는 수정세금계산서 실무와 동일한 구조다
- 화면명을 `청구 내역 수정 및 삭제`에서 변경했다. 삭제를 제거하고 무효 처리로 일원화했다

### 【연관 화면】 PAY-2, PAY-3, PAY-9, CTR-3, REC-1
### 【알림】 이메일 — 재발행 시 청구 내역서 재발송 / 내부 — 수정·무효·재발행 결과

## PAY-13 · 입금 매칭

**목적** 입금을 **한 건씩** 임차인에 붙이고 청구에 배분해 원장에 기록한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 청구 · 수납 → 입금 매칭 / PAY-1 미기록 입금 안내 / DASH-1 계약 미지정 입금 카드

> **작업 화면이자 돈 기준 화면이다.** 관리비 정산(PAY-10)처럼 확정 전에 하나씩 확인하는 곳이다.
> 계약별 납부상태는 수납 내역(PAY-6)에서 본다.

### 【입출력 항목】

```
필터: 건물(단일 선택), 청구년월
[상단] 은행 거래내역 업로드

[대기열]  왼쪽. 이 건물·월의 입금 전부. 입금일시 오름차순
  입금일시, 입금자명, 입금액, 상태(자동 매칭 / 미매칭 / 확정 / 무시)
  [진행] 처리 N / 전체 M건

[선택한 입금]  오른쪽. 한 건만 크게 표시
  (입금)   입금일시, 입금자명(원문), 비교용 이름, 거래구분, 입금액, 매칭 상태
  ① 임차인   임차인 선택(자동 매칭이면 그 임차인, 미매칭이어도 상호가 비슷한 임차인이 있으면 미리 채우고 확인을 안내)
             「앞으로 ○○을(를) 이 임차인의 입금자명으로 등록」(기본: 체크)   ※ 이미 등록된 입금자명이면 표시만
  ② 배분 미리보기   이 임차인의 이 건물 미납 청구 전부
     계약고유이름, 청구항목, 우선순위, 배분 전 미납액, 배분액, 배분 후 미납액(0이면 `완납`)
     ※ 이번 회차가 아닌 청구(밀린 달)만 청구항목 옆에 `26.07월분`처럼 달을 붙인다
     ※ 이 입금으로 채우지 못하는 청구도 배분액 `—`로 함께 보인다. 배분 후 남는 미납이 모두 보여야 한다
     [합계] 배분 전 미납 합계 · 배분 합계 · 배분 후 미납 합계
     [남는 금액] 입금액이 미납보다 크면 표 아래에 따로 표시(미배분)
     [임차인 미납] 배분 전 합계 → 배분 후 합계
  [하단] 무시 · 확정하고 다음 입금

[기록된 입금을 선택하면]
  배분 내역(계약고유이름, 청구항목, 우선순위, 청구액, 배분액, 배분 후 미납),
  결제수단, 등록방식, 등록관리자, 매칭 근거(등록된 입금자명 / 담당자 지정), 거래번호, 메모
  미배분 잔액 처리(환불 / 다음 회차 배분), 수정·취소 → PAY-9

[은행 거래내역 업로드]  파일, 건물 선택, 은행 선택 → 4.6.1
```

### 【동작 규칙】

**마감한 달**
- **마감한 달의 입금은 확정·무시·되돌리기·수정·취소를 할 수 없고 볼 수만 있다.** 은행 거래내역 업로드도 막는다
- 화면 안에 `마감된 회차입니다 — 고치려면 월 마감에서 마감 취소`를 표시하고 월 마감 링크를 둔다 → PAY-11
- 수납 내역(PAY-6)과 미납 관리(PAY-2)는 조회·현장 수납 화면이므로 막지 않는다. 오늘 받은 돈은 오늘 날짜로 기록된다

**한 건씩 확정한다**
- **일괄 승인을 두지 않는다.** 확정은 선택한 입금 한 건에만 한다
- 확정하면 입금 기록과 수납 배분이 원장에 기록되고 **다음 대기 입금으로 넘어간다**
- 자동 매칭은 **임차인을 미리 채울 뿐**이다. 담당자가 배분 미리보기를 보고 확정해야 기록된다
- 임차인을 고르지 않으면 확정할 수 없다

**배분 미리보기는 지금 원장 기준이다**
- 미리보기는 **이미 확정된 입금만 반영한 상태**에서 이 입금을 넣었을 때의 결과다.
  아직 확정하지 않은 다른 입금은 계산에 넣지 않는다. 보이는 그대로 기록된다
- 대기열은 입금일시 순서다. **순서대로 처리하는 것을 기본으로 한다.** 같은 임차인이 나눠 낸 입금(예: 13:05:36 임대료 →
  13:05:37 나머지)은 앞 입금을 먼저 확정해야 뒤 입금이 나머지 항목을 채운다
- 배분 순서 → 4.3. 여러 계약·미납 회차에 걸친 배분도 같은 순서다

**상태 — 넷뿐이다**

| 구분 | 상태 | 뜻 |
|---|---|---|
| 처리 전 | **자동 매칭** | 등록된 입금자명과 같다. 임차인이 미리 채워진다 |
| 처리 전 | **미매칭** | 등록된 입금자명이 없다. 담당자가 임차인을 고른다 |
| 처리 후 | **확정** | 원장에 기록되었다 |
| 처리 후 | **무시** | 임차인 입금이 아니다 |

- 상호가 비슷한 임차인이 있어도 상태는 `미매칭`이다. 임차인 선택란에 미리 채우고 확인하라고 안내할 뿐이다
- 담당자가 임차인을 골라도 확정 전까지는 `미매칭`이다
- `자동 매칭`도 확정해야 기록된다

**매칭**
- 자동 매칭·미매칭 규칙 → 4.6.3. **첫 달에는 모든 입금을 담당자가 고른다**
- 임차인을 고를 때 입금자명을 그 임차인의 별칭으로 등록한다(기본). 등록하면 대기열의 같은 이름 입금도 자동 매칭으로 바뀐다
- **임차인 입금이 아니면 `무시`한다.** 사유를 받지 않는다. 무시한 입금은 대기열에서 되돌릴 수 있다
- 같은 거래가 두 번 올라오면(겹치는 기간의 파일) 이미 기록된 입금은 대기열에 다시 넣지 않는다.
  입금일시 · 입금액 · 입금자명이 같으면 같은 거래로 본다

**미배분 잔액**
- 입금액이 미납 합계보다 크면 남는 금액을 **미배분으로 입금 기록에 보관**한다. 기록된 그 입금을 선택해
  환불 또는 다음 회차 배분 중 하나를 고른다. 자동 처리하지 않는다 → 4.3.4

**대기열**
- **통장 1행 = 대기열 1행이다.** 입금을 합치거나 나누지 않는다
- `무시`한 입금도 대기열에 남긴다

**계약 상태 연동**
- 보증금 전액이 수납으로 기록되면 `이 계약을 진행중으로 전환하시겠습니까?`를 안내한다. **자동 전환하지 않는다** → 3.2

### 【설계 의도】

- 매칭 오류는 다른 임차인 원장에 돈을 기록하고, 되돌리려면 무효 처리가 필요하다. 한꺼번에 승인하면
  배분 내역을 보지 않고 지나가게 되므로 **한 건씩 크게 보여주고 한 건씩 확정**한다
- 판단에 필요한 정보 — 누가 보냈나, 그 임차인에게 무엇이 밀려 있나, 이 돈으로 무엇이 채워지나 — 를 한 화면에 모은다
- 한 건물의 월 입금은 15건 안팎이라 한 건씩 처리해도 부담이 크지 않다
- **작업 화면과 조회 화면을 나눈다.** 확정 전 단계를 거치는 작업(PAY-10, PAY-13)은 작업 화면에서,
  기록된 결과의 확인은 목록 화면(PAY-6)에서 한다
- **입금 매칭은 돈 기준, 수납 내역은 계약 기준이다.** 누가 얼마를 보냈는지는 여기서, 어느 계약이 다 냈는지는 PAY-6에서 본다

### 【연관 화면】 PAY-6, PAY-2, PAY-1, USER-7, CTR-3, DASH-1
### 【알림】 없음 / 내부 — 은행 거래내역 매칭 결과(자동 매칭/미매칭 건수)

## PAY-6 · 수납 내역

**목적** 선택한 달의 청구를 **계약별로** 다 받았는지 확인한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 청구 · 수납 → 수납 내역 / PAY-13 처리 완료 / PAY-12 수납 칸

> **계약 기준 조회 화면이다.** 관리자가 궁금한 것은 "누가 얼마를 보냈나"가 아니라 "어느 계약이 이번 달 청구를 다 냈나"다.
> 입금 한 건 한 건은 입금 매칭(PAY-13)에서 본다.

### 【입출력 항목】

```
필터: 건물(단일 선택), 청구년월, 납부상태(전체 / 완납 / 부분납 / 납부전 / 미납)

[목록]  계약별 그룹. 접고 펼칠 수 있으며 기본은 접힘. PAY-1과 같은 구조
  그룹 행   계약고유이름, 청구액, 수납액, 미납액, 납부상태
  항목 행   청구항목, 청구액, 수납액, 미납액, 납부상태
            ※ 입금 행을 두지 않는다. 어느 입금이 들어왔는지는 입금 매칭(PAY-13)과 계약 원장(CTR-3)에서 본다

[합계]  계약 수, 청구액 합계, 수납액 합계, 미납액 합계

상태 정의
  납부상태  완납 / 부분납 / 납부전 / 미납 → 3.2   ※ 무효 청구는 목록에 올리지 않는다
```

### 【동작 규칙】

**목록**
- **한 계약 × 한 청구년월이 한 행이다.** 청구서 발행(PAY-1)의 청구서 단위와 같다
- **계약의 납부상태는 그 달 청구항목들로 정한다.** 전부 완납이면 `완납`, 수납이 0이면 납부마감일 전 `납부전` · 후 `미납`, 그 외 `부분납`
- 금액은 모두 부가세 포함이다 → 3.4
- 선택한 달의 청구만 본다. **이전 달 미납은 여기에 합치지 않는다.** 밀린 달 전부는 미납 관리(PAY-2)에서 본다
- 이번 달 청구가 없는 계약은 올리지 않는다
- 확정 전 입금이 남아 있으면 상단에 안내한다. **기록되지 않은 입금 때문에 미납으로 보일 수 있다** → PAY-13

**2단 구조**
- **입금은 1건, 수납 배분은 N건이다** → 2.6
- **입금은 계약이 아니라 임차인(사업자)에 속한다.** 한 입금이 같은 건물에 있는 그 사업자의 여러 계약에 배분될 수 있다 → 4.3
- 원장에는 배분된 항목별로 수납 거래가 각각 기록된다 → CTR-3
- 납부상태는 직접 바꾸지 않는다. 수납이 기록되면 따라온다 → 3.2

**정정**
- 이 화면에서는 정정하지 않는다. 입금 매칭(PAY-13)에서 기록된 입금을 골라 `수정·취소`로 PAY-9에 진입한다.
  입금액은 수정할 수 없고 무효 처리 후 다시 기록한다

### 【설계 의도】

- **세 화면이 같은 돈을 범위만 달리해 본다.** 건물별·이번 달(PAY-12) → 계약별·한 달(PAY-6) → 계약별·밀린 달 전부(PAY-2).
  PAY-6은 확인하는 화면, PAY-2는 현장 수납과 미납 안내로 조치하는 화면이다
- 청구에 입금을 직접 연결하지 않는다. 임차인은 청구서 합계를 일괄 입금하지만 청구는 항목별 다건이므로,
  청구에 직접 붙이면 실제 입금 시점과 금액이 소실된다 → 2.6

### 【연관 화면】 PAY-13, PAY-2, PAY-12, PAY-9, CTR-3
### 【알림】 없음

## PAY-9 · 수납 내역 수정 및 취소

**목적** 잘못 등록된 입금 기록을 수정·무효 처리하고 배분을 재조정한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** PAY-13 기록된 입금 → 수정·취소

### 【입출력 항목】

```
[수정]           입금일, 입금자명, 결제수단, 메모, 변경 사유
[배분 재조정]    청구ID별 배분액    ※ 입금액 총액 고정
[무효 처리]      무효 사유
[계약 재지정]    변경할 계약, 변경 사유   ※ 등록방식이 은행거래내역매칭인 경우
[변경 이력]      변경일시, 변경자, 변경 항목, 변경 전/후 값, 사유
```

### 【동작 규칙】

**무효 처리**
- **수납 기록은 완전 삭제하지 않는다. 무효 처리만 수행한다**
- 무효 처리 시 원장에 `수납 취소` 거래를 기록해 미수금을 원복한다. 원 수납 거래는 삭제하지 않는다

**수정 범위**

| 구분 | 항목 |
|---|---|
| 수정 가능 | 입금일, 입금자명, 결제수단, 메모 (사유 필수) |
| **수정 불가** | 입금액 — 무효 처리 후 재등록 |
| 수정 불가 | 등록방식, 등록관리자, 거래번호 (시스템 기록) |

**배분 재조정**
- **입금액 총액을 고정한 채 배분처만 다시 지정한다**
- 실무에서 가장 빈번한 수정이 `관리비 입금이 임대료로 배분된 경우`이며, 무효 처리 없이 해결된다
- 재조정 시 원장의 기존 수납 거래를 `수납 취소`로 되돌리고 새 배분대로 수납 거래를 다시 기록한다

**등록방식별 제한**

| 등록방식 | 수정 범위 |
|---|---|
| 수동 | 전체 |
| 은행거래내역매칭 | 수동과 동일. **계약 재지정 허용** |
| [2차] PG자동 | 메모 외 수정 불가. 무효 처리는 사유 입력 시에만. 화면에 `자동 수납건은 수정 불가` 명시 |

**무효 처리 시 연동**
- 미배분 잔액이 있으면 함께 회수한다
- 보증금 수납이었고 해당 계약이 진행중이면 `이 계약이 진행중 상태입니다. 계속하시겠습니까?` 경고를 표시한다
- 관련 청구의 납부상태와 미납액을 자동 재계산한다

**이력**
- 모든 변경 사항을 이력으로 보존한다. 누가·언제·무엇을·왜 처리했는지 기록하며 화면에서 조회한다 → 3.6

### 【설계 의도】

- 임차인이 입금을 주장하는데 데이터가 없으면 분쟁이 발생하므로 완전 삭제를 금지한다
- 입금액 수정을 막는 이유는 금액 변경 시 배분이 전부 재계산되고 원장의 수납 거래가 모두 변경되기 때문이다. PAY-5와 동일한 원칙이다
- PG 자동 건의 수정을 제한하는 이유는 외부 시스템 기록이므로 변경 시 PG 정산과 어긋나기 때문이다

### 【연관 화면】 PAY-6, PAY-2, CTR-3, REC-1
### 【알림】 없음 / 내부 — 수납 수정·무효 처리·배분 재조정 결과

## PAY-10 · 건물 관리비 정산

**목적** 건물 단위로 공과금 고지서와 유닛별 검침값을 입력해 유닛별 청구 금액을 산출한다.
**사용자** 슈퍼관리자, 관리자
**진입 경로** 메인 메뉴 → 관리비 정산 / DASH-1 정산 미확정 카드

> **매월 수행하는 필수 업무이며 청구 발행의 선행 조건이다.** 이번 회차에 정산할 항목이 있으면 본 화면의 산출 결과가 확정되어야 해당 월의 청구서를 발행할 수 있다. 정산할 항목이 없으면 이 화면을 거치지 않는다.

### 【입출력 항목】

필터: 건물고유이름, 정산회차(년월)

#### 화면 구성

**청구항목마다 거치는 단계가 다르다. 단계를 화면의 축으로 삼지 않는다.**

```
전기요금       고지서 → 검침 입력 → 조정 → 산출 결과      4단계
정화조청소비    고지서 → 조정 → 산출 결과                3단계  검침이 없다
전력기금       고지서 → 산출 결과                      2단계  전기요금의 배분을 따른다
주차비         금액 입력 → 산출 결과                    2단계  고지서·검침·조정이 없다
```

**항목당 한 페이지를 주고, 그 항목이 실제로 거치는 단계만 세로로 쌓는다.**

```
✓ 전기요금  ✓ 수도요금  가스요금 [미검침 3]  ✓ 주차비    [+ 청구항목 추가]   ← 항목 탭
─────────────────────────────────────────────
① 고지서        수령일 · 총사용량 · 공급가액 · 부가세 · 소계
② 검침 입력      유닛별 직전/당월 검침값
③ 조정          유닛별 배율
④ 산출 결과      유닛별 금액 · 검증
```

**단계 번호는 항목마다 다시 매긴다.** 주차비의 산출 결과는 ②다.

> **설계 의도** 단계를 가로 네비게이션으로 고정하면 항목마다 「이 단계에는 이 항목이 없다」는
> 예외가 생긴다. 실제로 그랬다 — 2단계에서 계량기 없는 항목을 걸러내고, 3단계 이름은
> `조정`인데 직접 입력 항목에서는 금액 입력 화면이 떴다.
> **항목별 페이지에서는 그것이 예외가 아니라 그 항목의 모양이 된다.**
> 담당자의 실제 작업 단위도 항목이다 — 한전 고지서를 받아 검침하고 조정해 결과를 확인하는
> 일련의 과정이 한 항목 안에서 완결된다.

**항목 탭**

```
✓ 전기요금   ✓ 수도요금   가스요금 [미검침 3]   ✓ 주차비        [+ 청구항목 추가]
```

- **새 회차를 열면 건물 관리비 탭에서 반복주기가 `매월`인 정산 항목이 이미 탭에 올라와 있다.** 매달 추가할 필요가 없다
- 가끔 오는 고지서(정화조청소비 반기, 교통유발부담금 연1회 등)는 도착했을 때 탭 오른쪽 끝의 **`+ 청구항목 추가`**로 올린다
- 이번 달에 고지서가 오지 않은 매월 항목은 그 항목 페이지 고지서 절의 `이번 회차 제외`로 뺀다
- **`전체` 탭을 두지 않는다.** 항목 목록만 보여주는 화면은 따로 할 일이 없다
- **완료한 항목에 `✓`를 표시한다.** 어디까지 했는지 탭에서 바로 보인다
- 손봐야 할 항목에는 사유를 배지로 표시한다

| 표시 | 조건 |
|---|---|
| `✓` | 입력이 끝났고 **저장했다** |
| `고지서 미입력` | 공급가액이 0이다 |
| `미검침 N` | 계량기 보유 유닛 중 당월 검침값이 없다 |
| `검침 역전 N` | 당월이 직전보다 작다 → 4.1.8 |

**항목별 저장**
- 항목 페이지 맨 아래에 `저장하기` 버튼을 둔다. **저장해야 탭에 `✓`가 붙는다.** `✓`가 없으면 저장하지 않은 것이다. 따로 `저장 전` 표시를 두지 않는다
- 입력이 끝나지 않았으면 버튼이 눌리지 않는다. 저장한 뒤 그 항목의 값을 하나라도 고치면 `✓`가 사라진다
- **모든 항목을 저장해야 `정산 확정`이 눌린다**

**지난 회차**
- 정산회차 필터로 지난 달을 고르면 **이번 달과 같은 항목 페이지**(고지서 · 검침 · 조정 · 산출 결과)로 그 달의 입력값을 본다.
  항목 탭에는 모두 `✓`가 붙어 있다(확정된 회차). `+ 청구항목 추가`·`저장하기`는 없다
- **마감한 회차는 잠긴다.** 화면 안에 `마감된 회차입니다 — 0000.00.00 마감, 고치려면 월 마감에서 마감 취소`를 표시하고 월 마감으로 가는 링크를 둔다 → PAY-11
- 마감을 취소하면 그 회차를 다시 고칠 수 있다. 고친 뒤 다시 마감한다

**일회성 청구**

```
`+ 청구항목 추가`에서 `일회성 청구`를 고르면 항목 탭에 `일회성 청구`가 생긴다. 이번 회차에만 특정 계약에 붙는 청구
  [한 줄] 계약, 항목명(예: 엘리베이터 사용료, 파손 수리비), 금액(부가세 포함), 발행 문서, 근거·메모, 삭제
  [+ 한 줄 추가] · 합계 · [이번 회차 제외]
```

- 이사할 때 엘리베이터 사용료, 임차인이 부순 시설의 수리비처럼 **한 번만 청구하는 돈**을 넣는다
- 계약 등록(CTR-2)에서 미리 넣지 않는다. 생길 때 그 달 관리비 정산에서 넣는다
- 정산을 확정하면 그 계약의 이번 회차 청구서에 함께 실린다 → PAY-1. 원장에는 청구 한 줄로 기록된다
- 안분하지 않는다. 입력한 계약에 입력한 금액 그대로 청구한다
| `미입력` | 직접 입력 항목에 금액이 하나도 없다 |
| `전기요금 미완` | **참조 항목** — 참조 대상이 아직 끝나지 않았다 |
| `전기요금 미선택` | **참조 항목** — 참조 대상이 이번 회차에 없다 |
| `건물 미설정` | PRO-3에 등록했으나 배분 기준을 지정하지 않았다. 임대면적으로 계산한다 |

**참조 항목은 참조 대상의 상태를 물려받는다.**

```
전기요금 [미검침 1]   전력기금 [전기요금 미완]   TV수신료 [전기요금 미완]
```

참조 항목은 자체 입력이 없어 **언제나 `✓`로 보이지만 금액은 확정되지 않는다.**
전기요금 검침이 끝나야 전력기금·TV수신료 금액이 정해지므로 **작업 순서가 강제된다.**
그 순서가 탭에 드러나지 않으면 담당자가 전력기금을 끝냈다고 오인한다.

참조 대상이 이번 회차에서 제외되면 배분 기준 자체가 없으므로 경고한다.

**화면 머리글**

화면 머리글에 **상태 배지나 합계를 두지 않는다.** 정산 상태는 PAY-12에서, 회차 합계는
청구서 발행(PAY-1)에서 확인한다. 이 화면은 항목 하나를 처리하는 자리다.

**고지서 입력 절의 배치**

```
수령일        고지서 총사용량      공급가액        부가세                    소계
2026-09-08   12,400 kWh     1,920,000 원   192,000 원        2,112,000원
```

- 단위(`kWh`·`원`)는 **입력란 오른쪽에 같은 줄로** 둔다. 아래로 떨어뜨리지 않는다
- 소계는 오른쪽 끝에 정렬하되 다른 필드와 **같은 행에서 줄바꿈되게** 한다
- 사용량이 없는 항목은 `고지서 총사용량`을 표시하지 않는다
- 면세·비과세 항목은 부가세란을 `면세` 표시로 잠근다

**검침 입력 절**

**전 유닛을 한 표에 표시한다.** 조정·산출 결과 절과 대상이 같다.

- [목록] **계약고유이름**, 검침일, 직전 검침값, 당월 검침값, **개별 사용량**, **계량기 배율**, **증감**
- 개별 사용량 = (당월 − 직전) × 계량기 배율. 배율이 반영된 값이다
- 증감 = 계량기 배율로 더해진 양. 배율이 1이면 `—`
- 계량기 배율은 이 화면에서 **직접 입력한다.** 검침을 돌며 계량기를 확인하는 자리이기 때문이다
  건물 관리비 탭(PRO-3)의 계량기 목록에서도 같은 값을 고칠 수 있다 → 4.1.3-3
- **`지침 차이` 열을 따로 두지 않는다.** 직전·당월이 같은 행에 있으므로 복원할 수 있고,
  조정 절과 같은 「현재 값 + 조작 + 증감」 구조를 유지한다
- [합계 행] 개별 사용량 합계 (계량기 보유 유닛 수 병기)
- [입력] 당월 검침값(유닛별), 검침일(유닛별)
- [일괄] 상단에 `검침일 일괄 적용`을 둔다. 전 유닛의 검침일을 한 번에 맞춘다
- [미입력 표시] 계량기 보유 유닛 중 당월 검침값이 입력되지 않은 건수

**계량기가 없는 유닛도 행으로 표시하되 입력을 잠근다.**

```
계량기 있음   검침일·직전·당월 입력 가능. 개별 사용량 자동 산출
계량기 없음   행은 보이되 전 칸이 잠긴다. 당월 검침값란에 「계량기 없음」 표시
계량기 공유   전 칸이 잠기고 「본관302호 공유」처럼 상대 유닛을 표시한다 → 4.1.3-4
```

**설계 의도**
어느 유닛에 계량기가 있는지가 이 화면에서 그대로 읽혀야 한다.
계량기 보유 유닛만 추려서 보여주면 **목록에 없는 유닛이 누락인지 계량기가 없는 것인지**
구분되지 않는다. 담당자는 매월 「빠진 유닛이 없는가」를 확인하는데, 전 유닛이
같은 자리에 같은 순서로 나와야 그 확인이 성립한다.
한 항목의 검침 입력·조정·산출 결과는 **모두 같은 유닛 목록을 같은 순서로 표시한다.**

- 계약이 없는 유닛은 `건물별칭|유닛고유번호` 두 요소로 표기한다 → 3.1
- 유닛상태는 칼럼이 아니라 계약고유이름 뒤 칩으로 표기한다 → 3.2-3
- 직전 검침값은 **직전 정산 회차의 당월 검침값**이며 수정할 수 없다.
  격월·반기 항목은 직전 회차가 전월이 아니므로 `전월`이라 부르지 않는다
- 검침 기록은 원본이며 수정하지 않는다
- **당월 검침값이 비어 있으면 그 유닛의 개별 사용량은 `0`으로 둔다.**
  `당월 − 직전`을 그대로 계산하면 음수가 되어 공용 사용량 합계가 부풀고 청구금액이
  음수로 나온다. 미입력과 `0`을 구분해 처리한다
- **당월 검침값이 직전보다 작으면 경고한다.** 계량기 교체(0으로 리셋)나 오입력이다.
  그대로 확정할 수 없다 → 4.1.8
- **검침일은 유닛 단위로 저장한다.** 기본값은 당일이며 유닛마다 수정할 수 있다.
  계량기 교체·검침 누락으로 일부 유닛만 다른 날 검침하는 경우가 있어 항목 단위로 고정할 수 없다
- 계량기 보유 유닛은 **건물 관리비 탭(PRO-3)**에서 지정한다. 이 화면에서 바꾸지 않는다

**조정 절**

**배분 기준이 `직접 입력`인 항목은 조정 절 대신 「금액 입력」 절을 갖는다** → 4.1.3-2

```
[목록] 계약고유이름, 청구 금액(입력), 비고
[합계] 입력 합계 = 이 항목의 공급가액
※ **비율을 입력하지 않는다.** 입력한 금액이 그대로 그 계약에 청구된다
※ 비율 열을 두지 않는다. 안분하지 않으므로 보여줄 비율이 없다
※ 배율을 쓰지 않는다
※ 계약이 없는 유닛은 입력란을 잠근다
```

**그 외 항목은 아래 조정 표를 쓴다.**

**전 유닛을 한 표에 표시한다.**

```
[헤더] 공용 사용량 합계, 배분 기준
[목록] 계약고유이름, 배분 기준값, 공용 배분 비율, 공용 사용량, 배율, 증감
[합계] Σ배분 기준값, 100%, 공용 사용량 합계, 증감 합계 = 0
[입력] 배율 (0.1 단위, 기본값 1.0, 0 허용)
```

**참조 항목은 참조 대상의 `부담 비율`을 쓴다.**

```
전력기금 217,690원  →  전기요금의 부담 비율(총 사용량 ÷ 고지서 총사용량)대로 나눈다
                      본관7층 25.30% → 55,076원
```

공용 배분 비율(공용분만)이 아니라 **부담 비율(개별 + 공용)**이다.
전력기금은 한국전력이 **전기 사용량 전체**에 비례해 부과하는 부담금이므로,
개별 사용분을 빼고 나누면 전기를 많이 쓴 유닛이 전력기금을 적게 내게 된다.

**참조 항목은 조정 절을 두지 않는다.** 전력기금·TV수신료처럼 자체 검침값 없이 타 항목의
검침값을 쓰는 항목은 **배분이 참조 대상에 완전히 종속된다.** 여기에 배율 입력란을 두면
값을 바꿔도 계산에 반영되지 않는 죽은 입력이 된다 → 4.1.3
산출 결과 절 위에 `전기요금의 배분을 그대로 따른다`고 안내한다.

| 열 | 내용 |
|---|---|
| 배분 기준값 | 배분 기준 = 사용량 → `개별 사용량`, 임대면적·사용량+임대면적 → `임대면적`. **배율 적용 전 값** |
| 개별 사용량 | **배분 기준이 면적이면서 계량기가 있는 항목에만 추가로 표시한다.** 누가 얼마를 직접 썼는지 알아야 배율을 정할 수 있다. 배분 기준이 사용량이면 배분 기준값과 같은 값이므로 열을 따로 두지 않는다 |
| 공용 배분 비율 | 공용 사용량 ÷ 공용 사용량 합계. **공용분을 나누는 비율이다** |
| 공용 사용량 | **배율이 반영된 현재 값.** 배율을 바꾸면 즉시 다시 계산된다. 배율이 `0`이면 `부담 없음` |
| 배율 | 담당자가 입력한다. 기본값 1.0. **넣은 값만큼 정확히 배가된다** → 4.1.2 |
| 증감 | **전 유닛 배율이 1.0일 때 대비** 변화. 합계는 언제나 0이다 |

- **`(조정후) 공용 사용량` 열을 따로 두지 않는다.** 공용 사용량 열이 곧 조정 후 값이며
  변화량은 증감 열이 보여준다. 같은 값을 두 열에 놓으면 무엇이 현재 값인지 흐려진다

> **⚠️ 공용 배분 비율에 배율을 반영한다.**
> 배율 적용 전 비율을 보여주면 **화면에서 검산이 성립하지 않는다.**
> 배율 2.0인 유닛이 `비율 8.34% · 공용 884.7`로 나오는데 `합계 5,748.8 × 8.34% = 479.5`라
> 담당자가 계산이 틀렸다고 판단하게 된다.
>
> ```
> 공용 사용량    = 기준 공용 × 배율        (배율을 지정한 유닛)
> 공용 배분 비율 = 공용 사용량 ÷ 공용 사용량 합계
> ```
>
> 배율 적용 전 값은 `배분 기준값` 열에 그대로 있으므로 환산 과정을 따라갈 수 있다.
- **사용량을 재지 않는 항목**(정화조청소비·교통유발부담금)은 `공용 사용량`을 `배분 금액`으로
  바꾼다. 사용량 열을 두면 전부 `0`으로 나와 배율이 무엇을 바꾸는지 보이지 않는다

- **지정한 몫의 합이 공용 사용량 합계를 넘으면 경고한다.** 전 유닛 비례 배분으로
  물러섰음을 알리고 배율을 낮추도록 안내한다. 배율 1.0인 유닛이 하나도 없을 때도 같다 → 4.1.2

**설계 의도**
`증감 합계 = 0`이 **화면에서 확인 가능한 검산**이다. 한 유닛이 더 부담한 만큼 나머지가
덜 부담하고, 공용 사용량 합계는 변하지 않는다.

> **⚠️ 증감의 기준선은 「전 유닛 배율 1.0」이지 「직전 저장값」이 아니다.**
> 기준선을 조정 후 상태로 잡으면 배율을 바꿔도 증감이 나타나지 않고 합계도 0이 되지 않는다.

- 배율 `0`은 유효한 값이다. 미입력이 아니라 「이 유닛은 부담하지 않는다」는 지시다.
  공실·비운영중을 이번 회차만 빼는 수단이며 그 몫은 나머지 유닛이 나눠 갖는다 → 4.1.7
  구현 시 `0`을 falsy로 처리해 기본값 1.0으로 되돌리지 않도록 주의한다
- 배율을 1.0으로 되돌리면 조정 기록이 삭제된다
- **조정 사유는 화면에서 입력하지 않는다.** 배율 변경은 이력에 기록한다 → 3.6
- 작성자·작성일시는 화면에 표시하지 않는다

**산출 결과 절**

```
[목록] 계약고유이름, (조정 후)개별 사용량, (조정 후)공용 사용량, 총 사용량, **부담 비율**, 청구 금액
※ **부담 비율 = 총 사용량 ÷ 고지서 총사용량.** 조정 절의 `공용 배분 비율`과 다른 값이다
  조정 절은 **공용분을 나누는** 비율이고, 여기는 **고지서 전체에서의** 몫이다.
  이름을 구분하지 않으면 두 화면의 숫자가 달라 보여 계산이 틀렸다고 판단하게 된다
※ 공실·비운영중 유닛도 이 비율을 가지며 그 몫은 건축주가 부담한다.
  따라서 `청구 비율`이 아니라 `부담 비율`이다
[별도 행] 공실·미청구분 (건축주 부담)
[검증] 임차인 청구액 합계 + 공실·미청구분 = 고지서 총금액
```

- **사용량을 재지 않는 항목은 사용량 열을 표시하지 않는다.** `부담 비율`과 `청구금액`만 남긴다
- 계량기가 없는 항목은 `개별 사용량` 열을 표시하지 않는다
- 절사 잔차를 받은 유닛에 `절사 +N원`을 표시한다 → 4.1.8
- [캡션] 각 열의 산출 근거 — 개별 사용량 · 공용 사용량 · 총 사용량의 관계
- **열 이름에 `(조정 후)`를 붙인다.** 계기배율과 배분배율이 반영된 값임을 드러낸다

**절 캡션 작성 원칙**

- **읽는 사람은 개발자가 아니라 담당자다.** 지금 이 화면에서 무엇을 해야 하는지만 적는다
- 절마다 **세 줄 안쪽.** 계산식·용어 정의·예외 규칙은 캡션에 넣지 않는다
- 화면에 이미 보이는 것(열 이름, 버튼, 상태 배지)을 문장으로 반복하지 않는다
- 규칙의 근거와 예외는 본 명세서에 둔다. **화면은 조작 방법만 말한다**
- **이번 회차의 값을 캡션에 넣지 않는다.** 금액·사용량·예시 배수를 박으면
  회차마다 달라지는 값이 규칙의 일부처럼 읽힌다. 그 값은 표와 카드 머리글에 이미 있다

```
쓰지 않는다   개별 사용량 = (당월 − 직전 검침값) × 계기배율.
              계량기가 실측한 전용부 사용량이다.
              → 계산식은 명세서에 둔다

쓰지 않는다   공용 사용량 합계 15,500.9 kWh은 변하지 않습니다.
              2.3을 넣으면 정확히 2.3배가 됩니다.
              → 회차마다 달라지는 값과 임의의 예시 배수

쓴다         각 유닛의 당월 검침값만 넣으세요. 개별 사용량은 자동으로 계산됩니다.
             아직 검침하지 못한 유닛은 비워 두세요. 그 유닛은 공용분만 부담합니다.
             공용 사용량 합계는 배율을 어떻게 바꿔도 변하지 않습니다.
```

#### 정산 확정

정산 확정 → 산출 결과를 고정한다. 청구 건 생성과 원장 기록은 청구서 발행(PAY-1) 시점이다.

### 【동작 규칙】

**적용 범위**
- 임대료와 고정관리비는 계약 약정액이므로 본 화면에서 다루지 않는다. **사용량에 따라 금액이 달라지는 항목만 정산한다** → 3.2-2
- **이번 회차의 청구항목을 고르는 것이 첫 단계다.** 담당자는 정산할 항목을 정한 뒤 고지서를 입력한다
- **건물 관리비 탭(PRO-3)에 등록된 항목만 선택할 수 있다.** 목록에 없는 항목은 PRO-3에서 먼저 등록한다
- 사용 중인 항목이 초기 선택으로 표시되며 회차마다 제외하거나 다시 추가한다
- **청구항목을 하나도 선택하지 않을 수 있다.** 전기·수도를 포함한 모든 비용을 고정관리비로
  받는 운영사가 있다. 이 경우 정산 절차를 생략하고 고정액 항목만으로 청구서를 발행한다

**고지서 입력**
- **고지서 총금액은 입력하지 않는다.** 공급가액·부가세 등 구성 항목의 합계로 산출한다
- 부가세는 공급가액의 10%로 자동 계산하되 수정할 수 있다. 고지서 표기와 다를 수 있다
- 면세·비과세 항목은 부가세란을 잠근다. 과세 여부는 항목의 발행 문서가 결정한다 → 3.3
- **고지서 수령일을 입력한다**
- **고지서 한 건에서 청구항목이 복수로 도출될 수 있다.**
  한국전력 고지서에는 전기요금·부가세·전력산업기반기금·TV수신료가 함께 표기되나,
  전력기금과 TV수신료는 발행 문서가 `일반내역서`인 독립 청구항목이다.
  각각을 별도 청구항목으로 선택해 입력한다 → 3.3, 4.1.2

**설정의 소재**
- **본 화면에서는 배분 설정을 변경하지 않는다.** 매월 반복하는 작업이므로 회차마다
  설정을 확인하게 하지 않는다
- 청구항목의 정의(이름·발행 문서·산정방식·우선순위)와 배분 설정은 모두 PRO-3에서 건물별로 관리한다
- 건물별 배분 설정(배분 기준·참조 항목)의 **정본은 PRO-3 관리비 탭**이다.
- PRO-3에 등록했으나 배분 기준을 지정하지 않은 항목은 **임대면적을 기본값으로 적용**하고
  항목 탭에 `건물 미설정` 배지를 표시한다. 변경하려면 PRO-3으로 이동한다

**산정**
- 산정 규칙·건물별 설정·검산 예시는 **→ 4.1**

**검침 대상**
- **계량기 유무는 유닛 × 청구항목 단위로 판정한다** → 6.3 유닛 검침 설정
  동일 항목이라도 유닛마다 계량기 보유 여부가 다르다
- **계량기 보유는 등록된 설정으로 판정한다.** 검침값의 존재 여부로 판단하지 않는다.
  계량기가 있으나 당월 검침값이 아직 입력되지 않은 상태를 구분할 수 있어야 한다
- **왜 이 유닛만 검침 대상인지 화면에서 확인할 수 있어야 한다.**
  다만 설정값을 카드로 재현하지 않고 **캡션으로 간략히 안내한다.**
  설정 자체는 PRO-3 관리비 탭이 정본이며 본 화면에서 변경하지 않는다
- **계량기를 보유한 유닛이 하나라도 있는 항목만 검침 입력 절을 둔다.**
  절 안에는 전 유닛을 표시하고 계량기 없는 유닛은 입력을 잠근다 → 검침 입력 절
- 배분 기준이 `사용량`이더라도 자체 계량기가 없는 항목(전력기금·TV수신료)은
  참조 항목의 검침값을 사용하므로 검침하지 않는다 → 4.1.3
- 계량기가 없는 항목의 페이지에는 검침 입력 절이 나타나지 않는다

> **일부 유닛만 계량기를 보유한 경우** — 1층 상가에만 수도 계량기가 있는 건물이 해당한다.
> 해당 유닛은 개별 사용량을 청구받고 **공용분도 함께 부담한다.** 계량기는 전용부를 실측할 뿐
> 공용 화장실 급수는 그 계량기를 지나지 않는다. 산정 예시는 → 4.1.6

**검침과 조정**
- **조정 대상은 전 유닛이다.** 계량기 유무와 무관하다.
  계량기를 추가하려면 건물 관리비 탭(PRO-3)에서 지정한다
- **검침 기록은 원본이며 수정하지 않는다.** 공용분 부담을 바꾸려면 배율을 별도 기록으로 남긴다.
  사유는 받지 않으며 변경자·변경일시는 이력에서 확인한다 → 3.6
- 조정은 해제할 수 있으며 회차별로 이력이 축적된다
- **배율은 회차 값이다.** 기본값은 언제나 1.0이며 유닛에 상시 설정하지 않는다.
  계량기 자체의 환산 계수는 계기배율이며 배율과 다르다 → 4.1.3-3

**전용부 직접 납부 유닛**
- 임차인이 공급자와 직접 계약해 전용부를 따로 내는 유닛은 계량기가 없는 유닛으로 보인다. 공용분만 청구한다 → 4.1.7-2
- 안분에서 유닛을 빼는 설정은 따로 없다. 공용부도 쓰지 않는 유닛만 조정 절에서 배율 `0`으로 뺀다 → 4.1.7

**공실 처리**
- 공실 유닛도 공용분 안분 대상에 포함하되 청구서를 생성하지 않는다 → 4.1.7
- 공실 유닛은 별도 규칙 없이 배율대로 참여한다. 배분 기준이 사용량이면 공실 몫은 0에 가깝고, 면적이면 공실 면적만큼 발생한다. 기준은 건물·항목별 설정을 따른다 → PRO-3
- 산출 결과에 **`공실·미청구분`을 별도 행으로 표시**해 건축주 부담액을 확인할 수 있게 한다

**부분 기간**
- 임차인이 산정 기간 중 일부만 사용한 경우(입주·퇴거) 담당자가 해당 유닛의 금액을 직접 계산해 덮어쓰고 사유를 남긴다. **시스템은 검침과 안분까지만 처리하며 일할 계산은 하지 않는다** → 4.1.9

**확정 전 — 저장하지 않고 매번 다시 계산한다**
- 저장하는 것은 **입력값뿐이다.** 고지서(총사용량·금액), 검침값·검침일, 배율.
  부담 비율·공용 사용량·청구금액은 **저장하지 않고 화면을 열 때마다 계산한다**
- 따라서 어느 단계의 값을 고쳐도 이후 단계가 즉시 전부 갱신된다.
  고지서 총사용량을 바꾸면 같은 페이지 아래의 검침·조정·산출이 함께 바뀐다.
  **이것이 정상 동작이며, 항목별 페이지에서는 그 연쇄가 한 화면에 보인다**
- 단계를 순서대로 완료할 필요가 없다. 되돌아가 고치는 것이 기본 사용 방식이다

> **설계 의도** 산출 결과를 중간 저장하면 입력값과 어긋난 상태가 생긴다.
> 어느 것이 맞는지 판단할 근거가 없으므로 **파생값은 저장하지 않는다.**

**확정 시 — 산출 결과를 고정한다**
- 확정 시 청구항목별로 **(임차인 청구액 합계 + 공실·미청구분 = 고지서 총금액)** 을 검증한다.
  불일치 시 확정할 수 없다 → 4.1.8
- 원 미만 절사 잔차는 **부담 비율이 가장 큰 유닛에 더한다.** 따라서 정상적인 경우
  이 검증은 언제나 통과한다. 걸린다면 절사가 아니라 실제 오류다 → 4.1.8
- 산출 결과에서 잔차를 받은 유닛에 `절사 +N원`을 표시한다
- **확정 시점의 산출 결과를 스냅샷으로 저장한다.** 이후 재계산하지 않는다

```
저장 대상   고지서 총사용량 · 총금액
            유닛별 개별 사용량 · 공용 사용량 · 부담 비율 · 공급가액 · 부가세 · 절사 잔차
            적용된 설정 — 배분 기준 · 계량기 보유 유닛 · 계기배율 · 계량기 공유 ·
                          참조 항목 · 임대면적 · 배율 · 정산액 대납 계약
```

> **설계 의도** 임대면적은 재실측으로 바뀌고, 계량기는 나중에 달 수 있고,
> 참조 항목·계량기 공유 상대도 바뀔 수 있다. 이 값들이 과거 회차에 소급 적용되면
> **이미 발행해 임차인에게 보낸 청구서와 시스템 값이 어긋난다.**
> 확정된 회차는 그때의 설정으로 계산된 결과를 그대로 보존한다.

- 확정 후 PAY-10은 **읽기 전용**이며 스냅샷을 표시한다. 현재 설정으로 다시 계산하지 않는다
- **확정은 청구 건을 만들지 않는다.** 청구 건 생성과 원장 `청구` 거래 기록은 청구서 발행 시점이다 → PAY-1

**확정 해제**

| 시점 | 해제 | 정정 방법 |
|---|---|---|
| 청구서 발행 전 | **가능.** 스냅샷을 폐기하고 미확정으로 되돌린다 | 값을 고치고 다시 확정 |
| 청구서 발행 후 | **불가** | 발행된 청구를 정정한다 → PAY-5 |
| 월 마감 후 | **불가** | 마감을 먼저 해제한다 → PAY-11 |

해제는 이력에 기록한다. 발행 후 해제를 막는 것은 **이미 나간 청구서를 시스템이 뒤에서
바꾸지 않기 위해서다.** 원장 우선 원칙과 같다 → 2부

**미확정 회차가 있을 때의 설정 변경**
- 건물 관리비 탭(PRO-3)에서 배분에 영향을 주는 값을 바꾸면 **미확정 회차의 산출이 즉시 바뀐다**
- 영향 항목: 임대면적 · 배분 기준 · 계량기 보유 유닛 · 계기배율 · 계량기 공유 · 참조 항목
- **변경 전 경고한다.** 해당 건물에 미확정 회차가 있으면 영향받는 회차를 명시하고 확인을 받는다

```
「카리나빌딩의 2026-09 정산이 미확정 상태입니다.
  501호의 임대면적을 변경하면 해당 회차의 부담 비율이 다시 계산됩니다.」
```

- **미확정 회차에 검침값이 있는 유닛은 계량기 보유 유닛에서 뺄 수 없다.** 검침값을 먼저 지운다 → 4.1.3-3

**주기**
- 정산 주기는 항목마다 다르다 (예: 전기요금 매월 / 수도요금 격월 / 교통유발부담금 연1회 / 정화조청소비 반기)
- 격월 또는 연 1~2회 발생 항목은 청구 주기를 사전 고정하지 않고 **해당 회차에서 항목을 추가해 정산한다**

**주차비**
- 배분 기준이 `직접 입력`이다 → 4.1.3-2
- 방문 차량 요금은 경비원이 현장에서 계산한 결과를 유닛별 월 합계 금액으로 입력한다
- [2차] 입·출차 시간 기록과 시간제 자동 계산은 주차 관제 연동 시 검토한다

**범위 밖**
- [2차] 세금계산서·계산서 발행과 은행 입금 자동 확인은 초기 오픈 범위에서 제외한다. 청구 내역서를 임차인 담당자 이메일로 발송하는 것까지가 초기 오픈 범위다

### 【설계 의도】

- 본 업무는 단일 계약 정보만으로 금액 산출이 불가능하다. 동일 건물 내 타 유닛의 면적과 검침값이 필요하다
- **입력 중 화면 위치가 유지되어야 한다.** 검침값·배율은 유닛 수만큼 연속 입력하므로
  한 칸을 채울 때마다 화면이 이동하면 작업이 불가능하다
- 검침 원본을 보존하는 이유는 금액 산출 근거의 추적과 조정 해제를 가능하게 하기 위함이다
- 정산 미확정은 해당 월 청구서 미발행으로 이어지므로 대시보드 최상단에 표시한다 → DASH-1

### 【연관 화면】 PRO-3, PRO-4, PAY-3, CTR-3, DASH-1, REC-1
### 【알림】 없음 / 내부 — 정산 확정 결과, 검증 불일치 경고

## PAY-11 · 월 마감

**목적** 건물 × 월 단위로 장부를 마감해 이후 거래 변경을 차단한다. 건물 하나를 골라 달마다 마감 상태를 보고 마감한다.
**사용자** 슈퍼관리자
**진입 경로** 메인 메뉴 → 월 마감 / PAY-12 월 마감 칸 / DASH-1 마감 대기 카드

> 원장을 기록 중심으로 운용하면 취소 거래를 되돌릴 수 없다. 과거 회차를 수정하면 이미
> 산출한 임대인 보고서와 어긋나므로, 월 단위로 장부를 잠근다.

### 【입출력 항목】

```
필터: 건물(단일 선택). 기본값은 담당 건물 중 첫 건물
      옆에 안내: `2026년 7월이 마감을 기다립니다` / `마감할 달 없음 · 2026년 8월은 진행 중`

[상단 버튼]  월 마감 보고서 발행(선택 N건)   ※ 체크한 달이 없으면 비활성

[달 목록]  이 건물의 최근 3개월. 최근 달이 위
  선택 체크박스(마감한 달만), 청구년월, 정산상태, 청구서(발행 N / 대상 N), 청구액, 수납액, 이 달 청구분 미납,
  마감(마감 / 열림 / 진행 중), 마감일시·마감자, 버튼
  버튼   열림 → `마감` / 마감 → `마감 취소` / 진행 중(청구서 발행 전) → `마감` 비활성

[마감 실행시]   끝나지 않은 항목이 있으면 목록을 보여주고 확인 문구. 모두 끝났으면 안내만
[마감 취소시]   취소 사유    ※ 필수. 입력 전에는 버튼이 눌리지 않는다

[월 마감 보고서]  체크한 달마다 PDF 한 부
  건물고유이름, 청구년월, 마감일시·마감자,
  청구서 발행 건수, 청구액, 수납액, 이 달 청구분 미납,
  다음 달로 넘어가는 미납(계약별: 계약고유이름, 미납액, 연체일수)
```

### 【동작 규칙】

**마감 단위**
- **건물 × 월 단위로 마감한다.** 건물마다 임대인과 운영계좌가 다르므로 건물 단위가 기준이다
- 마감 시 해당 건물의 그 월 원장 거래가 잠긴다

**마감 효과**

| 마감 후 차단되는 행위 | 대응 화면 |
|---|---|
| 해당 월 청구의 무효 처리·재발행 | PAY-5 |
| 해당 월 수납의 무효 처리·배분 재조정 | PAY-9 |
| 해당 월 정산 내용 수정 | PAY-10 |
| 해당 월 원장 거래 추가 | CTR-3 |

- 마감 후 정정이 필요하면 **당월에 조정 거래로 처리한다.** 과거 월을 소급 수정하지 않는다

**마감 전 확인**
- 미해결 항목이 있으면 경고를 표시한다. 강제로 차단하지는 않으며 관리자가 판단한다
- 정산 미확정 회차가 있으면 해당 월 청구서가 발행되지 않은 상태이므로 특히 주의한다

**마감 취소**
- **슈퍼관리자만 수행하며 사유 입력이 필수다**
- 마감·마감 취소 모두 이력에 기록한다(일시, 관리자, 행위, 취소 사유) → 3.6
- **이 화면에는 이력을 보여주지 않는다.** 슈퍼관리자가 변경 이력(REC-1)에서 확인한다

**권장 순서**
```
정산 확정(PAY-10) → 청구 발행 → 수납 기록 → 미납 확인(PAY-2)
→ 임대인 보고서 발송(REP-1) → 월 마감(PAY-11)
```

### 【설계 의도】

- 취소 거래는 삭제할 수 없으므로 잘못된 취소가 누적되면 원장 가독성이 떨어진다. 마감으로 정정 가능 기간을 제한한다
- 임대인 보고서를 발송한 뒤 과거 수치가 변경되면 신뢰 문제가 발생한다
- 건물 단위로 본다. 관리자는 보통 건물 두어 개를 맡으므로 자기 건물의 달 목록이면 충분하다.
  여러 건물을 한꺼번에 보는 일은 청구·수납 현황(PAY-12)의 월 마감 칸으로 한다
- 달마다 행에 `마감` 버튼을 둔다. 누군가 마감을 확정해야 장부가 잠기기 때문이다.
  끝나지 않은 일은 목록에 늘어놓지 않고, `마감`을 눌렀을 때 확인 창에서 한 번 보여준다
- 월 마감 보고서는 **마감한 달만** 발행한다. 잠긴 숫자라 언제 다시 뽑아도 같다.
  임대인 보고서(REP-1)는 임대인에게 보내는 운영 보고이고, 월 마감 보고서는 그 달 장부를 닫은 결과를 남기는 내부 기록이다
  건물마다 납부마감일이 달라(익월 10일 등) 같은 달이라도 마감 시점이 다르다

### 【연관 화면】 PAY-2, PAY-5, PAY-9, PAY-10, REP-1, DASH-1
### 【알림】 없음 / 내부 — 마감 결과, 마감 취소 발생
