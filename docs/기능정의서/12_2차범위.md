# 8. 2차 범위

본 장은 1차 개발에서 제외한 범위를 정리한다. **2차 항목은 세부 명세를 확정하지 않는다.**
1차 운영 결과를 근거로 2차 착수 시점에 다시 검토한다.

| 구분 | 수량 |
|---|---|
| 2차 이관 화면 | 42개 |
| 1차 화면 내 2차 항목(탭·필드·기능) | 16건 |
| 기능정의서에 없던 신규 필요 기능 | 3건 |

---

## 8.1 이관 기준

| # | 기준 | 적용 |
|---|---|---|
| 1 | 월 단위 업무 완결성 | 없어도 월 주기(정산 → 청구 → 수납 → 보고 → 마감)가 완결되는 기능은 2차 |
| 2 | 외부 서비스 의존 | PG·알림톡·세금계산서 발행 등 외부 계약·심사가 필요한 기능은 2차 |
| 3 | 부분 구현 시 이중 관리 | 일부만 전산화하면 엑셀과 병행 관리하게 되는 기능은 전체를 2차 |

## 8.2 2차 이관 화면 — 42개

| 영역 | 화면 수 | 기준 | 1차 대체 수단 |
|---|---|---|---|
| 임차인 포털 (TEN) | 12 | 1 | 관리자가 대행. 청구서·미납 안내는 이메일 발송 |
| 알림 센터 (NTF) | 13 | 2 | 이메일 8종. 발송 결과는 NTF-6에서 확인 |
| 임대인 포털 (OWN) | 7 | 1 | REP-1 보고서를 PDF·메일로 전달 |

| 수납 자동 처리 (PAY-7) | 1 | 2 | 은행 거래내역 업로드 + 별칭 매칭 (PAY-13) |

### 8.2.1 임차인 포털 (TEN) — 12개

| ID | 화면명 |
|---|---|
| TEN-1 | 계약 정보 조회 |
| TEN-2 | 수납 내역 조회 |
| TEN-3 · TEN-4 · TEN-5 | 요청 목록 조회 · 요청 등록 · 요청 상세 조회 |
| TEN-6 · TEN-7 · TEN-8 | 공용 시설 예약 · 예약 내역 확인 · 예약 상세 조회 |
| TEN-9 | 받은 알림 목록 조회 |
| TEN-10 · TEN-11 | 공지 목록 조회 · 개별 공지 조회 |
| TEN-12 | 정보 수정 요청 |

**착수 시 결정 사항**
- 포털 사용자는 임차인(사업자)이 아니라 **담당자**다. 담당자 교체 시 계정 이관 방식
- 한 계약에 담당자 복수 계정을 허용할지, 담당자별 열람 범위를 나눌지
- 한 사업자가 여러 계약을 보유한 경우 계약 간 전환 방식
- 12개 항목의 축소 범위. 요청(TEN-3~5)·예약(TEN-6~8)은 REQ·RES 계열의 도입 여부에 종속
- 1차에 생성된 담당자 계정(로그인 미지원)의 초대 메일 발송 시점

### 8.2.2 알림 센터 (NTF) — 13개

| ID | 화면명 |
|---|---|
| NTF-1 · NTF-2 · NTF-3 | 공지 목록 조회 · 공지 등록 · 공지 상세 조회 |
| NTF-4 · NTF-5 | 알림 목록 조회 · 개별 알림 조회 |
| NTF-7 | 알림 직접 발송 (수동) |
| NTF-8 ~ NTF-11 | 템플릿 목록 조회 · 등록 · 상세 조회 · 미리보기 |
| NTF-12 ~ NTF-14 | 발송 알림 규칙 목록 조회 · 등록 · 상세/수정 |

**착수 시 결정 사항**
- 알림톡 채널 도입 여부. 발신 프로필 심사와 템플릿 사전 승인 일정
- 1차 이메일 8종의 본문을 코드에 고정할지 템플릿 관리 화면으로 옮길지
- 자동 발송 규칙의 범위(납부 안내·미납 안내·계약 만료 안내 등)
- 수신 거부 처리. 청구서는 수신 거부 대상에서 제외할지
- 공지(NTF-1~3)는 포털이 전제이므로 TEN·OWN과 함께 판단

### 8.2.3 임대인 포털 (OWN) — 7개

| ID | 화면명 |
|---|---|
| OWN-1 | 건물 및 유닛 정보 조회 |
| OWN-2 | 위임 계약서 조회 |
| OWN-3 | 계약 정보 조회 (임대인 전용) |
| OWN-4 · OWN-5 | 공지 목록 조회 · 개별 공지 조회 |
| OWN-6 | 요청 현황 조회 |
| OWN-7 | 보고서 조회 |

**착수 시 결정 사항**
- 공동소유 건물의 열람 범위. 지분별로 금액을 분할 표시할지 건물 전체를 공유할지
- 임차인 정보(상호·임대 조건)의 공개 범위
- 보고서(OWN-7)를 확정본만 공개할지. 월 마감(PAY-11) 이후 공개를 원칙으로 검토
- 위임 계약서(OWN-2)는 건물 단위로 관리하므로 건물별 열람으로 구성

### 8.2.4 공용시설·예약 (RES) — 4개

| ID | 화면명 | 비고 |
|---|---|---|
| RES-1 · RES-2 | 공용 시설 조회 · 상세 조회 | PRO-3 요약탭(공용시설)에 흡수됨. 항목 존치 여부부터 판단 |
| RES-4 · RES-5 | 예약 관리 조회 · 예약 설정 | 저장 테이블 부재 |

원문에 RES-3은 존재하지 않는다.

**착수 시 결정 사항**
- 기능 도입 여부. 회의실 등 예약 대상 공용시설이 실제로 운영되는지
- 도입 시 예약 단위(시간·일), 유료 여부, 유료인 경우 청구항목과의 연결

### 8.2.5 요청 관리 (REQ) — 3개

| ID | 화면명 |
|---|---|
| REQ-1 | 요청 사항 조회 |
| REQ-2 | 요청 등록 (관리자 전용) |
| REQ-3 | 요청 상세 조회 |

**함께 이관된 1차 화면 내 항목**: PRO-3 요청탭 · PRO-4 요청이력 · CTR-3 요청내역탭 · USER-7 요청탭 · USER-9 요청탭 · DASH-1 요청 카드 · REP-1 수선 요청 처리 현황

**착수 시 결정 사항**
- 요청 유형의 상업용 재정의(민원/제안/문의/수선 → 시설·설비 중심)
- 출처 3종(임차인요청/임대인요청/대면요청)과 처리상태 5종의 유지 여부
- 담당자 배정, 처리 기한, 완료 확인 흐름
- **수선 이력은 원상복구 정산과 분쟁의 근거가 된다.** 포털 없이 관리자 등록(REQ-2)만 먼저 도입하는 방안을 우선 검토
- 이력 대상 종류(REC-1)에 `요청` 추가

### 8.2.6 권한 관리 (USER) — 2개

| ID | 화면명 |
|---|---|
| USER-4 | 사용자 역할 조회 |
| USER-5 | 사용자 역할 등록 |

**착수 시 결정 사항**
- 권한 단위. 1차에 구현한 담당 건물 배정(USER-3)과 기능별 권한의 조합 방식
- 1차에서 슈퍼관리자 전용으로 둔 기능(월 마감 취소, 계약 삭제, 청구항목 관리)의 위임 가능 여부
- 착수 시점은 관리 인원이 복수가 되는 때

### 8.2.7 수납 자동 처리 (PAY-7) — 1개

PG사 웹훅으로 가상계좌·카드 입금을 수신해 시스템이 수납 기록을 자동 생성한다. **사용자는 시스템이다.**

**1차 검토에서 확정한 사항** — 2차 착수 시 그대로 적용한다.

| 항목 | 내용 |
|---|---|
| 구조 | 가상계좌는 계약당 1개. 입금이 계약 단위로 수신되므로 입금 1건 : 배분 N건 구조에 그대로 부합. 매칭 과정 불필요 |
| 배분 | 수동 수납과 동일 규칙 → 4.3 |
| 중복 방지 | **PG 거래번호를 유일값으로 두고 기존 거래번호 수신 시 무시.** 웹훅은 응답 실패 시 재전송되므로 미처리 시 동일 입금이 이중 기록 |
| 처리자 | `admin_system`으로 기록. null 불가 |
| 트랜잭션 이력 | 수신일시 · 웹훅 원문 · 처리결과(정상/중복무시/오류) · 오류사유를 별도 보관 |
| 수정 제한 | 메모 외 수정 불가. 무효 처리는 사유 입력 시에만 → PAY-9 |

**PG사 선정 체크리스트**

```
□ 가상계좌 발급 단위    계약당 고정 계좌인가, 건별 일회성인가
□ 부분입금 허용         청구액 미만 입금이 가능한가 (불가 시 부분납 처리 불가)
□ 입금자명 전달         가상계좌 입금 시 실제 입금자명이 전달되는가
□ 웹훅 재전송·멱등키    중복 방지를 PG가 지원하는가
□ 수수료               가상계좌 건당 / 카드 요율
□ 정산 주기            입금일부터 실제 계좌 입금까지의 기간
□ 테스트 환경          개발·검증용 샌드박스 제공 여부
□ 정산 계좌 요건 ★     건물마다 운영계좌가 다르다. 단일 가맹점에서 건물별 계좌로 분리 정산이
                      가능한가. 불가 시 건물마다 가맹점을 개설해야 하며 수수료·계약 조건에 영향
```

## 8.4 신규 필요 기능 — 3건

기능정의서에 항목이 없는 업무다. 전환 검토 중 도출했으며 기준 3에 따라 2차로 편성했다.

### 건물 비용 관리

| 항목 | 내용 |
|---|---|
| 배경 | 시스템에 지출 데이터가 전무하다. 임대인 보고서(REP-1)가 수입만 제시하고 손익을 제시하지 못하는 원인 |
| 대상 | 청소·경비 용역비, 승강기 유지보수비, 수선비, 재산세, 보험료, 관리인 급여, 공과금 건축주 부담분 |
| 2차 이관 사유 | 일부 항목만 입력하면 시스템과 엑셀을 병행 관리하게 되어 양쪽 모두 불완전해진다 |
| 1차와의 접점 | PAY-10의 `공실·미청구분`은 건축주 부담 공과금으로 비용에 자동 반영 가능 |

**착수 시 결정 사항**: 비용 항목 목록 · 거래처 관리 여부 · 세금계산서 수취 관리 · 지급 처리와 증빙 · 건물별·임대인별 수지 산출 · 월 마감(PAY-11)의 잠금 대상에 비용 포함 여부

### 임대인 정산·송금

| 항목 | 내용 |
|---|---|
| 배경 | 위탁 운영 방식은 두 가지다. ① 임대인 직수취 — 임대인 통장으로 수취, 임대인이 위탁사에 수수료 지급 ② 위탁사 수취 후 정산 — 위탁사 통장으로 수취, 수수료를 제외하고 임대인에게 송금 |
| 1차 전제 | **현 운영 모델은 ①이다.** 건물운영계좌가 곧 임대인 계좌이므로 정산·송금이 불필요 |
| 2차 대상 | ② 지원에 필요한 정산서 산출, 송금 기록, 관리 수수료 청구·수납 |

**착수 시 결정 사항**: 정산 주기 · 정산식(수입 − 비용 − 수수료)의 비용 범위(건물 비용 관리에 종속) · 공동소유 건물의 지분별 송금 · ②를 운용하는 건물이 실제로 발생하는 시점에 착수

### 서비스 운영 기능

| 항목 | 내용 |
|---|---|
| 배경 | 1차는 운영사 3개를 시스템 운영자가 직접 생성해 운용한다. 외부 운영사를 수임하면 운영 업무가 발생한다 |

## 8.5 착수 판단 기준

2차 항목의 우선순위는 1차 운영 데이터를 근거로 결정한다.

| 항목 | 착수 판단 신호 |
|---|---|
| PG 연동 (PAY-7) | 은행 거래내역 매칭의 수작업 부담이 관리 건물 증가로 한계에 도달. 미매칭 비율로 판단 |
| 알림톡 (NTF) | 청구서·미납 안내 이메일의 미확인으로 인한 납부 지연이 반복 |
| 요청 관리 (REQ) | 수선 이력 부재로 원상복구 정산 또는 분쟁에서 근거 제시가 곤란한 사례 발생 |
| 권한 관리 (USER-4·5) | 담당 건물 배정만으로 구분이 부족해져 기능별 권한이 필요 |
| 임대인 포털 (OWN) | 보고서 메일 전달 외에 임대인의 상시 조회 요구가 발생 |
| 임차인 포털 (TEN) | 청구 내역·납부 현황에 대한 임차인 문의가 관리자 업무를 압박 |
| 건물 비용 관리 | 임대인이 수지 보고를 요구하거나 비용 엑셀 관리의 부담이 증가 |
| 임대인 정산·송금 | 위탁사 수취 방식으로 운영하는 건물을 수임 |
| 공용시설 예약 (RES) | 예약 대상 공용시설을 실제로 운영하게 되는 시점 |
| 서비스 운영 기능 | 외부 운영사를 수임하기로 결정. 1차 운용 1년의 결과로 판단 |
