## 2. 문체 규칙 ★ 가장 중요

가장 여러 번 수정이 필요했던 부분이다. 아래 규칙을 먼저 지킨다.

### 2.1 종결 어미

| 용도 | 형태 | 예 |
|---|---|---|
| 본문 서술 | `~합니다` 체 (절제해서 사용) | 기능정의서 72개 항목을 코드와 대조했습니다 |
| 표 셀 · 불릿 | **명사형 종결(개조식)** | `전면 제거` / `호출 0건` / `압축 불가` / `미결` |
| 판단·결정 | 단정형 | 전량 2차 이관, 1차는 대체 수단 적용 |

- 표와 불릿에서는 **`~입니다`를 쓰지 않는다.** 명사로 끝낸다.
- 본문에서도 한 문단이 세 문장을 넘지 않게 한다.

### 2.2 쓰지 말 것 — 실제로 지적받은 단어

| 금지 | 대체 | 이유 |
|---|---|---|
| 함의 | **검토 의견**, 시사점 | 번역투 |
| 결어 | **종합 의견** | 학술문 투 |
| 정합하다 | **맞다**, 일치하다 | 딱딱함 |
| 개략 판정 | **개략적으로 판정** | 명사 남용 |

그 밖에 **구어체 금지**. `~인 셈이다`, `~하는 편이 낫다`, `~라고 볼 수 있다` 같은 표현을 쓰지 않는다.

### 2.3 써도 되는 실무 용어

`편성`(범위 배정) · `이관`(2차 이월) · `미결` · `전가` · `전제` · `부재` · `상이` · `수반`
— 기획·제안 문서에서 통용되는 말이므로 그대로 쓴다.

## 3. 구성 규칙

### 3.1 문서 골격

```
표지        제목 2줄 + 부제 1줄 + 문서정보(보고일/대상/검토범위/수신)
주요 결론 요약   ← 표 1개 + 「핵심 판단」 박스. 첫 화면에서 전체가 보여야 한다
1. 현황      수치 표 → 결함 표(등급 포함) → 유지 자산
2. 판단 근거  비교표 → 핵심 사례 상술 → 반증 사례 → 순서 논리
3. 범위 구분  기준 표 → 1차 표 → 2차 표(기준 번호 참조) → 대체 방안 → 결과
4. 리스크 및 대응   ← 불리한 내용을 숨기지 않는다
5. 향후 일정
```

장 수는 5개를 넘기지 않는다. 넘으면 하위 절로 접는다.

### 3.2 표 중심 — 문단을 표 셀로

설명을 문장으로 풀지 말고 표에 넣는다. **표 1개 = 논점 1개.**

```
(나쁨) 청구서를 생성하는 코드와 입금을 기록하는 코드가 저장소 전체에서
       호출되지 않는다. 청구 목록과 미납 조회 화면은 존재하나…

(좋음) │1│ 청구·수납 기능 부재 │ 청구서 생성 및 입금 기록 코드 호출 0건.
       │ │                    │ 청구 목록·미납 조회 화면은 존재하나 항상
       │ │                    │ 빈 목록. 임대관리 핵심 기능        │ 치명 │
```

기준 산출물은 6쪽에 **표 12개**를 넣고 서술 문단은 최소로 유지했다.

### 3.3 수치는 항상 근거와 함께

```
19개 / 72개 (26%)          ← 분모·비율 병기
1차 45%                     ← 전체 대비 비중
신규 테이블 4종 필요         ← 건수 명시
86개 → 47개 ▼39개 (45% 축소) ← 벤치마킹 원본 방식. 변화량+비율
```

### 3.4 각주

표 아래 `*` 로 단서·예외를 한 줄씩. 본문에 넣지 않는다.

```
* 7개 영역 중 4개 영역에서 신규 테이블 필요. 나머지 3개도 기존 테이블 구조 변경 수반.
* 기준 열은 표 7의 구분 기준 번호.
```

### 3.5 기준 번호 참조

판단 기준을 표로 먼저 세우고, 이후 표에 **「기준」 열**을 만들어 번호를 단다.
근거가 문서 안에서 연결되어 설득력이 올라간다.

### 3.6 리스크 장을 반드시 넣는다

읽는 쪽이 가장 먼저 묻는 내용이다. 빼면 신뢰를 잃는다.
`리스크 → 대응` 2열 표로 5개 내외.

### 3.7 균형

전부 부정적으로 쓰지 않는다. **「유지 자산」 절**을 두어 살릴 수 있는 것을 명시한다.
결함 나열이 목적이 아니라 판단 근거 제시가 목적이다.

## 4. 디자인 규칙

**과하지 않게.** 내용이 우선이며, Google Docs에 붙여 넣어도 형태가 유지되는 수준으로 만든다.

### 쓰지 않는 것
큰 숫자 타일 · 검은 배경 띠 · 색 스트라이프 카드 · 누적 막대 그래프 · 장식용 아이콘

### 토큰

```css
--bg:#FFFFFF        --ink:#1F2226       --ink-soft:#3C4043   --muted:#5F6368
--rule:#CFD3D7      --rule-soft:#E4E7EA --head:#EEF1F3
--accent:#14507C    --accent-bg:#E9F0F5
```

- 서체 **Noto Sans KR** (Google Fonts). 본문 14.5px / 행간 1.75
- 표: 1px 실선 테두리, 머리행 `--head` 배경, 수치 열은 우측 정렬 + `tabular-nums`
- 강조는 `--accent` 굵게 1회용. 본문에 색을 뿌리지 않는다
- 다크 모드 토큰을 `:root:not([data-theme="light"])`와 `:root[data-theme="dark"]` 양쪽에 정의

### 구조 클래스

| 클래스 | 용도 |
|---|---|
| `.cover` | 표지 (제목 + 부제) |
| `.docinfo` | 보고일·대상·검토범위·수신 그리드 |
| `.scroller` | 표 감싸개. 좁은 화면에서 가로 스크롤 |
| `.kbox` | 「핵심 판단」·「검토 의견」·「종합 의견」 강조 박스 |
| `.fn` | 표 아래 각주 |
| `td.lbl` `td.n` `td.c` | 표의 라벨 열 / 수치 우측정렬 / 가운데정렬 |
| `.dn` | 표에서 강조할 값 (accent 색 + 굵게) |

## 5. PDF 생성

### 5.1 인쇄용 HTML 만들기

아티팩트 HTML은 `<!doctype>`·`<html>`·`<head>`가 없는 조각이므로, 로컬 인쇄용으로 감싸야 한다.
`data-theme="light"`를 박아 다크 모드가 섞이지 않게 한다.

```python
head, body = src.split('</style>', 1)
doc = f'''<!doctype html>
<html lang="ko" data-theme="light">
<head><meta charset="utf-8">
{head}</style>
<style>
  html{{-webkit-print-color-adjust:exact;print-color-adjust:exact}}
  @page{{size:A4;margin:16mm 14mm}}
  body{{font-size:10.2pt;line-height:1.62;font-family:"Noto Sans KR","Apple SD Gothic Neo",sans-serif}}
  .doc{{max-width:none;padding:0}}
  h2{{break-after:avoid;page-break-after:avoid}}
  thead{{display:table-header-group}}      /* 표가 쪽을 넘을 때 머리행 반복 */
  tr{{break-inside:avoid;page-break-inside:avoid}}
  .kbox{{break-inside:avoid;page-break-inside:avoid}}
  .scroller{{overflow:visible}}             /* 인쇄에서는 스크롤 해제 */
  table{{min-width:0;font-size:8.8pt}}
  .docinfo{{grid-template-columns:repeat(2,1fr)}}
</style></head>
<body>{body}</body></html>'''
```

### 5.2 Chrome 헤드리스로 변환

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"

"$CHROME" --headless --disable-gpu --no-sandbox \
  --virtual-time-budget=15000 \
  --no-pdf-header-footer \
  --print-to-pdf="출력.pdf" \
  "file:///절대경로/print.html"
```

> ⚠️ **`--no-pdf-header-footer` 를 쓸 것.**
> 구 플래그 `--print-to-pdf-no-header` 는 최신 Chrome에서 **무시되어**
> 날짜·문서제목·`file:///…` 경로가 페이지마다 찍힌다.

> `--virtual-time-budget` 은 Google Fonts(Noto Sans KR) 다운로드를 기다리는 시간이다.
> 너무 짧으면 한글이 시스템 폰트로 대체된다. 12000~15000ms 권장.

### 5.3 검증

```python
from pypdf import PdfReader
r = PdfReader('출력.pdf')
print('페이지 수:', len(r.pages))
bad = [i for i,p in enumerate(r.pages,1)
       if 'file:///' in p.extract_text() or 'print.html' in p.extract_text()]
print('머리말/꼬리말 잔존:', bad or '없음')
```

### 5.4 브라우저에서 직접 인쇄할 경우

아티팩트 본문에도 `@media print` 규칙을 넣어두었다. 단, 머리말·꼬리말은 CSS로 제어할 수 없으므로
인쇄 대화상자에서 **`옵션 더보기` → `머리글 및 바닥글` 체크 해제**가 필요하다.

## 6. 작성 절차

1. **근거 수치를 먼저 확정한다.** 문장을 쓰기 전에 표에 들어갈 숫자를 뽑는다. 추정치는 쓰지 않는다
2. **표부터 짠다.** 논점 하나당 표 하나. 표가 정해지면 본문은 표를 잇는 접착제 역할만 한다
3. **요약을 맨 앞에 쓴다.** 첫 화면에서 결론이 보여야 한다
4. **리스크 장을 채운다.** 불리한 내용을 먼저 적는다
5. **문체를 훑는다.** 2장의 금지 단어와 구어체를 검색해 제거한다
6. **PDF로 뽑아 확인한다.** 표가 쪽을 넘어 잘리는지, 제목만 남고 내용이 다음 쪽으로 가는지 확인
