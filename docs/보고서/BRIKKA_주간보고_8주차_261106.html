표 2. 조정 사유
#사유내용
1명세 확정 범위 확대 v1.5 전달 이후 확정된 명세 변경이 10건으로 늘었습니다. 그중 보증금 처리와 연체료가 데이터베이스 구조를 다시 건드립니다. 보증금은 거래 유형 3종 · 권한 구분 · 관련 화면까지 함께 걸리는 변경입니다. 구조를 확정한 뒤 설계서를 내는 순서로 조정합니다
2시스템 구조 재정비 금액 계산 로직을 데이터베이스 함수에서 애플리케이션 계층으로 옮깁니다. 계산 규칙 검산 테스트를 코드로 관리할 수 있고, 운영 환경을 옮길 때 데이터베이스에 묶이지 않습니다. 임대관리 시스템의 가치가 금액 계산의 정확성에 있으므로 착수 초기에 바로잡는 쪽을 택했습니다

* 두 사유 모두 Phase 1의 개발 범위(35개 화면)를 늘리지 않습니다. 총액과 납품물 목록은 Change Order 1호 그대로입니다.

검토 의견: 조정의 대상은 설계서 확정 시점입니다. Stage 1 납품물 4건 중 데이터베이스 설계서가 위 두 사유에 직접 걸리며, 구조가 바뀌기 전에 낸 설계서는 검수 직후 다시 고쳐야 합니다

핵심 판단

설계서를 예정일에 내는 것보다, 구조가 확정된 설계서를 내는 쪽이 전체 일정에 유리합니다. 데이터베이스 설계서는 검수 후 화면 개발 전체의 기준이 되는 문서입니다. 구조가 바뀌기 전에 낸 설계서는 검수 직후 다시 고쳐야 하고, 그 사이에 쌓인 화면 코드까지 함께 수정 대상이 됩니다. Stage 1 한 달의 조정으로 그 재작업을 없애는 선택입니다. Phase 1 최종 납품일 · 계약 기간 · 개발 범위 · 총액은 모두 변동이 없습니다.

연말 검수 기간
Stage 1 검수 12.15~12.28		 성탄 · 연말 휴일이 포함되어 실제 검토 가능일이 줄어듦. 검수 의견 회신이 늦어지면 화면별 공수 재산정도 함께 밀림 납품물 4건을 12.14에 전량 제출하고, 검수 의견은 1월 8일까지 받는 것으로 운영. 회신이 늦어도 화면 개발은 멈추지 않도록 설계서 기준으로 선행
구조 재정비의 범위
계산 로직 위치 변경		 이미 작성한 코드 일부를 다시 작성. 범위가 예상보다 넓으면 11월 중 구조 확정이 밀림 인증 영역은 영향 없음(완료). 금액 계산기는 검산 테스트를 먼저 만들어 다시 작성해도 계산 결과를 같은 기준으로 검증. 11월 11일 협의에서 범위를 확정
데이터베이스 구조의 반복 수정
보증금 · 연체료 반영이 3번째 수정		 수정이 반복되면 설계서 확정이 다시 밀리고, 그 뒤 화면 코드까지 수정 대상이 됨 12월 14일 설계서 확정 이후에는 구조 변경을 받지 않음. 그 뒤의 명세 변경은 화면 동작 범위로 한정하거나 2차로 이관. Phase 1 최종 납품일을 지키는 전제
운영사 격리
한 시스템에서 여러 운영사의 데이터를 다룸		 격리가 한 곳이라도 빠지면 다른 운영사의 임차인 · 금액이 노출. 사고 범위가 전체로 확대 데이터베이스 수준 격리를 계약 기술 기준에 명시. 격리 자동 테스트를 산출물에 포함해 화면이 늘어도 매번 반복 확인
마스킹 규칙의 일관 적용
계약 종료 5년 경과 후 마스킹		 테이블 한 곳이 아니라 조회 · 검색 · 출력 · 내보내기 전 구간에 걸림. 한 곳이라도 빠지면 개인정보가 그대로 보임 적용 지점을 설계 단계에서 모두 정하고 자동 검증에 포함. 12.14 설계서에 적용 지점을 명시
