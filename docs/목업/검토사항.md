# 목업 검토 사항

목업 제작 중 발견한 명세의 누락·충돌·불일치를 누적한다.
목업이 완료되면 본 목록을 근거로 기능정의서를 일괄 개정한 뒤 번역에 착수한다.

| 상태 | 의미 |
|---|---|
| 미정 | 결정 대기 |
| 확정 | 결정됨. 명세 미반영 |
| 반영 | 기능정의서 개정 완료 |

**기능정의서 v1.1(2026-09-27)에 전건 반영.** #8은 기준표 3.3 표기로 통일했다.
**미결 2건** — #35 계량기 해제 시 기존 검침값, #51 계약 없는 사용중 유닛. 기능정의서 4.7에 등재
**PAY-6 (2026-09-27)** — #59·#61·#62·#63·#64 반영. **미정 #60 · #65**, #66 확정 제안

## PAY-10 관리비 정산

### 1. 절사 차액과 검증 규칙의 충돌 · **반영** (→ #1 종결)

**발견** 유닛별로 원 미만을 절사하므로 (임차인 청구액 + 공실·미청구분)이 고지서 총금액과 일치하지 않는다.
예시 회차에서 전기요금 6원 차이. 유닛 10개면 최대 9원, 청구 항목이 여럿이면 항목마다 발생한다.

**충돌 조항** 4.1.8 및 PAY-10 동작 규칙 — "불일치 시 확정할 수 없다"
절사를 유지하는 한 항상 불일치하므로 정산 확정이 영구 차단된다.

**선택지**
| | 방식 | 비고 |
|---|---|---|
| 가 | 차액을 공실·미청구분에 가산 | 공실이 없는 건물에서는 불가 |
| 나 | 금액이 가장 큰 유닛에 가산 | 어느 건물에서나 가능. 청구 건에 `단수 조정` 기록 |
| 다 | 검증에 허용 오차 (유닛 수 × 1원) | 「정확히 일치」 원칙이 깨짐 |

**제안** (나). 4.2.6 단수 절사액 기록 방식과 동일하게 처리한다.

### 2. 정산 항목이 0개인 회차 · **반영** (→ #13)

**발견** 전기·수도를 고정관리비에 포함해 받는 운영사는 정산할 항목이 없다.

**충돌 조항** PAY-10 — "본 화면의 산출 결과가 확정되어야 해당 월의 청구서를 발행할 수 있다"
정산 대상이 없는 건물은 청구서를 영영 발행할 수 없게 된다.

**제안** 정산 항목이 0개이면 정산 절차를 생략하고 고정액 항목만으로 청구서를 발행한다.
PAY-10 동작 규칙에 단서를 추가한다.

### 3. 고지서 1건에서 청구 항목이 복수로 분리됨 · **반영**

**발견** 한국전력 고지서에는 전기요금·부가세·전력산업기반기금·TV수신료가 함께 표기된다.
그런데 기준표(3.3)에서 **전력기금(16)과 TV수신료(17)는 독립 청구 항목**이며 묶음이
`기타-일반내역서`라 발행 문서가 다르다 (전기요금은 세금계산서).

입력은 고지서 단위로 1회, 청구와 배분은 항목 단위로 분리되어야 한다.

**누락 조항** PAY-10 입출력 항목은 "[전기 추가 입력] 공급가액, 부가세, 전력기금, TV수신료"로만
기재되어 있고, 이 값들이 별도 청구 항목으로 분리된다는 설명이 없다.
4.1.2의 8단계("전력기금·TV수신료도 동일 비율로 환산")가 유일한 단서다.

**결정** 전력기금·TV수신료를 전기요금의 구성 요소가 아니라 **독립 청구 항목으로 취급**한다.
정산 항목 목록에서 각각 선택·입력하며, 배분 기준은 `전기요금과 동일`로 둔다. (2026-09-24, 대표)

**명세 반영 필요**
- PAY-10 입출력 항목에서 "[전기 추가 입력] 전력기금, TV수신료" 삭제
- 4.1.2 8단계를 재기술 — 전력기금·TV수신료는 별도 항목이며 **배분 기준은 `개별 사용량`**.
  전기 검침값을 근거로 배분한다 (해당 항목 자체의 계량기는 없음)
- 기본 선택 항목은 전기요금·수도요금 2종. 그 외는 회차별 추가

### 4. 고지서 총금액은 입력값이 아니라 합계 · **반영**

**발견** 명세는 "고지서 총금액(부가세 포함)"을 입력 항목으로 기재하고 있으나,
실제로는 공급가액·부가세·기금 등을 각각 입력하고 합산한 값이다. 총금액을 따로 입력하면
합계와 어긋날 수 있다.

**결정** 총금액은 입력하지 않고 구성 항목의 합계로 산출한다. (2026-09-24, 대표)

---

### 5. 항목별 고지서 입력 필드가 다름 · **반영**

**발견** 과세 항목(전기·가스·주차비)은 공급가액과 부가세를 나누어 입력하고,
면세 항목(수도·교통유발부담금·정화조청소비)은 금액만 입력한다.
사용량이 없는 항목(교통유발부담금·정화조청소비·주차비)은 총사용량 입력란이 불필요하다.

**결정** 항목의 묶음(과세/면세)과 계량기 유무에 따라 입력 필드를 달리한다. (2026-09-24, 대표)

---

### 6. 건물 청구 설정의 화면 배치 · **반영**

**발견** 정산 화면에 건물 설정(검침분 청구여부·잔여분 부담대상·배분기준)을 표시했으나,
설정은 PRO-3 청구설정탭의 소관이며 매월 확인할 정보가 아니다.

**결정** 정산 화면에서 설정 카드를 제거한다. 배분 기준은 산출 결과의 부제로만 표기한다. (2026-09-24, 대표)

---

### 7. 정산 항목 선택이 첫 단계 · **반영**

**발견** 담당자의 실제 업무 순서는 「이번 회차에 무엇을 정산할지 결정 → 고지서 입력」이다.
기존 화면은 고지서 입력이 먼저였다.

**결정** 1단계를 「항목 선택 + 고지서 입력」으로 합치고 항목 선택을 최상단에 둔다.
건물 기본 설정값이 초기 선택으로 표시되며 회차마다 자유롭게 가감한다. (2026-09-24, 대표)

## 9. 고지서 입력 UI · **반영**

**발견** 항목마다 카드를 따로 두면 세로로 길어지고, 월초에 여러 고지서를 몰아 입력하는
실제 업무와 맞지 않는다.

**결정** 1단계를 **단일 표**로 구성한다. 선택된 항목이 행이 되고 행 안에서 수령일·총사용량·
공급가액·부가세를 입력한다. 소계와 합계는 자동 산출한다. (2026-09-24, 대표)

**부가 결정**
- 고지서 수령일을 입력 항목에 포함한다 (기존 명세에 없음)
- 부가세는 공급가액의 10%로 자동 계산하되 수정 가능. 면세 항목은 입력란을 잠근다
- 항목 추가는 드롭다운, 제외는 행 우측 `×`

## 10. 계량기 없는 항목의 개별 사용량 배분 · **반영**

**발견** 전력기금·TV수신료는 자체 계량기가 없으나 배분 기준은 `개별 사용량`이다.
전기요금의 검침값을 근거로 배분한다.

**명세 공백** 4.1.3 잔여분 배분 기준 선택지는 `자동 / 사용량 비율 / 임대면적 비율` 3종이며,
"어느 항목의 사용량인가"를 지정하는 수단이 없다. 계량기가 없는 항목이 다른 항목의
검침값을 참조하는 경우를 규정하지 않았다.

**결정** 배분 기준이 `개별 사용량`인 항목에 **참조 항목** 속성을 둔다.
자체 계량기가 있으면 자기 검침값을, 없으면 지정한 항목의 검침값을 사용한다.
건물 청구설정(PRO-3)에서 항목별로 지정한다. (2026-09-24, 대표)

**명세 반영 필요**
- 4.1.3 건물·항목별 설정에 `참조 항목` 행 추가
- PRO-3 청구설정탭 입출력 항목에 `참조 항목` 추가
- 4.1.2 8단계를 참조 항목 방식으로 재기술

## 용어

### 11. 「청구 항목」과 「정산 항목」의 관계 미정의 · **반영**

**발견** 두 용어가 문서 곳곳에 혼용되나 관계가 정의되어 있지 않다.

```
청구 항목  기준표 19종 전체 (임대료 · 고정관리비 · 전기요금 · 연체료 …)
정산 항목  그중 산정방식이 「정산」인 항목. 청구 항목의 부분집합
```

3.3 기준표는 `기본 산정방식` 열로 `고정액 / 정산`을 구분할 뿐,
"정산 항목"이라는 명칭을 정의하지 않는다. 해당 용어는 PAY-10에서 처음 등장한다.
개발자가 별개 엔터티로 오인할 수 있다.

**제안** 3.1 용어에 다음을 추가한다.
- **청구 항목** — 청구서에 오르는 항목의 마스터. 기준표 19종과 관리자 추가 항목
- **정산 항목** — 청구 항목 중 산정방식이 `정산`인 것. 사용량·고지서에 따라 회차마다 금액이 달라진다

**화면 표기** 사용자에게는 **「청구 항목」 하나만** 노출한다. (2026-09-24, 대표)
`정산 항목`은 문서상의 분류 용어로만 쓰고 화면에는 쓰지 않는다.
PAY-10의 표 제목은 `이번 회차 청구 항목`, 추가 패널은 `청구 항목 추가`로 표기했다.

## 12. 항목 설정의 소재와 회차별 예외 · **반영**

**발견** 항목 설정이 세 층위로 나뉘나 명세에 정리되어 있지 않다.

| 층위 | 화면 | 정하는 것 | 범위 |
|---|---|---|---|
| 1 | PAY-4 청구 항목 관리 | 이름 · 묶음 · 산정방식 · 부가세 · 우선순위 | 운영사 전체 |
| 2 | PRO-3 청구설정탭 | 사용 여부 · 검침분 청구여부 · 잔여분 부담대상 · 배분 기준 · 참조 항목 | 건물별 |
| 3 | PAY-10 | 이번 회차 정산 여부 | 회차별 |

**문제** 연 1회 항목(교통유발부담금)을 처음 정산할 때 건물 설정이 없으면
PRO-3으로 이동해 설정한 뒤 PAY-10으로 돌아와야 한다.

**결정** **PAY-10에서는 설정하지 않는다.** 정산 대상을 넣고 빼는 것만 수행한다.
매월 반복하는 작업이므로 회차마다 설정을 확인하게 하면 부담이 된다. (2026-09-24, 대표)

- 배분 설정의 정본은 PRO-3 청구설정탭 한 곳이다
- 건물에 설정이 없는 항목은 **임대면적 비율을 기본값으로 적용**하고 `건물 미설정` 배지를 표시한다
- 설정을 바꾸려면 PRO-3으로 이동한다

> 최초 안(PAY-10에서 설정 입력)은 연 1회 항목 추가 시 화면 이동을 줄이려는 의도였으나,
> 매월 반복 작업의 부담이 더 크다고 판단해 철회했다.

## 13. 정산 대상이 0개인 건물 · **반영**

**발견** 전기·수도를 포함한 모든 비용을 고정관리비에 넣어 받는 운영사가 있다.
이 경우 정산할 항목이 하나도 없다.

**결정** 전기요금·수도요금을 포함해 **모든 항목을 정산 대상에서 제외할 수 있다.**
정산 대상이 0개면 정산 절차 없이 고정액 항목만으로 청구서를 발행한다. (2026-09-24, 대표)

검토사항 #2와 같은 사안이며 이로써 확정한다.

## 14. 임차인이 직접 계약한 유닛의 안분 처리 · **반영**

**발견** 1층 상가가 상수도사업본부와 별도 수용가로 계약해 수도요금을 직접 납부하는 경우가 있다.
해당 유닛을 안분에 어떻게 처리할지 명세에 규정이 없었다.

**두 경우를 구분해야 한다**

| | 상황 | 건물 고지서에 |
|---|---|---|
| 가 | 공급자와 직접 계약. 별도 수용가 | **포함되지 않음** |
| 나 | 건물 계량기 내부. 해당 유닛 몫만 따로 정산 | 포함됨 |

(나)는 기존 `검침분 청구함` 설정으로 처리되므로 신규 규칙이 불필요하다.
(가)만 새로운 처리가 필요하다.

**결정** (가)에 해당하는 유닛은 **해당 항목의 안분에서 제외**한다. (2026-09-24, 대표)

- 고지서에 그 유닛 몫이 처음부터 없으므로 배분 모수에서도 빼야 총액이 일치한다
- 배분 기준(사용량·면적)과 무관하게 **가중치 산정에서 제외**하는 것으로 동일하게 처리한다
- 제외 유닛에는 청구 건을 생성하지 않으며 공실·미청구분에도 포함하지 않는다
- 설정 위치는 **PRO-3 청구설정탭**. 유닛의 성질이 아니라 항목의 배분 규칙이므로 항목 쪽에 둔다

## #22 · 조정 배수 적용 위치 — 반영 완료

**문제** 명세 4.1.2는 `정산 사용량 = 개별 사용량 × 조정 배수`로 정하고, 그 값을 잔여 사용량
계산과 배분 가중치에 모두 사용했다. 이 경우 배수를 올린 유닛은 **실측하지 않은 전용 사용량까지
청구받는다.** 계량기가 실측한 값을 시스템이 임의로 부풀리는 셈이라 임차인에게 설명할 수 없다.

**변경** 배수를 **공용 사용량 가중치에만** 적용한다.

```
변경 전   정산 사용량 = 검침 × 배수 → 잔여 = 총 − Σ정산 → 가중치 = 정산 사용량
변경 후   개별 사용량 = 검침 (원본)  → 공용 = 총 − Σ개별 → 가중치 = 검침(또는 면적) × 배수
```

**결과**
- 검침값은 어떤 경우에도 변형되지 않는다
- 공용 사용량 총량이 배수와 무관하게 고정된다. 한 유닛이 더 부담하면 나머지가 정확히 그만큼 덜 부담한다
- 배수의 의미가 "사용량 보정"에서 **"공용부 부담 비율 가감"**으로 바뀐다

## #28 · 조정 배수의 적용 지점이 유닛마다 다르다 — 반영 완료

**발견 경위** 수도요금을 검토하다 드러났다. 영준빌딩 1층은 커피숍이라 물을 많이 쓰고,
그래서 개별 계량기를 달았다. 그런데 수도요금은 `부담 대상 = 검침기 없는 유닛만`이라
**1층은 공용분 배분 대상이 아니다.** 1층의 부담을 키우려 해도 공용 가중치를 올릴 수가 없다.

**규칙** 배수는 **그 유닛이 부담을 지는 곳**에 한 번만 적용한다.

| 유닛 | 적용 지점 |
|---|---|
| 공용분을 부담하는 유닛 | 공용 사용량 배분 가중치 (개별 사용량은 원본 유지) |
| 공용분을 부담하지 않는 계량기 보유 유닛 | 개별 사용량 |

두 대상은 배타적이다. 한 유닛이 양쪽에 걸리지 않으므로 이중 적용이 생기지 않는다.
`부담 대상 = 전체 유닛`인 전기요금에는 후자가 없고, 수도요금에서만 생긴다.

개별 사용량이 늘면 `공용 사용량 합계 = 총 − Σ조정 개별`이 줄어 나머지 유닛 부담도 준다.
고지서 총량은 어느 쪽이든 불변이다.

**화면** 한 표를 유지한다. 두 표로 나눴다가 되돌렸다 — 화면이 규칙의 복잡성을 그대로
비추면 쓰기 어려워진다. `증감` 열이 적용 지점의 차이를 흡수하므로 표를 나눌 필요가 없다 → #32

## #29 · 조정 배수 0 = 부담 없음 — 반영 완료

건물 전체 사용량이므로 공실·비운영중도 부담하는 것이 원칙이나, **건물마다 실무가 달라
회차 단위로 뺄 수 있어야 한다.** 배수를 `0`으로 두면 가중치가 0이 되어 배분에서 빠지고
그 몫은 나머지 유닛이 나눠 갖는다.

안분 제외(4.1.7-2)와 다르다. 안분 제외는 고지서에 그 유닛 사용량이 **처음부터 없는** 경우이고,
배수 0은 **포함되어 있으나 그 유닛에 물리지 않는** 경우다. 전자는 PRO-3 상시 설정,
후자는 PAY-10 회차 설정이다.

**구현 주의 — 실제로 걸렸던 버그.** `mul = adj.mul || 1`은 `0 || 1 → 1`이라
배수 0이 조용히 1.0으로 되돌아간다. `Number.isFinite`로 판별해야 한다.

## #32 · 증감의 기준선 — 반영 완료

조정 탭을 한 표로 되돌리면서 드러난 문제.

`공용 사용량`(조정 전) 열을 **현재 상태에서** 계산하면, 계량기 유닛의 개별 사용량을
올렸을 때 나머지 유닛이 줄어든 것이 증감에 나타나지 않는다. 공용 사용량 합계 자체가
이미 줄어든 값이기 때문이다.

```
101호 배수 1.5 → 개별 78 → 117톤,  공용 합계 542 → 503톤

기준선을 현재로 잡으면   201호  조정전 39.4  ×1.0  증감 —      ← 줄어든 3.1톤이 숨는다
기준선을 배수 1.0으로    201호  조정전 42.4  ×1.0  증감 −3.1   ← 드러난다
```

**기준선은 「전 유닛 배수 1.0」이다.** 그래야 증감 합계가 0이 되고, 그 0이 화면에서
확인 가능한 검산이 된다. 개별 +39.0 과 공용 −39.0 이 상쇄되는 것이 눈에 보인다.

구현은 같은 계산 함수를 배수 1.0으로 한 번 더 돌려 기준선을 얻는다.

## #33 · PAY-10 전 단계의 유닛 목록을 통일 — 반영 완료

## #34 · 공용분 부담 대상을 없앴다 — 정책 변경

**변경** `남은 금액 부담 대상` 설정을 삭제한다. **공용분은 언제나 안분 제외를 뺀 전 유닛이
부담한다.**

**근거** 개별 계량기는 **전용부 사용량을 실측할 뿐 공용부 사용을 면제하지 않는다.**
1층 커피숍에 수도 계량기가 있어도 공용 화장실 급수는 그 계량기를 지나지 않는다.
계량기 보유 유닛을 공용 배분에서 빼면, 그 유닛이 쓴 공용부를 다른 임차인이 대신 부담한다.

**연쇄적으로 사라지는 것들**

| 사라진 것 | 설명 |
|---|---|
| `부담 대상` 설정 (PRO-3) | 선택지 3개 + 자동 규칙 |
| 「배수 적용 지점이 유닛마다 다르다」 규칙 (#28) | 공용분을 안 받는 유닛이 없으므로 불필요 |
| `조정 개별 사용량` 용어 | 개별 사용량은 언제나 원본이다 |
| 3단계의 두 표 분리 | 이미 한 표로 되돌렸으나 근거가 남아 있었다 |
| `배분 대상 0개` 경고 | 발생할 수 없다 |

**규칙이 하나로 줄었다.** 배수는 언제나 공용 사용량 배분 가중치에만 작용한다.

**빠뜨리는 경우가 있는가** 「이 유닛은 공용분을 안 낸다」는 계약이 실제로 있다면
조정 배수 `0`으로 처리한다(#29). 회차 단위로 켜고 끌 수 있어 오히려 유연하다.

**수도요금 결과 변화**

```
이전   101호  개별 78톤만                    155,999원
       나머지 10개가 공용 542톤을 면적 비율로
이후   101호  개별 78톤 + 공용 28.9톤         213,832원
       전체 11개가 공용 542톤을 면적 비율로
```

## #35 · 확정 전 연쇄 재계산은 정상이나, 그 전제가 두 가지를 미정의로 남겼다

**확인된 동작** PAY-10은 **입력값만 저장하고 파생값은 저장하지 않는다.**
저장 대상은 고지서·검침값·검침일·조정 배수뿐이고, 배분 비율·공용 사용량·청구금액은
화면을 열 때마다 계산한다. 그래서 1단계 고지서 총사용량을 고치면 2·3·4단계가 즉시 바뀐다.
**이것이 정상이며 바꿀 이유가 없다.** 산출 결과를 중간 저장하면 입력값과 어긋난 상태가
생기고, 어느 것이 맞는지 판단할 근거가 없다.

### 미정의 1 — 확정 시점의 고정 (반영 완료)

파생값을 저장하지 않는다는 전제는 **확정 후에도 계속 재계산된다**는 뜻이 된다.
임대면적이 재실측으로 바뀌거나 계량기를 새로 달면 **이미 발행한 과거 청구서가 소급해서
달라진다.** 임차인에게 보낸 종이와 시스템 값이 어긋난다.

**확정 시 산출 결과를 스냅샷으로 저장한다.** 적용된 설정(면적·계량기·안분 제외·배수)까지
함께 저장한다. 확정 후 PAY-10은 읽기 전용이며 스냅샷을 표시한다.

확정 해제는 **청구서 발행 전까지만** 가능하다. 발행 후 정정은 원장 조정 거래로 처리한다.

### 미정의 2 — 미확정 회차에 대한 설정 변경 (반영 완료)

PRO-3에서 임대면적·계량기 보유 유닛·안분 제외·배분 기준을 바꾸면 **미확정 회차의 산출이
조용히 바뀐다.** 담당자 A가 2단계까지 검침을 입력해 둔 상태에서 담당자 B가 유닛 면적을
수정하면, A는 자기가 입력하지 않은 변화를 보게 된다. 1차 관리자 5명 환경에서 실제로 발생한다.

**변경 전 영향받는 미확정 회차를 명시하고 확인을 받는다.**

### 남은 미결 — 계량기 해제 시 기존 검침값

계량기 보유 유닛에서 유닛을 뺄 때 이미 입력된 검침값을 어떻게 할 것인가.

| 안 | 결과 |
|---|---|
| (가) 삭제 | 되돌릴 수 없다. 실수로 해제하면 재입력 |
| (나) 보존 · 숨김 | 다시 계량기를 켜면 되살아난다. 다만 계량기 없는 유닛에 값이 남는다 |
| (다) 미확정 회차에 검침값이 있으면 해제 자체를 막는다 | 가장 안전. 담당자가 값을 먼저 지워야 한다 |

확정된 회차의 검침값은 스냅샷에 들어 있으므로 어느 안이든 영향받지 않는다.
**(나) 또는 (다)를 권한다.** 결정 필요.

## #36 · 1단계에 항목 서브탭이 없어 단계마다 화면 구조가 달라졌다 — 반영 완료

2·3·4단계는 항목이 2개 이상이면 서브탭이 뜨는데 1단계는 뜨지 않았다.
단계를 넘길 때마다 화면 구조가 바뀌는 느낌을 준다.

**검토** 1단계도 서브탭으로 바꿔 항목별 입력 화면을 따로 두는 방안을 검토했으나 **채택하지 않았다.**

| 반대 이유 | 설명 |
|---|---|
| 작업 단위가 다르다 | 2~4단계는 유닛이 행, 1단계는 **항목이 행**이다. 이미 항목이 나열되어 있으므로 서브탭은 목록을 세로에서 가로로 옮기고 나머지를 숨길 뿐이다 |
| 합계를 대조할 수 없다 | 하단 합계는 **책상에 놓인 고지서 뭉치의 총액과 대조하는 값**이다 |
| 입력 누락이 보이지 않는다 | 담당자가 확인하는 것은 「고지서 3장을 다 넣었나」다. 검침 입력에서 전 유닛을 표시하기로 한 것과 같은 논리다 → #33 |

**채택** 1단계에도 서브탭을 같은 자리에 두되 **맨 앞에 `전체`를 넣고 기본값으로 한다.**
화면 구조가 네 단계 내내 같아지면서 표와 합계는 그대로 유지된다.
항목이 많아졌을 때만 하나를 골라 집중한다.

`전체`가 1단계에만 있는 것은 근거 있는 차이다. 1단계는 항목이 행이라 전체가 자연스럽고,
2~4단계는 유닛이 행이라 kWh와 톤을 한 표에 섞을 수 없다.

## #37 · 사용량을 재지 않는 항목의 3·4단계 — 반영 완료

정화조청소비를 추가해 전 단계를 시험한 결과다. **계산은 정확했다**(Σ배분 비율 100%,
차액은 절사분 6원). 2단계에서도 검침 대상이 아니므로 정상적으로 빠졌다.
**표시에 두 가지 문제가 있었다.**

**3단계** 단위가 없는 항목이라 고지서 총사용량이 `null`이고, 따라서 공용 사용량이
전 유닛 `0.0`으로 나왔다. **배수를 바꿔도 0 → 0이라 화면에 아무 변화가 없다.**
실제로는 배분 비율과 금액이 바뀌는데 그것을 확인할 수 없었다.

**4단계** `공용 사용량` 열이 전부 `—`로 남아 있었다.

**해결** 단위가 없는 항목은 사용량 열을 **금액 열로 대체한다.**

```
3단계   계약고유명 | 배분 금액 | 면적 비율 | 조정 배수 | 증감 | (조정후) 배분 금액
4단계   계약고유명 | 배분 비율 | 청구금액                    ← 사용량 열 없음
```

```
정화조청소비 880,000원 · 101호 ×2.0 · 공실 401·402호 ×0
  101호    46,949원  5.34%  ×2.0  +55,391원   102,340원
  201호    65,229원  7.41%  ×1.0   +5,864원    71,093원
  401호    65,229원  7.41%  ×0.0  −65,229원    부담 없음
  합계    879,994원           1원   879,995원
```

**남은 것** 금액 열은 원 미만 절사가 누적되어 증감 합계가 0에서 1~2원 어긋난다.
사용량 열(소수 유지)에서는 정확히 0이다. 검토사항 #1과 같은 뿌리이며 화면에 명시했다.

## #1 종결 · 절사 잔차 처리 — 반영 완료

**문제** 유닛별로 원 미만을 절사하므로 합계가 고지서보다 몇 원 적다(유닛 11개면 최대 10원).
명세 4.1.8은 「불일치 시 확정할 수 없다」고 정하고 있어 **확정이 영구 차단**되었다.
목업에서 전기요금 5원, 수도요금 7원, 정화조청소비 6원이 계속 검증 불일치로 떴다.

**결정 — 잔차를 배분 비율이 가장 큰 유닛에 더한다.**

```
잔차 = 고지서 총금액 − Σ 유닛 청구금액(절사 후)      언제나 0 이상
대상 = 안분 제외를 뺀 유닛 중 배분 비율이 가장 큰 유닛. 동률이면 정렬 순서가 앞선 유닛
표시 = 산출 결과의 해당 행에 「절사 +5원」
```

| 안 | 채택 여부 |
|---|---|
| **최대 몫 유닛에 가산** | ✅ 결정적이다. 규칙이 한 줄이고, 큰 몫을 받는 유닛이 부담하는 것이 설명하기 쉽다 |
| 최대 잔여법 | 가장 공평하나 매월 대상이 바뀌어 설명이 어렵다. 몇 원을 위한 복잡성으로 과하다 |
| 건축주(공실·미청구분)에 가산 | 공실이 없으면 성립하지 않아 규칙이 둘이 된다 |
| 검증을 ±N원까지 허용 | 원장 합계가 고지서와 어긋난다. 회계상 불가 |

**반올림을 쓰지 않는다.** 반올림하면 합계가 고지서를 초과할 수도 있어 잔차 부호가
양·음 양쪽으로 생긴다. 절사로 고정하면 언제나 부족하므로 더하기만 하면 되고,
임차인에게 과다 청구되는 경우가 원천적으로 없다.

**부수 효과** 검증 규칙이 살아났다. 잔차를 배분했으므로 정상적인 경우 언제나 일치하고,
**검증에 걸린다는 것은 절사가 아니라 실제 오류라는 뜻**이 된다. 안전장치로서 의미를 갖는다.

금액 모드(#37)의 증감 합계도 잔차 배분 후 값을 쓰므로 정확히 0이 된다.

## #38 · 접이식 그룹 목록은 `<table>`로 만들지 않는다 — 반영 완료

**증상** PAY-1에서 계약 그룹을 펼치면 그룹 행의 열이 항목 행과 어긋나고, 행 오른쪽 절반에
셀이 없어 **그 영역을 눌러도 접히지 않았다.**

**세 번 실패했다**

| 시도 | 결과 |
|---|---|
| 그룹 행을 `colspan="5"`로 묶음 | 항목 행이 정한 열 너비와 충돌. 그룹 셀이 왼쪽으로 몰림 |
| `colspan` 제거, 빈 `<td>`로 7칸을 맞춤 | 여전히 어긋남 |
| `table-layout: fixed` + `<colgroup>` | 여전히 어긋남 |

마크업은 매번 유효했다(모든 행 7칸, 열 합계 일치). 그런데도 브라우저에서 어긋났다.

**해결 — 표를 버리고 그리드 목록으로.**

```css
.schr{display:grid;
  grid-template-columns:minmax(200px,1fr) 84px 72px 104px 58px 128px 118px}
```

그룹 행·항목 행·머리글·합계가 **모두 같은 `.schr`** 을 쓴다. 표 레이아웃 알고리즘이
개입하지 않으므로 열이 어긋날 수가 없고, 각 행이 컨테이너 전체 폭을 차지하므로
클릭 영역 문제도 함께 사라진다.

**규칙** 접었다 펴는 그룹 목록은 모두 이 방식을 쓴다. 성격이 다른 두 종류의 행을
한 `<table>`에 섞지 않는다.

## #39 · PAY-1을 청구 약정 조회에서 청구서 발행으로 — 화면 성격 변경

**두 가지가 동시에 드러났다.**

**① PAY-1에 할 일이 없었다.** 약정의 등록·수정은 계약 상세(CTR-3)에서 하고 조회도 거기서 된다.
PAY-1은 조회 전용이라 열어서 확인하는 것 말고 할 수 있는 동작이 없었다.

**② 월 업무 주기 ④단계에 대응하는 화면이 없었다.**

```
③ 정산 확정 → 청구 생성   PAY-10
④ 청구서 발송            ← 화면 ID가 비어 있었다
⑤ 입금
```

PAY 화면 11개를 확인한 결과, 생성된 청구서를 **모아서 확인하고 발행하는 화면이 어디에도
없었다.** PAY-10은 정산 부분만 만들고, PAY-2는 미납된 것만 보고, PAY-5는 발행 후 수정이다.
매월 19일에 열어야 할 화면이 없었던 것이다.

**해결 — PAY-1을 ④단계 화면으로 바꾼다.** 화면 수는 그대로다.

```
계약 × 청구년월 = 청구서 1장
  고정액 항목   근거 「약정」     ← 계약의 청구 약정에서
  정산 항목     근거 「2026-09」  ← PAY-10 확정 결과에서
```

**잃는 것이 없다.** 각 항목 행의 `산정방식`과 `근거`가 그 금액이 약정에서 왔는지 정산에서
왔는지 보여주므로, 약정 확인은 회차 맥락 안에서 그대로 된다.
항목 단위 횡단 조회(「주차비를 받는 계약이 몇 개인가」)만 전용 화면을 잃는데,
계약이 수십 건을 넘을 때 필요해지는 기능이라 2차로 미룰 수 있다.

**발행 게이트** 해당 건물·회차의 정산이 `확정`이 아니면 발행을 막는다.
PAY-12의 `정산 확정` 상태가 여기서 실효를 갖는다.
고정액만 있는 건물은 정산 없이 발행한다.

## #40 · 「미산출」이 서로 다른 두 가지를 뭉쳐놓고 있었다 — 반영 완료

PAY-1 청구서 발행에서 계약마다 `미산출` 수가 달랐고 의미를 알 수 없었다.
확인해 보니 **두 가지가 섞여 있었다.**

```
501호 미산출 3
  정화조청소비(반기)    ← 이번 회차 대상이 아니다. 정상
  교통유발부담금(연1회)  ← 이번 회차 대상이 아니다. 정상
  주차비(매월)         ← 이번 회차 대상인데 금액이 없다. 확인 필요
```

정상인 격월·반기 항목 때문에 **진짜 누락이 묻혔다.** 그리고 `미산출`이 상태 열을
차지하고 있어 상태가 셋처럼 보였으나 실제로는 둘이었다.

**분리**

| 구분 | 판정 | 표시 |
|---|---|---|
| 해당 없음 | PAY-10 1단계에서 선택되지 않은 항목 | **화면에 올리지 않는다** |
| 미산출 | 선택되었으나 금액이 없음 | 경고색. `고지서 금액 미입력` |

처음에는 해당 없는 항목을 흐리게 표시해 「이번 달엔 수도요금이 없구나」를 확인할 수 있게
하려 했으나 **철회했다.** 그 확인은 PAY-10 1단계에서 이미 끝났고, 발행 화면에서 다시
보여주면 **실제 청구서에 없는 줄을 보여주게 되어** 미리보기·발행물과 어긋난다.

```
PRO-3 관리비 설정   이 건물이 쓰는 청구 항목을 정의
      ↓
PAY-10 1단계       이번 회차에 정산할 항목을 고른다
      ↓
PAY-1 청구서 발행   선택된 것만 올라온다
```

「이번 회차 대상인가」는 **반복주기로 자동 판정하지 않고 PAY-10 1단계의 선택을 따른다.**
검토사항 #31에서 정한 원칙과 같다 — 고지서 수령이 기준이고 판단은 담당자가 한다.

**상태 층위 정리**
- 청구서(계약) 상태 — 배타적 둘: `발행 대기` / `발행 완료`
- 항목 표시 — 둘: `약정`(고정액) / `정산`
- 미산출 — 상태가 아니라 **경고**. 발행을 막지는 않는다.
  고지서가 늦게 도착해 다음 회차에 합산하는 경우가 있기 때문이다

## #41 · 근거 문서를 설정 항목으로 신설 — 반영 완료

PAY-1의 `근거` 열이 `약정` / `2026-09` 같은 **출처 층위**를 보여주고 있었으나,
실무에서 근거란 **금액을 뒷받침하는 문서**다 — 고지서 · 계약서 · 내역서.

```

전기요금    정산   한국전력 고지서          235,387원   2026-09 정산

회차 정보는 비고로 옮겼다.

임차인이 산출 근거를 물으면 이 문서를 보여준다. 근거를 지정하지 않은 항목은 설명할

## #42 · 배분 기준 `직접 입력` 신설 — 반영 완료

## #46 · 「사용분 청구 여부」 설정 삭제 — 배분 기준 4종으로 충분하다

**경위** 금악빌딩(전용부 전기를 임차인이 한전과 직접 계약)이 실제 사례로 확인되어
이 설정이 필요한 줄 알았다. 그러나 그 건물의 처리를 따라가 보니 설정이 필요 없었다.

```
금악빌딩   임차인이 한전과 직접 계약 → 전용부는 임차인이 알아서 납부
           건물은 공용부 고지서만 수령
           → 건물이 나눌 대상은 공용부 전액뿐이다
           → 임차인 계량기를 읽을 이유가 없다. 그 계량기는 한전 것이다
           → 배분 기준 「임대면적」, 계량기 없음. 끝.
```

이 설정이 커버하던 유일한 조합은 **「계량기는 있는데 개별분을 청구하지 않는다」**였다.
그러려면 건물이 남의 계량기를 읽어야 하고 그럴 근거가 없다.
**공용부만 고지된다면 계량기 없이 면적으로 나누면 된다.**

**연쇄 삭제**

| 사라진 것 |
|---|
| PRO-3 `사용분 청구 여부` 설정 |
| 그 자동 판정 규칙 (`계량기가 있으면 청구함`) |
| `ratios()`의 `charge` 분기 — 계량기가 있으면 언제나 개별분을 청구한다 |
| 4.1.2 2단계의 「검침분 미청구 건물은 합계 = 총사용량」 단서 — Σ개별이 0이라 자동 성립 |
| 관리비 설정 표의 `사용분 청구` 열 |

**남은 설정** 발행 문서 · 반복주기 · 배분 기준 · 계량기 보유 유닛 · 근거 문서 ·
(예외) 참조 항목 · 안분 제외 유닛.

**4.1.5 재작성** 예시 2를 계량기 없는 면적 배분으로 바꿨다. 결과는 같고 설정이 단순해졌다.
「일부 유닛만 직접 계약」과의 차이를 다시 명시했다 — 그때는 고지서에 전용부가 섞여
들어오므로 계량기로 가려내거나 안분 제외로 뺀다.

## #47 · 당월 검침값 미입력이 음수 사용량을 만든다 — 반영 완료

가스요금 테스트 데이터를 넣으며 드러났다. 기존 목업은 전기·수도 모두 당월 검침값이
채워져 있어 이 경로를 한 번도 지나지 않았다.

```
개별 사용량 = 당월 − 직전
당월이 null이면  null − 4,820 = −4,820㎥
```

**결과가 조용히 전체를 망가뜨린다.**

```
고지서 1,840㎥ / 2,428,800원
  공용 사용량 합계  1,840 − (−4,820 −1,150 −2,340) = 10,150㎥   ← 부풀었다
  101호 청구금액    −5,647,600원                              ← 음수
  임차인 합계 167,270 + 공실 2,261,530 = 2,428,800원           ← 검증은 통과한다
```

**4.1.8 검증 ①(합계 일치)은 성립한다.** 음수가 다른 유닛의 양수와 상쇄되기 때문이다.
그래서 이 오류는 검증에 걸리지 않고 그대로 청구서가 나간다.

**수정**
- `당월 검침값이 없으면 개별 사용량은 0`. 미입력과 `0`을 구분한다
- 당월 < 직전이면 **경고**. 계량기 교체(0으로 리셋)나 오입력이다
- **4.1.8에 검증 ②③ 추가** — 개별 사용량 ≥ 0, 청구금액 ≥ 0
- 검증 스크립트에 음수 검사 추가

**실무 시나리오** 검침을 하루 만에 다 못 돌면 일부 유닛만 입력된 상태로 화면을 떠난다.
그 상태에서 산출 결과를 보면 지금까지는 엉뚱한 숫자가 나왔다. 이제 미입력 유닛은
개별 사용량 0으로 두고 공용분만 부담하며, 나머지는 정상 계산된다.

## #48 · 청구서 발행 시 미납 잔액 표시 — 반영 완료

**질문** 관리비 정산 다음에 「미납 확정」 단계를 두고, 확정해야 청구서 발행으로 넘어가게
해야 하는가?

**결정 — 확정 단계를 두지 않는다.**

미납액은 `청구액 − 수납액`으로 **원장에서 계산되는 값**이다(명세 07-257).
확정 시점을 두면 확정 후 들어온 입금과 어긋나고, 어느 쪽이 맞는지 판단할 근거가 없다.
같은 이유로 이 프로젝트는 이미 **파생값을 저장하지 않는다**는 원칙을 세웠다 → #35

**대신 청구서 발행 화면에서 확인한다.**

```
⚠ 미납이 있는 계약 2건 · 4,920,000원
  청구서에 별도 안내로 표기됩니다. 청구 합계에는 포함되지 않습니다.  [미납 관리로 이동 →]

  계약고유명        미납 잔액               이번 회차 청구      상태
  202호        1,240,000원 (2026-08~1건)   5,335,326원   발행 대기
  601호        3,680,000원 (2026-07~2건)  11,726,779원   발행 대기
  합계            4,920,000원             73,652,839원
```

**미납은 청구 합계에 넣지 않는다.** 청구서 한쪽에 별도 안내로 적는다. 내역이 다르다.

**세금계산서에는 넣을 수 없다 — 이중 발행이 된다.**
세금계산서·계산서는 그 달 공급분에 대한 증빙이고, 전월 미납은 이미 전월에 발행되었다.
따라서 **임차인에게 보내는 청구 안내서와 세금계산서의 금액이 다를 수 있다.**

```
청구 안내서   이번 회차 5,335,326원  +  [안내] 미납 1,240,000원
세금계산서    이번 회차 과세분만
```

**미납 관리(PAY-2)는 발행 전 관문이 아니라 상시 업무다.** 월 업무 주기 ⑦단계에 명시했다.

## #49 · 부가세 별도와 포함이 한 열에 섞여 있었다 — 반영 완료

PAY-1 청구서 발행에서 청구 합계가 `VAT 별도`로 표시되고 있었다. 실제로는 **두 종류가
섞여 있어 합계 자체가 무의미했다.**

```
임대료    4,280,000원   ← 계약 약정액. 부가세 별도
전기요금    235,386원   ← 고지서 총액(공급 + VAT)을 배분한 값. 부가세 포함
합계      ???          ← 더할 수 없는 값을 더하고 있었다
```

**수정 — 공급가액과 부가세를 분리해 각각 배분한다.**

```
유닛 공급가액 = 고지서 공급가액 × 배분 비율
유닛 부가세   = 고지서 부가세   × 배분 비율
유닛 청구금액 = 공급가액 + 부가세
잔차도 각각 최대 몫 유닛에 더한다
```

합쳐서 배분하면 **유닛별 부가세를 알 수 없어 세금계산서를 만들 수 없다.**
이것만으로도 분리해야 할 이유가 충분하다.

**PAY-1 열 구성**

```
계약고유명 · 청구항목   발행 문서        근거 문서          공급가액      부가세      합계      상태
임대료              세금계산서(과세)  임대차계약서     4,280,000   428,000  4,708,000  약정
수도요금             계산서(면세)    상수도 고지서      213,839         —    213,839  정산 미확정
주차비              세금계산서(과세)  경비실 내역서      100,000    10,000    110,000  정산 미확정
계약 합계                                        5,639,626   542,577  6,182,203
```

한 계약의 청구서 안에 **과세·면세·비과세가 섞인다.** 합계는 셋을 모두 더한 값이며
임차인이 실제로 납부하는 금액이다.

**딸린 버그** 직접 입력 항목(주차비)은 공급가액 입력 경로가 달라 부가세 자동계산이
걸리지 않아 과세 항목인데 부가세가 0이었다. 입력 금액을 공급가액으로 보고 10%를
자동 계산하도록 고쳤다.

## #50 · PAY-10을 단계 축에서 항목 축으로 — 구조 변경

**문제** 화면이 `1 고지서 → 2 검침 → 3 조정 → 4 산출` 네 단계를 가로 네비게이션으로 고정하고,
그 안에서 항목 서브탭을 고르는 구조였다. **항목마다 거치는 단계가 다른데 틀은 하나였다.**

```
전기요금       고지서 → 검침 → 조정 → 산출      4단계
정화조청소비    고지서 → 조정 → 산출            3단계  검침이 없다
주차비         금액 입력 → 산출                2단계  고지서·검침·조정이 없다
```

그래서 예외가 네 군데로 흩어졌다.

| 예외 | 어디 |
|---|---|
| 계량기 없는 항목을 2단계에서 걸러냄 | `stepItems(1)` |
| 3단계 이름은 `조정`인데 직접 입력 항목에서는 금액 입력 화면 | `stAdj` 분기 |
| 1단계에서 직접 입력 항목의 공급가액이 읽기 전용 | `billRow` |
| 4단계 검증이 직접 입력 항목에서는 항상 참 | 4.1.8 |

**변경 — 항목당 한 페이지, 그 항목이 실제로 거치는 단계만 세로로 쌓는다.**

```
[전체] 전기요금  수도요금  가스요금 [미검침 3]  주차비
────────────────────────────────────────────
① 고지서        ② 검침 입력        ③ 조정        ④ 산출 결과
```

단계 번호는 항목마다 다시 매긴다. 주차비의 산출 결과는 ②다.
**예외가 사라지고 그 항목의 모양이 된다.**

**부수 효과**
- 담당자의 실제 작업 단위와 일치한다 — 고지서 받아 검침하고 조정해 결과 확인까지 한 항목 안에서 완결
- 고지서 금액을 고치면 **같은 화면 아래에서** 산출 결과가 바뀌는 게 보인다.
  전에는 1단계에서 고치고 4단계로 이동해야 확인할 수 있었다
- 단계 네비게이션이 사라져 화면이 단순해졌다

**`전체` 탭은 두지 않는다.** 처음에는 기존 1단계 역할로 남겼으나 **철회했다.**
항목 목록만 보여주는 화면은 따로 할 일이 없었다.

| 1단계가 하던 일 | 옮긴 곳 |
|---|---|
| 항목 추가 | 탭 오른쪽 끝 `+ 청구 항목 추가` 버튼 |
| 항목 제외 | 각 항목 페이지의 고지서 절 |
| 고지서 금액 입력 | 각 항목 페이지의 고지서 절 |
| **이번 회차 합계** | **화면 머리글** — 항목을 옮겨 다녀도 늘 보인다 |
| 진행 상황 | 탭의 `✓` 표시 |

**항목 탭 경고** `고지서 미입력` · `미검침 N` · `검침 역전 N` · `미입력`.
어느 항목을 손봐야 하는지 탭에서 바로 보인다.

## #51 · 계약이 없는 사용중 유닛 — **미결**

실제 데이터를 넣으며 드러났다. **본관 B1 「영준복합문화공간」은 건물주가 직접 운영하는
공간이다.** 임차인이 없고 계약도 없지만 공실이 아니며 전기를 실제로 쓴다(2,274.8kWh).

현재 유닛상태는 셋뿐이다 → 3.2

|---|---|---|
| 사용중 | 계약이 있고 운영 중 | 운영 중은 맞으나 **계약이 없다** |

| 비운영중 | 창고·기계실 등 임대 대상이 아님 | 임대 대상은 아니나 **실제로 쓰고 있다** |

- PAY-10 산출 결과에는 나오고 금액이 잡힌다 (758,620원)

**금액 처리는 맞다. 이름이 틀렸다.** 공실이 아닌데 `공실·미청구분`에 들어간다.

**선택지**

| 안 | 내용 |
|---|---|
| (가) 집계 이름만 바꾼다 | `공실·미청구분` → **`미청구분(건축주 부담)`**. 공실·비운영중·직영 공간을 모두 포괄 |
| (나) 유닛상태에 `직영`을 추가한다 | 상태가 넷이 된다. 건물주가 직접 쓰는 공간을 명시 |
| (다) 건물주를 임차인으로 등록해 계약을 만든다 | 청구서가 발행되어 자기가 자기에게 청구하는 형태가 된다 |

**(가)를 권한다.** 상태를 늘리지 않고 집계 라벨만 정확하게 만든다.
직영 공간인지 공실인지는 임차인명으로 이미 구분된다.

## #52 · 정산액 부담 계약(대납) 신설 — 반영 완료

실제 계약 구조에서 드러났다.

```
본관301호 고우컴퍼니    임대료 360,000원만 청구
본관302호 유니버셜      자기 임대료·관리비 + 301호의 정산액까지 부담
                      두 계약의 실질 주인이 같다
```

**기존 수단으로는 표현할 수 없었다.**

| 시도 | 왜 안 되는가 |
|---|---|
| 안분 제외 | 고지서에 301호 사용량이 **포함되어 있다.** 모수에서 빼면 총액이 어긋난다 |
| 가중치 0 | 301호 몫이 **나머지 13곳에 흩어진다.** 302호만 부담하는 결과가 아니다 |
| 301·302를 한 유닛으로 합침 | 물리적으로 두 호실이고 임차인이 둘이다. 임대료를 따로 청구해야 한다 |

**신설 — 계약 속성 `정산액 부담 계약`**

```
산출   유닛 기준으로 정상 계산한다. 안분 모수는 그대로다
청구   산출 결과를 지정된 계약으로 옮긴다
표시   받는 계약의 청구서에 「본관301호|고우컴퍼니 대납」으로 구분해 싣는다
```

```
본관301호|고우컴퍼니   (정산액은 본관302호가 부담)
   임대료                     360,000    36,000    396,000
   합계                       360,000    36,000    396,000

본관302호|유니버셜     (대납 본관301호)
   임대료                   4,620,000   462,000  5,082,000

   합계                     7,185,730   704,783  7,890,513

**고정액은 옮기지 않는다.** 계약 약정액이므로 그 계약에 청구한다.

## #53 · 계기배율 신설 — 배율을 빠뜨리면 조용히 틀린다

**본관1층 에스씨케이컴퍼니의 계량기는 1/30이다.** 지침 차이 336.28에 30을 곱해야
실사용량 10,088.4kWh가 된다.

```
배율 미적용   개별 합 27,591.08   공용 15,500.92 (36.0%)
배율 적용     개별 합 37,343.20   공용  5,748.80 (13.3%)
```

**검증(4.1.8)은 이 오류를 잡지 못한다.** 합계는 어느 쪽이든 고지서와 일치하기 때문이다.
잘못된 쪽에서는 에스씨케이컴퍼니가 실사용량의 1/30만 청구받고 나머지를 다른 임차인이
공용분으로 나눠 부담한다. 본관1층 청구액이 323,343원 → 2,170,582원으로 바뀐다.

**신설 — 계기배율 (유닛 × 청구항목)**

```
지침 차이   당월 − 직전.  원본
계기배율    계량기의 고정 속성. 기본 1
개별 사용량  지침 차이 × 계기배율
```

검침 입력 절에 세 열을 나란히 두어 환산 과정을 보인다.

**가중치와 혼동하지 않는다.**

| | 계기배율 | 가중치 |
|---|---|---|
| 성격 | **물리적 환산** — 계량기가 1/30로 잰다 | **정책적 배분** — 1층이 공용부를 많이 쓴다 |
| 적용 대상 | 개별 사용량 | 공용 사용량 배분 몫 |
| 저장 | 계량기 설정. 상시 | 정산 회차. 회차마다 |
| 바뀌면 | 공용 사용량 합계가 바뀐다 | 합계 불변, 유닛 간 비율만 |

**「가중치를 개별 사용량에 곱하지 않는다」(#28)는 원칙과 충돌하지 않는다.**
계기배율은 실측값을 부풀리는 것이 아니라 **계량기가 축소해 표시한 값을 복원**하는 것이다.

**남은 확인** 본관B1 영준복합문화공간도 지침이 소수(3,161.9 → 5,436.7)다.
배율 30을 적용하면 68,244kWh로 고지서 총량 43,092를 넘으므로 1/30은 아니다.
현재 배율 1로 두었다.

## #54 · 계량기 공유 신설 — 오탐 경고 제거

**본관301호 고우컴퍼니는 302호와 한 공간을 쓰고 전기 계량기가 302호에 하나뿐이다.**
301호 사용분은 302호 지침에 이미 포함되어 있다.

**문제** 301호를 「계량기 없음」으로 두니 `사용량` 기준 경고가 떴다 —
「계량기 없는 유닛의 배분 몫이 0이 되어 다른 유닛이 대신 냅니다」.
**여기서는 배분 몫 0이 정상이다.** 오탐이 뜨면 경고가 무뎌진다(#53의 계기배율처럼
경고가 실제로 작동해야 하는 자리가 있으므로 중요하다).

**신설 — 계량기 공유 (유닛 × 청구항목)**

| | 사용분이 | 사용량 기준에서 | 면적 기준에서 |
|---|---|---|---|
| 계량기 없음 | 공용분에 섞여 있다 | 배분 몫 0 → **경고** | 면적대로 부담 |
| **계량기 공유** | **상대 유닛 지침에 포함** | 배분 몫 0 → **정상** | 면적대로 부담 |
| 안분 제외 | 고지서에 없다 | 모수 제외 | 모수 제외 |

**항목마다 다르다.** 301호는 전기를 공유하지만 수도는 면적 기준이라 자기 몫을 부담하고,
그것을 302호가 대납한다(#52).

```
본관301호|고우컴퍼니          본관302호|유니버셜
  임대료      396,000원        임대료        5,082,000원
  합계        396,000원        고정관리비      1,815,000원
                              전기요금        641,714원
                              수도요금         58,207원
                              수도요금 ← 301호 대납  58,207원
                              합계         7,671,240원
```

**대납 목록에서 0원 항목을 제외했다.** 전기·전력기금·TV수신료는 301호 몫이 0이므로
싣지 않는다. 0원 줄이 쌓이면 무엇을 대납하는지 흐려진다.

## #55 · 변수 가림으로 조정 배율이 무력화되어 있었다 — 반영 완료

계기배율(#53)을 넣으면서 `ratios()` 안에 지역 변수 `raw`(지침 차이)를 만들었다.
그런데 함수 시그니처가 `ratios(m, raw)`이고 **`raw`는 「전 유닛 배율 1.0」 기준선 모드 플래그**였다.

```js
function ratios(m, raw){            // raw = 기준선 모드
  ...
  const raw = typed ? r[1]-r[0] : 0;    // ← 파라미터를 가린다
  const mul = raw ? 1 : (adj.mul ?? 1); // ← 지침 차이가 0이 아니면 항상 배율 1
}
```

**결과: 조정 절의 배율이 전혀 적용되지 않았다.** 배율을 2로 넣어도 공용 사용량이 그대로였다.

**검증이 잡지 못했다.** 배율이 안 먹어도 합계·배분 비율·차액은 모두 정상이기 때문이다.
화면상으로는 증감 열이 계속 `—`로 나올 뿐이어서 「조정할 게 없나 보다」로 보인다.

**조치**
- 지역 변수를 `diff`로 바꾸고 파라미터 주석을 남겼다
- **검증에 ④번 추가** — 배율을 2로 넣어 공용 사용량이 실제로 늘어나는지 확인한다

```
④ 조정 배율 반영 본관8층  공용 479.2 → 884.7  ✓
```

기능이 있는데 동작하지 않는 것은 합계 검산으로 잡히지 않는다.
**조작이 결과를 바꾸는지**를 검사해야 한다.

## #56 · 배분 비율에 배율이 반영되지 않아 화면 검산이 깨졌다 — 반영 완료

**계산은 정확했다.** 공용 사용량 합계 불변, 증감 합계 0, 총액 일치.
**틀린 것은 화면이었다.**

```
본관8층   개별 3,113   비율 8.34%   공용 884.7   배율 ×2.0
                      ↑ 배율 미반영          ↑ 배율 반영

합계 5,748.8 × 8.34% = 479.5 ≠ 884.7
```

배분 비율이 배율 적용 **전** 값이라 공용 사용량과 대조가 안 됐다.
담당자는 계산이 틀렸다고 판단하게 된다.

**수정**

```
배분 비율  = (배분 기준값 × 배율) ÷ Σ(배분 기준값 × 배율)
공용 사용량 = 공용 사용량 합계 × 배분 비율
```

열 이름도 `개별 사용 비율`·`면적 비율` → **`배분 비율`**로 통일했다.
배율이 반영된 값이므로 기준값의 이름을 붙이면 오해를 부른다.
배율 적용 전 값은 `배분 기준값` 열에 그대로 있어 환산 과정을 따라갈 수 있다.

```
유닛         개별 사용량   배분 비율   공용 사용량   배율      증감   검산
본관8층         3,113     16.31%      937.4   ×2.0   +458.2    ✓
본관7층         6,980     18.28%    1,050.9   ×1.0    −23.6    ✓
본관B1        2,274.8      0.00%     부담 없음   ×0.0   −350.2    ✓
합계         37,343.2    100.00%    5,748.8             0.0
```

**화면에서 검산이 되는 것이 중요하다.** 값이 맞아도 대조가 안 되면 담당자가 믿지 못한다.

## #57 · 배분배율을 정규화에서 목표값 방식으로 — 내가 틀렸던 것

**사용자가 처음 설명한 방식이 옳았다.**

> "1층에 배수 2를 넣으면 혼자 공용 사용량이 늘어나겠지. 그럼 다른 임차인이 감당해야 할
> 공용 사용량은 줄어들거야. 여기서 축소된 비율을 활용해서 줄어든 공용 사용량을 남은
> 임차인에게 다시 안분하는게 핵심이야. 실제 공용 사용량의 총량은 줄어들거나 늘어나지 않으면서."

당시 나는 **「총량 불변과 정확한 N배는 동시에 성립할 수 없다」**고 답하고 정규화
(배분 몫 ÷ Σ배분 몫)를 택했다(#22). **틀렸다. 둘 다 성립한다.**

**정규화 방식의 문제**

```
본관1층 기준 공용 1,553.1 · 배율 2.3
  정규화     2,643.3   (1.70배)   ← 분모가 함께 커진다
  목표값     3,572.04  (2.30배)   ← 의도한 값
```

담당자가 2.3을 넣었는데 1.7배가 나온다. **화면 값과 의도가 다르면 도구를 믿을 수 없다.**

**새 방식**

```
배율 ≠ 1인 유닛   공용 = 기준 공용 × 배율                      지정 몫
배율 = 1인 유닛   공용 = (합계 − Σ지정 몫) × 원래 비율          잔여를 나눠 갖는다
```

총량은 정의상 불변이다. 검산 결과 배율 2.3 · 1.5 · 0을 섞어도 합계가 정확히 유지된다.

**예외 하나** 지정한 몫의 합이 합계를 넘으면(배율 5 등) 잔여가 음수가 되어 배분할 수 없다.
배율 1.0인 유닛이 하나도 없는 경우도 같다. **그때만 전 유닛 비례 배분으로 물러서고 경고한다.**

**검증 강화** ④번에 「배율 N이면 정확히 N배인가」를 추가했다.
전에는 「늘어나기만 하면 통과」였다.

## #60 · 「금액 일치」의 범위와 순서가 정의되어 있지 않다 — **미정** (재설명 요청)

청구 건이 10개면 조합이 1,000개가 넘고, 여러 조합이 같은 금액이 될 수 있다.

**실제 사례**
- `에스씨케이컴퍼니` 13,200,000원 = 임대료 1건(12,000,000 + 부가세) · 1초 뒤 7,549,294원 = 나머지 전부
- `ICB` 28,789,967원 = 청구서 2장의 합
- `(유)유니버셜대부` 13,625,312원 = 8월 청구서. 7월 미납 3,680,000원이 따로 있다

**제안** 일치를 다음 순서로만 찾고, **같은 단계에서 둘 이상 맞으면 자동 배분하지 않는다.**

```
① 청구서 1장의 미납 합계        (계약 × 청구년월)
② 청구서 여러 장의 미납 합계     같은 사업자의 계약들, 여러 회차
③ 청구 건 1건
④ 없으면 오래된 회차 → 우선순위  계약이 하나일 때만. 여럿이면 담당자가 고른다
```

임의의 청구 건 조합은 찾지 않는다. 설명할 수 없는 조합이 우연히 맞는 경우가 생긴다.

**입금은 시간순으로 처리한다.** 앞 입금의 배분이 뒤 입금의 미납액을 줄인다. 그러면 에스씨케이컴퍼니처럼
나눠 낸 입금도 각각 ③·①로 자연스럽게 맞는다. **4.6.5 「묶어서 한 계약에 배분」은 필요 없어진다.**
묶으면 어느 입금이 어느 항목을 냈는지가 사라진다.
